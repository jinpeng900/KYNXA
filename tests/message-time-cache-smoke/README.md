# 本机回复结束时间缓存验证

独立纯 .NET 10 控制台夹具，直接链接产品 `MessageEndTimeCache.cs`、`MessageTimePresentation.cs`、消息转换器及共享工具合同。不依赖 WinUI、网关、模型、凭据或真实聊天数据，不启动产品 UI。全部文件写入夹具生成的系统临时目录，完成后清理。

从仓库根运行：

```powershell
dotnet run --project tests/message-time-cache-smoke/MessageTimeCacheSmoke.csproj
```

验证范围：

- 独立写入进程退出后，另一个进程读取原始结束时刻；不同聊天、消息和 Desktop 根目录相互隔离。
- 多个缓存实例及独立进程并发写入不丢记录；默认保留同身份、状态和内容指纹的首次观测。
- 删除单条记录后重试，以及 `replaceExisting: true` 的同内容明确重试，可以记录新的结束时刻。
- 非终态、空 GUID、非规范 SHA256 指纹和无效时间被拒绝；结束时间统一为 UTC。
- 损坏 JSON、未知版本、超大文件和身份不匹配的文件，在读取、写入、明确重试和删除时均原字节保留。
- 整个聊天的清理仅删除直属目录中已验证的消息 GUID 文件，保留无关文件和子目录。
- 写锁不可用时读取仍然成功，写入约两秒后返回失败；恢复后可以继续写入，无临时文件残留。
- 目标文件被禁止替换时，旧文件仍可读取，失败写入的唯一临时文件会清理。
- 路径被普通文件阻挡时，缓存失败不会向聊天调用方抛出文件系统异常。
- 真实 facade 的重试先等待旧写入；同 ID、状态和内容的新尝试在配置重置和对象重载后仍恢复新的结束时间。
- 旧记录被禁止删除而失效清理失败时，迟到的旧保存不能清掉重试标记，新尝试仍强制替换同内容旧时间。
- 历史对象恢复时间后，删除聊天、使用原对象撤销保存及重载对象，可以恢复原观测时间。
- 切换缓存根目录时，旧观测与迟到的读取不会污染新根；文件写入失败仍保留内存结束时间。
- 网关保存的创建时刻晚于本机观测时刻时，匹配的缓存仍可恢复；正式消息序列化不加入本机结束时间。

JSON 使用 `schemaVersion: 1`，只包含 `conversationId`、`messageId`、终态 `status`、64 位小写十六进制 `contentHash` 与 UTC `endedAt`。缓存记录的是本机观测时间，不是网关正式消息或供应商生成时刻。构造器要求调用方提供绝对 Desktop 路径；IO 操作失败返回 `null` / `false`，诊断仅输出操作类别与错误类型。
