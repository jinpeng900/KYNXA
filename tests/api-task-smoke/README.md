# 真实 API 长任务与独立子代理验收

`py -3.12 tests/api-task-smoke/test_controls.py` 可离线检查实验额度暂停、同任务续接、终态保护、凭据清理、固定资料和增量计量；这些检查不发送模型请求，不代替真实任务验收。

`run.py` 启动本轮随包 Rust 网关，并使用调用方明确授权的真实 API 模型；它不连接日常网关，也不修改日常 Data、模型配置或聊天。临时目录独立包含 Data、Models、Extensions、工作文件及日志，仅复制所选连接；结束后删除临时凭据文件，报告不包含 key、请求认证头或原始连接文档。

```powershell
py -3.12 tests/api-task-smoke/run.py --bundle-root '<本轮 Windows x64 包目录>' --model-home '<已有模型配置目录>' --scenario children --result-path artifacts/development/api-task-acceptance/children.json
```

测试先通过产品模型发现核对配置名称，不能把不可用模型静默替换成其他模型。必须通过 `--scenario children|long|disconnect` 明确选择一项，分别保留各场景的失败与成功记录；针对修复后的受影响行为补测，不自动重跑其他场景：

如原生核心刚独立编译，可增加 `--gateway '<本轮新 kynxa-gateway.exe>'`；`--bundle-root` 仍提供已核验的只读 ToolHost、资源服务及原生依赖，不覆盖日常安装包。

- 两个真实、独立、只读子代理分别计算文件数据，父代理等待结果、汇总并写入读回验证。记录子任务独立输入、实际模型调用、回执、用量及父聚合。
- 顺序审查十份合成发布记录，制造真实工具结果的上下文压力，观察实际压缩计量与继续工作。只输出长文字、模型自称压缩都不算压缩证据。
- 一次正式文件写入成功后断开 SSE；后台继续、原 request 重发复用完成记录；核对实际操作状态只有一次成功写入，没有新增模型派发。

三种场景均提供独立 Python 标准库 `unittest` 校验，模型必须实际通过 `terminal.host.run` 在测试工作目录执行。夹具从真实源文件推导应有数值或检查写入内容；实际退出码为 0，且正式版本账本确认覆盖当前写入版本，才算闭环通过。开发机命令使用已配置的 `py -3.12 -m unittest`，不要求产品安装 Python，也不额外下载测试依赖。

默认只在临时旧配置字段填入 16,384，单调用输出上限 4,096 tokens；实际投影以能力选择结果为准，不改变产品的默认大窗口。任务总时间 30 分钟，普通验收原生工具轮次 16、长读取验收 32，每任务调用 80，运行过程同时监控所有根任务聚合成本：实际调用 40 次或已知输入输出合计 250,000 tokens 后显式取消。监控阈值不是底层原子硬预约，已经派发的并发请求仍可能结算；未知 token 用量另列，不能当零。需要更大实验可明确扩大命令参数，不靠无限循环或填充输出。

已知官方模型的能力合同优先于旧 `contextWindowTokens` 字段，因此仅改临时字段未必产生 16K 实际投影。只对压力场景可使用 `--scenario long --pressure-proxy`：本脚本提供自有本机透明转发，发现及所有生成均发往已配置的真实 API，完整传递实际响应和流式 usage，不能生成模拟答案；不支持的本地驻留观测返回 404。网关对这个未知入口采用 16K 未验证配置投影，而真实供应商能力仍为其官方上限（当前 DeepSeek 为 1M）。报告分别记录原始配置、验收投影、真实转发状态与计量。这只能验证受限上下文的整理和续接，不能证明供应商本身施加 16K 上限。独立子代理和断线场景继续使用官方入口。

报告保存实际事件及持久事件序号、根与子任务元信息、计量、正式结果引用和检查项。失败及超时保留，不把模型没有执行、部分完成、执行未知包装成通过。它验收这三个真实任务，不能外推完整 Agent 总体成功率或大型仓库语义准确率。测试只关闭自己启动的精确网关进程树，保留临时非敏感工作产物供诊断。

透明转发的正式暂停恢复复用报告中的同一回环端口，保持模型连接身份；端口已占用或原报告缺少有效端点时明确失败，不临时换端口，也不通过修改断点放宽身份核验。

仅诊断摘要拒绝时可增加 `--stop-on-summary-rejection`。脚本在首次实际模型摘要被拒绝后正式取消本次独立任务，保留安全响应形状计数、已接受事实、真实计量及在途未知成本；它不降低完整任务评分，提前停止不能算任务通过。该开关仅用于 `long` 场景，正常完整验收不使用。

需要保留实验额度边界的续接能力时，使用 `--guard-action pause`；默认仍为 `cancel`。脚本通过当前任务版本调用正式暂停接口，保留独立 Data、原任务 ID、操作账本及检查点，退出时移除凭据并关闭自有进程。暂停不是完整验收通过，也不增加产品原有轮次或工具预算。

明确授权继续同一个暂停任务后，可在相同模型、窗口、透明转发设置的命令上增加 `--resume-existing '<上一份暂停报告>'`，并给本次执行独立的 `--result-path`。脚本核对测试目录归属、原任务范围和冻结语料哈希，使用正式版本控制恢复，再通过 GET 观察同任务事件流；不创建新聊天或重发原请求，不改写测试原文。已取消或其他终态任务不能续接。恢复报告的 `usage` 仅计本段新增调用与用量，`priorTaskUsage` 和 `cumulativeTaskUsage` 保留累计对照，避免重复计数。只有原任务最终产物和原有验证标准全部通过才算成功；脚本的离线控制检查不替代真实 API 恢复验收。
