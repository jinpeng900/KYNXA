### 资源阻断与追加诊断

D5／D6 新版主结果出现 `RESOURCE_WAIT_TIMEOUT`，均为 0 模型调用。此前词法检索已返回证据，分别耗约 11.76／16.78 秒，随后生成准入受阻。检索协调器能捕获可选 E5 错误并退回词法；故障回执没有保留失败瞬间原生账本，不能凭 close 后预约为 0 认定当时没有资源压力。

当时只读采样系统可用主存约 844 MiB；按当前 Rust 的 70% 可用主存再扣 512 MiB 安全余量，资源池约 78.4 MiB，生成步骤申请 16 MiB。CPU E5 idle 仅释放执行线程租约、仍保留驻留预约，GPU-only 闲置回收不会释放 CPU 驻留；这给出静态竞争路径，但不能在缺少失败瞬间信用与预约数据时确诊重复扣减。测试连接 `acceptance-qwen`／独立端口不满足观察器默认 Ollama 识别条件，未额外申请 Qwen 权重／KV 增量预约，也不能将故障说成已证实的重复 Qwen 预约。

## 后续真实使用诊断：工具名称与验收资产

### 功能名称不等于供应商可调用函数名

同一个 Qwen 8B，在原生 Ollama 和 OpenAI 兼容接口中，仅提示调用 `filesystem.read`、而工具声明使用 `k_*` 别名时，均返回空正文且没有工具调用。明确声明名称后，两条传输都能返回合法的别名调用。这个对照支持“工具说明与声明身份没有对齐”的具体原因，不证明所有空回答都来自同一个问题，更不能把它归为 RAG 检索失败。

适配保留内部业务名、授权和解码合同：函数 description 直接以声明的 `wireName` 开头；公共提示要求按已声明函数名调用；`tool.load` 的业务参数继续使用 `filesystem.read` 等稳定名称。不接受未声明名称的隐式执行。泛化说明探针已生成合法调用，但探针没有真实派发文件读取，不冒充完整任务成功。

新增一个三协议回归，核验声明名称、业务加载参数、真实加载回执以及别名解码；同时复查现有小窗口合同。第一版重复两套名称的说明使 15 项短组中 6 项失败。仅缩短别名说明后仍有 4 项失败：OpenAI 两协议的 8K 下，`memory.propose` 加载超过 schema 额度，桌面动作加载后 `tool.result.read` 被挤出。实际量化中，输入为 3,686 tokens，schema 硬额度为 1,474；最小加载组合需要 1,495，超出 21 tokens。继续压系统提示不能突破既有 40% 硬上限。

最终精简发现／加载工具的重复描述，保留同一 schema、稳定 ID、权限、真实验证与分页含义，使最小 OpenAI 组合降至 1,471，落入原额度。未改模型窗口或 quota。最后同组 14 项业务与合同通过；剩余一项只是旧提示的字面匹配，经等价语义断言更新后单独通过，不重复另外 14 项。**最终 15 项合同通过**，包括三协议 8K 工具、2K 记忆、8K 自动证据及声明／加载身份。历史失败日志仍保留，不能将它们冒充最后一次整组零失败。

证据：[两传输原始对照](../../artifacts/windows-paired-acceptance/20261010/alias-transport-probe.json)、[公共规则探针](../../artifacts/windows-paired-acceptance/20261010/alias-generic-fixed-probe.json)、[紧凑声明探针](../../artifacts/windows-paired-acceptance/20261010/alias-description-compact-fixed-probe.json)、[最终合同与额度核算](../../artifacts/windows-paired-acceptance/20261010/alias-budget-regression.json)、[15 项最后同组观测](../../artifacts/windows-paired-acceptance/20261010/alias-budget-regression.log)、[等价提示合同补跑](../../artifacts/windows-paired-acceptance/20261010/alias-prompt-contract-regression.log)。

空响应另有恢复缺口：原解码器接受正常停止但无正文、无调用的返回，循环先结束，再由外层 runtime 抛“模型没有返回文本”。新增解码器自有的 `MODEL_RESPONSE_EMPTY`，仅在停止、参数和状态已校验、没有调用及可用正文、且不是明确拒答时进入现有有限恢复。修复当前步骤，不重启任务；成功写入继续用原回执，未知副作用仍只准观察。连续空响应至多一次修复、一次禁工具总结，再给诚实的部分结果。

对应短回归 **11/11 通过，162 毫秒**，其中 6 个新增、5 个相关既有用例：三协议空白分类、明确拒答／截断不混淆、写一次→空响应→重复请求→回执复用→最终回答，以及连续空／仅推理返回的完整计量。取消及配置撤销仍不恢复。使用模拟模型返回和真实隔离临时文件，没有额外生成或 embedding；真实 Agent 任务效果仍由 D 验收。证据：[空响应回归与源码身份](../../artifacts/windows-paired-acceptance/20261010/empty-response-regression.json)。

### 源码快照遗漏随包资源，不等于 GPU 产品故障

初始验收快照仅复制源码，未包含匹配资源服务的缓存产物，导致运行进入 fallback、可见 GPU 额度为 0。这是测试部署配置遗漏，不能将它算成 RAG 或 GPU 推理已经失效。

当前版按资源源码哈希使用匹配的 54 个随包文件；旧版按自己的源码离线、locked、Release 构建独立产物，不借用新版可执行文件，也没有重跑 Rust 全测。随后两版真实启动均报告 `mode: rust`，能申请并释放 1 MiB CPU 和 64 MiB GPU 小租约，已取消申请返回 `RESOURCE_CANCELLED`，退出后无活动预约。该检查没有生成、推理或改资源额度，不代表完成 GPU embedding 吞吐验收。

证据：[资源产物绑定与部署修正](../../artifacts/windows-paired-acceptance/20261010/resource-bundle-adaptation.json)、[两版实际租约与退出](../../artifacts/windows-paired-acceptance/20261010/resource-native-observation.json)。

## 当前结论与仍需保留的限制

可确认的是：Windows 原生运行可用，定向合同、别名小窗口和空响应恢复合同通过，SciFact 100 题检索质量未下降，图准备时丢弃现有向量的缺陷已修复。真实 Agent 任务旧新都只有 1/6 严格通过：新版能形成连续工具工作流，却仍存在不回读原文就解释、代码修复未通过测试、无收益重复读取和生成资源阻断。验收已经结束，不能宣布完整 Agent 收尾通过。

后续应集中处理这些真实使用缺口：把未解析词法关系保留为候选而非实现事实，发现重复低信息回读后换取正文；代码修改以当前文件版本对应的实际 exit 0 回执验收；资源阻断在失败瞬间保留信用、驻留与可用容量，不以调整大额度代替定位。持续后台语义增量仍需在允许新文档推理的独立条件下验收，不能用本轮拒绝新推理的恢复入口证明通过。本轮不提交、不改 B UI，未继续扩测。

本轮没有完成中文规模质量基准、百万容量重测、完整 30 题、商业 Agent 对照或干净机器安装。不能从英文 SciFact、小型本地模型或短原生检查外推整体产品水平。已有通过项继续复用；扩大验证只针对新的失败类别，出现范围越界、错源、未知副作用或数据损坏则停止相应任务并保留证据。
