## 检查发现并修复的问题

1. **存储维护未真正结算。** 网关现在关闭新准入，等待实际 HTTP 响应体、持久任务、后台模型准备及检索写入退出，再结算 SQLite WAL 和运行资源。迁移成功后重新解析指针并替换运行时；清理失败保留原位置并明确失败。任务账本和产物随 Data 迁移，扩展迁移不复制 Data 所有的任务文件。
2. **日志尾部恢复不一致。** 分页读取可恢复崩溃造成的最后一条不完整记录，包括被截断的中文 UTF-8；先保留原尾部字节。中间损坏、完整非法记录仍严格拒绝，不能当成空历史。
3. **旧请求权限未及时撤销。** 已保存的新配置可撤销旧请求的工具／Skill／MCP 能力；MCP 连接与派发验证同一配置代次。脚本 Skill 在 ask 模式下走正式审批，审批恢复核对原脚本身份，根任务和子任务同时执行过期与任务时限检查。
4. **MCP SSE 分片与容量。** 共用增量 UTF-8／CRLF 解码，限制累计响应容量，跨分片中文和超限响应均有真实本机 HTTP 检查。
5. **压缩后的重复模型调用。** 已核验摘要的可选交付精简按实际输入签名记录尝试；相同输入不反复触发计费调用。来源或额度变化后仍可重新整理，不影响未处理来源的正常续接。
6. **SQLite 旁车删除竞争。** 路径检查与句柄检查之间，SQLite 可删除 WAL／SHM。明确已删除且目录项缺失的零链接句柄按不存在处理；真实链接、联接点与硬链接继续拒绝。
7. **构建缓存与部署诊断。** MCP 缓存核验完整清单、关键文件、数量、字节和哈希，保留上游 BOM／换行兼容；原子发布使用 PowerShell 5.1 可正确绑定的空备份参数。原生准备串行化共享输出、正确初始化 C++ 编译环境，部署前检查实际目标路径长度。默认短布局和只读设计时构建继续保留。
8. **新 main 的包身份路径兼容。** 便携运行保留应用旁 Data／Extensions；带包身份运行将可写状态与载荷分开，保留已有明确存储选择。桌面向子网关传递相同的指针、默认位置和维护锁，迁移后的指针仍可重新解析；不会用固定旧 Data 环境覆盖新的选择。
