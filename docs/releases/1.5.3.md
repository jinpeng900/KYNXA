# KYNXA 1.5.3

> 发布准备中：本文记录本地源码变更。1.5.3 安装包与 GitHub Release 尚未发布，不能把下面的目标下载链接当成已可用文件。

本版延续 1.5 的原生网关、WinUI 桌面、用户数据与扩展目录，汇总项目、任务、模型和检索改动，并改善工具准备、存储热路径与后台执行的资源控制。此前截图附件导入、模型身份注入及无包身份 WinUI 编译资源的修正继续保留，不要求重新配置已有模型连接、数据和工具。

## 本地源码变化

- **多文件夹项目与代码检索**：一个项目可以关联多个挂载目录；项目创建、工作范围与文件检索共用挂载关系。后台按变更更新索引，并在项目激活后准备检索，普通聊天不必等待全目录扫描或无关检索。
- **任务恢复与消息衔接**：恢复保持原 taskId、requestId、消息及工具回执关系。写入结果未知或模型预约尚未结算时，先核验正式证据，再结算和继续；证据不足继续等待，不能直接重做副作用。SSE 观察中断时沿同一请求查询状态并重附，不通过重发用户消息来恢复。
- **本地模型与工具经验**：设置内提供 GGUF 模型目录、安装、导入、启用、删除和位置管理；按实际选择准备服务并核对模型与工具调用能力。工具声明和已结算使用经验持久保存，配置、schema、信任、禁用及删除变化同步失效；普通聊天不增加学习调用。
- **ANN 后台衔接**：大集合缺少图时先使用当前可用的检索路径，向既有后台队列安排建图，避免正式 auto 查询同步承担完整建图。图身份、构建参数、更新与范围仍参与复用核验；不能仅用低构图参数换取速度而宣称召回合格。
- **短网页查询与保存开销**：可并行的模型准备、工具目录与检索准备并行处理；搜索按实际 MCP 声明补齐必要字段，保留来源日期的原始含义。当前聊天保存和工具归档复用已完成的布局准备，只即时检查当前范围，仍核对正式目录、布局版本、未完成事务及实际文件身份；完整目录接口保留全布局检查。
- **沙箱额度与后台日志**：Rust 分配的 CPU、内存额度传给 C# ToolHost，Windows Job 设置后回读核验，成功后才执行。单进程、进程树、内存及 CPU 配额各自保留明确边界；AppContainer 的令牌、快照 ACL、无网络和进程树清理规则不变。沙箱及宿主后台作业日志达到保留上限后持续排空，避免只因日志多而停止任务；普通宿主命令的原有超量终止合同继续保留。

## 验证范围与边界

本版功能说明依据实际源码与对应定向检查，不把已有历史测试数字当成所有新场景的结果。最终桌面构建、真实 ToolHost 配额／日志夹具、安装包生成和发布状态须分别确认；生成安装器不等于已经在用户电脑安装运行。

资源不足的等待、任务检查点及工具进程生命周期分别处理。任务可以保留已有进度，但不承诺恢复任意原生进程的内存，也不会把未知写入当成可以安全重放。用户停止、明确工具超时、网络、认证、余额及模型服务可用性仍按实际状态反馈；不承诺模型不会选错工具或产生任何错误。

百万级向量存储容量验证不等于大库 ANN 的完整语义召回验收；大规模性能、图参数和检索质量仍须分开评估。重排按需启用，不声称对所有问题普遍提升。真实网站登录、验证、媒体播放，以及所有模型、设备和 Windows UI 时序，也不能由单元或协议检查替代验收。

## 安装与升级

标准目标文件名：

- `KYNXA-1.5.3-windows-x64-setup.exe`：完整离线安装包。
- `KYNXA-1.5.3-windows-x64-online-setup.exe`：在线入口，自动选择可用来源、保留断点并校验同版本完整包。

发布入口为 [1.5.3 Release](https://github.com/jinpeng900/KYNXA/releases/tag/v1.5.3)。完整包包含所需原生服务、.NET／WinUI、Chromium、私有 Node／MCP、文档组件与 E5／BGE 检索资源，普通用户不需要自行搭建开发环境。可选对话模型仍由软件内模型管理器下载，云端及第三方账号凭据由用户配置。

升级沿用已有存储指针、用户数据、工具配置和模型位置。安装包与在线入口使用新的版本身份和载荷校验，不能让旧版本下载缓存冒充新版文件；源码工程程序集版本继续按 1.5 产品系列单独维护。安装文件通过 Release 分发，不提交到源码仓库。
