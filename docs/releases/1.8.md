# KYNXA 1.8

**Windows x64 · Package version: `1.8.0` · Release tag: `v1.8.0`**

This release improves task boundaries, final reply delivery, and recovery while retaining queued messages, explicit steering, pause/resume, context, successful operation receipts, and existing caches.

## Changes

- A request to explain or propose a plan ends with that answer. Future implementation steps, optional work, and permissions needed for a later stage do not restart execution. The delivered plan is recorded as complete without claiming that its future deliverable has been built.
- Normal completed replies publish a valid final-answer segment with consistent IDs, ordering, and content. A task that cannot proceed can deliver a short, honest conclusion normally while preserving its unfinished task state; it is not reported as successfully completed.
- Recovery distinguishes transport interruptions from execution blockers. Network recovery, explicit pause, and application exit retain interruption semantics. Permission gaps, unavailable capabilities, unchanged execution evidence, and invalid review formatting do not trigger unattended continuation loops.
- Continuation uses real progress and saved evidence. Rewording the same plan, changing call IDs, or rereading unchanged content does not count as new work. Legitimate investigation, improving review-format repairs, and necessary new evidence remain supported.
- Application exit saves available drafts and task progress and pauses running work directly. It no longer turns the exit path into a draft-confirmation dialog. Closing the main window retains the existing tray behavior.
- Explicitly authorized host-terminal work can use a specified directory outside the project workspace. Full permission does not add an unrelated workspace-only restriction; Ask mode and formal-data protection remain effective. Cleanup commands still operate on their explicit targets, with successful receipts preserved.
- Ordinary application launches and saved-file presentation can rely on their successful receipts. Pixel analysis remains available for an actual visual question or requested visual-quality check; opening a sidebar preview does not require extra screenshots merely to finish the task.

## Downloads

The [release page](https://github.com/jinpeng900/KYNXA/releases/tag/v1.8.0) provides exactly two public assets:

| `KYNXA-1.8.0-windows-x64-setup.zip` | Extract the archive and run its included EXE to install the application and full base runtime. |
| `KYNXA-1.8.0-windows-x64-resources.zip` | Runtime resources for source builds; not a standalone application or developer SDK. |

Standalone EXEs, online installers, checksum sidecars, and maintenance manifests are not additional public assets. Internal integrity manifests and original third-party licenses remain inside the appropriate payload. User data, conversations, credentials, local verification files, and optional chat-model downloads are not release contents.

The full runtime retains the native gateway and resource service, Windows ToolHost, E5 retrieval, Office components, private Node/MCP dependencies, and Chromium. Windows package identity uses `1.80.0.0`, preserving upgrade ordering from `1.70.1.0` and older `1.65.0.0` packages.

## Validation scope

The corrected source passed 12 focused Rust regressions, five C# desktop-client checks, a 76.9-second isolated gateway HTTP/SSE regression, and a Windows x64 Debug build. The HTTP scenarios used temporary data and a deterministic local provider. They exercised plan-only delivery, genuine blockers, no-progress settlement, progressive review-format correction, steering, pause, restart, same-task continuation, and preservation of successful operations.

These results are targeted evidence, not a full test-suite run, a live cloud-model evaluation, an installer execution test, or a production code-signing claim. Earlier release results remain in their original notes rather than being counted again here.

Remaining work stays in the [maintained follow-up list](../team/pending-fixes.md). The [1.7.1 notes](1.7.1.md) and [first stable 1.7 notes](1.7.md) retain their historical scope.
