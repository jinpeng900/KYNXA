# KYNXA 1.7：首个正式版

**产品版本：1.7 · 安装包版本：1.7.0 · 平台：Windows x64 · 发布标签：`v1.7.0`**

1.7 是 KYNXA 的首个正式版，面向日常使用的桌面 Agent 工作流。云端与本地模型、长任务、项目文件、记忆、检索、MCP／Skill 和右侧工作区在同一应用中协作；正式版定位不改变已有数据、权限和执行回执的保护边界。

## 任务与上下文

- 保留持久任务身份、检查点、暂停恢复、中途引导、子代理与产物记录。重开聊天可重新观察原任务，明确续作优先接回原任务；多根任务需要选择。
- 已成功操作沿用原回执；结果未知的写入继续核验，不能为了恢复显示或重建上下文而重新执行。
- 插话后的回复关联新的用户消息，保留先前输出和累计计时。部分交付通过原任务的恢复入口继续，暂停任务保持暂停，直到用户明确继续。
- 保留按需工具发现、技能加载和范围隔离的有效记忆；工具与历史变化仍服从当前任务、权限和来源版本。

## 检索与缓存

- 多语言 E5 与词法检索按名次进行 RRF 融合，再做轻量结构化排序，替代 BGE 重排模型。BGE 权重及专属运行资源不再随包分发，已有 E5 索引不要求重新向量化。
- 项目可关联多个文件夹，索引增量更新并在后台准备。明确文件名、路径或符号时，可先用 glob／正则搜索再读取原文。
- 保留查询、检索候选、原文片段和模型前缀复用；缓存计量、协议适配与前缀诊断帮助分析实际开销，不承诺固定命中率。
- 搜索来源保持可配置；内置 DeepSeek Search 复用官方模型连接的已有凭据，并在原设置页显示来源与凭据状态。第三方来源的账号、网络和额度要求按各自服务执行。

## 文档与桌面工作区

- 保留原生 DOCX、PPTX、XLSX 生成，以及直接预览、DOCX 滚动、PPTX 翻页、XLSX 工作表切换和缓存文件标签。复杂或不支持的 Office 特性继续使用转换路径。
- 保留图片、PDF、Markdown／公式／Mermaid、代码与隔离 HTML 展示，网页与 Chromium 操作，以及多个内嵌终端。
- 终端执行保留命令身份、输出、完成状态和退出码，后续读取观察同一次命令。
- 设置继续使用左侧导航、右侧内容与统一圆角控件；审批和任务状态使用现有行内与工作区入口。
- 保留主窗口关闭到托盘、后台检索准备、云端／本地模型管理，以及 CPU／内存资源准入。

## 安装与运行资源

正式版已于 2026-10-22 在 [v1.7.0 Release](https://github.com/jinpeng900/KYNXA/releases/tag/v1.7.0)发布并设为 Latest，公开附件仅以下两个 ZIP。

| 文件 | 用途 |
| --- | --- |
| `KYNXA-1.7.0-windows-x64-setup.zip` | 解压后运行其中的 EXE，安装软件及完整基础运行资源。 |
| `KYNXA-1.7.0-windows-x64-resources.zip` | 为源码构建准备运行资源，不是独立安装器。 |

完整资源保留原生网关与资源服务、ToolHost、自包含桌面运行时、文档解析和转换组件、E5、私有 Node／MCP、Chromium 及原始许可证。可选对话模型继续由模型管理器按用户选择下载。软件、数据、用户工具与模型目录继续使用统一路径与已有迁移规则，升级保留用户内容。

本版不分发独立安装 EXE、在线入口或维护清单；在线构建工具保留在源码中供维护者使用。Windows 包身份内部版本使用 `1.70.0.0`，保证高于旧 `1.65.0.0` 并保持升级顺序；对外产品与安装发行版本仍为 `1.7`／`1.7.0`。

## 记录与边界

后续优化要求见[证据选择与右侧工作区待修复清单](../team/1.7-follow-up-fixes.md)，包括减少无必要截图、避免后台抢切标签，以及提高自动展示门槛；这些条目单独跟踪，不标作本版已修复能力。

本版已实际完成 Windows x64 Release 自包含应用、完整安装器和在线安装器编译；EXE 编译属于构建记录，不代表独立公开附件。当前公开的安装包 ZIP 与资源 ZIP 的大小及 SHA-256 均与本地产物匹配。未运行安装器，未执行实际安装验证，也未配置生产代码签名；编译和文件校验不替代安装验收。源码开发入口见[构建说明](../../apps/desktop/Build/README.md)，安装与多来源续传见[安装说明](../architecture/offline-installer.md)。

带日期的研究、评测和旧版本说明保留原始环境、数字及结论，不机械改写成 1.7 的验证成绩。真实模型效果、检索质量和外部服务可用性仍应按实际任务与环境判断。
