# KYNXA 1.8.1

**Windows x64 · Package version: `1.8.1` · Release tag: `v1.8.1`**

This patch improves ordinary task delivery, settings close behavior, local-model requests, and application shutdown. Queued messages, explicit steering, pause/resume, existing context, successful operation receipts, permissions, and caches remain in place.

## Changes

- Ordinary artifact creation no longer acquires an extra terminal-test requirement just because it wrote code. Explicit checks, real failures, unknown effects, and changed versions still require appropriate handling. Plans and test-case documents do not authorize their implementation or execution; an explicit request not to run tests is respected, while a request for relevant tests still applies.
- File previews retain their actual version hashes. Recovery can repair older preview proofs from their original archived receipts without writing or opening the output again, or reviving invalidated observations. Preview availability is not presented as pixel analysis or visual-quality certification.
- Interrupted task settlement describes available results and limitations concisely instead of replacing them with mixed-language boilerplate. Unreviewed or outdated completion drafts still cannot certify success. Only important work clearly requested by the user enters the task list; loading time, retries, and pauses do not promote ordinary chat into visible tasks.
- Closing settings during loading or refresh no longer reports unsaved edits. Real edits and automatic saves remain protected, and active-operation guards still apply to storage migration and scope changes.
- Local-model planning preserves the configured context window rather than silently shrinking it. Warm process reuse checks the observed window, replaces only an idle owned process when necessary, and shares preparation and output-budget rules across root and child tasks. Preparation timing distinguishes runtime setup, resource waiting, and model loading; Ollama requests use the negotiated context window.
- The tray icon is registered at startup. Closing the main window hides it while work continues; explicit tray exit removes the foreground promptly and lets the gateway save task state and receipts before stopping its owned services. Independent external applications remain separate.
- Cache fixes avoid retaining duplicate query-vector entries, normalize tool sets only for history-cache identity, and distinguish legitimate provider cache markers from meaningful prefix changes. Conflicting or missing provider usage counts remain unknown rather than becoming an invented cache-hit rate.

## Validation scope

Related source checks cover completion evidence, current work scope, older receipt recovery, task visibility, pause/resume, tray lifecycle, local-model budgets, and cache accounting. An isolated HTML delivery regression used a deterministic provider and real file-write and versioned-preview interfaces: writing and opening each occurred once, the final reply completed normally, and no terminal verification was added. Settings changes passed WinUI/C# compilation; interactive settings-close verification remains separate.

Earlier isolated live-model checks used Qwen2.5 1.5B Q8_0 with an 8192-token window. Two turns reused the same model process, and a third turn after a gateway restart retained the conversation context. Those checks exercised the selected CPU configuration; they do not establish the behavior or performance of every local model or device.

The maintained [follow-up and verification record](../team/pending-fixes.md) distinguishes each run and its limits. These targeted results do not imply a full-suite run, a new cloud-model evaluation, comprehensive desktop interaction coverage, an installation execution test, or production code signing. Historical release results remain in the [1.8 notes](1.8.md) and earlier records.
