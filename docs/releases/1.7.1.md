# KYNXA 1.7.1

**Windows x64 · Package version: `1.7.1` · Release tag: `v1.7.1`**

This maintenance release updates [1.7, the first stable release](1.7.md). It fixes message queuing, task steering and recovery, completion evidence, and large-file reads while preserving existing conversations, progress, and successful operation receipts.

## Changes

- Ordinary messages sent during an active reply stay in the editable queue. Only an explicit **Steer** action submits a queued message to the running task. Its card remains visible until acknowledgement; lost acknowledgements retain the original task and message identities.
- The task list displays status without requiring task selection before sending. Reconnection checks for an existing running task before dispatching queued input. Paused tasks do not block unrelated idle messages.
- New steering can revise or withdraw earlier requirements. Explicit stop instructions pause work and preserve progress; withdrawing a minimum duration does not erase elapsed time or successful receipts.
- Completion checks associate evidence with the relevant operation, target, version, and read coverage. An unrelated successful check cannot hide an unresolved required check. Root and child review phases retain the authorized tool channel when further work is needed.
- File reads support bounded pages from UTF-8 or BOM-marked UTF-16LE source files up to 16 MiB, with version checks and matching tool descriptions. Ordinary application launches can use reliable process or window receipts without a mandatory screenshot; explicit visual requirements still need visual evidence.
- Request admission distinguishes active work from completed reconnect records. Delegated task identities include their parent and dispatch scope. Stream reconnects preserve event ordering and committed output.
- Retrieval reuses existing E5 indexes and caches. Automatic ANN preparation runs through the background queue, reuses compatible disk graphs, and falls back to bounded exact search while graphs are unavailable. History indexing and presentation reuse unchanged data where valid.
- Project-owned comments have been shortened and aligned in English and Chinese. Original third-party licenses and texts remain unchanged.

## Validation and remaining scope

The Windows x64 Release application was compiled from the current source. Nine short checks passed against its new payload using isolated data: desktop version, native binary identity, retired BGE removal, self-contained ToolHost startup, native gateway startup, fresh storage, tool discovery, and the 16 MiB read description. The Full resource pack contains 41,616 files and passes the current resource compatibility inspection. Public package sizes and SHA-256 hashes are recorded on the release page; these payload checks do not replace an installation run.

Release compilation reported four existing Rust unused-code warnings. The later structural cleanup remains separate from this maintenance release.

The existing Full Debug build completed on 2026-10-23 with zero warnings and errors. The focused Windows queue/steering scenario passed 22 checks with isolated storage and a mock gateway. The broader keyboard-driven send scenario encountered an input-focus failure and is not reported as fully passed. No installation run or production code signing is claimed.

Background preview focus and automatic display thresholds remain tracked in the [workspace follow-up list](../team/1.7-follow-up-fixes.md). Large-scale restructuring, a general dependency-based repair engine, and measured performance improvements are not completion claims of this release. Existing test results do not establish every provider, multi-hour task, or large retrieval workload as validated.
