# 工具流错误恢复：要求与实施

日期：2026-10-09。最初按用户要求仅记录方案；随后用户授权集中修复、测试与提交，现已接入协议与工具循环。原始现象和初始方案保留用于追踪；以下“已确认源码”描述修复前状态，当前实现与实际验证见文末。不修改 B 的 UI，不重启正在执行任务的软件或网关。

## 用户要求

工具调用格式、序号、参数或工具可用性错误，不应直接使整轮回复只剩错误提示。优先保留已完成操作与有效历史，自动修复当前模型步骤并继续原任务；无法恢复时给出正常的限制说明和已完成结果，保留用户继续对话的能力。

停止某项执行不等于停止回答。恢复不绕过审批、用户停止或有效权限，不执行残缺参数，不把部分完成标成全部成功。

## 原始现象与修复前源码

用户截图显示“创建文件夹 ×2 已完成”，随后出现“工具调用序号无效。”，没有正常结果说明。截图中的路径和状态未通过正式执行日志独立核验。

- `models/tool-streaming.mjs` 的 OpenAI Completions 工具流仅接受整数 `index`，范围为 0～7；缺失、类型错误、负数或大于 7 均直接抛出 `StreamFailure`。
- `models/tool-protocols.mjs` 同时限制单轮最多 8 个调用。序号和数量目前关联为固定数字，但单轮序号并不应被当作跨轮执行身份。
- `orchestration/tool-loop.mjs` 解码模型步骤之后才派发该步骤的工具；先持久化调用，再持久化返回结果。模型步骤异常目前进入外层 catch，标记中断并上抛；`orchestration/runtime.mjs` 保存失败终态，结束本次生成。
- 未声明工具已有失败观察与继续/收束路径，应复用其恢复机制；协议解码错误尚未接入同等流程。
- `orchestration/runtime.mjs` 的请求准备阶段会拒绝已有工具记录的同请求重试（`TOOL_RETRY_REQUIRES_NEW_REQUEST`）。该防重放边界保留；恢复须在工具循环内部请求下一模型步骤，不能重新提交整个用户任务。

因此这是模型协议与编排恢复缺口，不是 Mermaid 渲染故障。尚未读取本次上游帧，不能断定具体触发值或供应商行为；实施前应使用脱敏诊断确认。

## 处理方案

1. **结构化分类。** 将序号错误、参数不完整、调用身份变化、单轮数量超限分别记录机器错误码、协议、模型步骤及是否派发。诊断仅保存必要的序号类型、调用数量和受限片段，不记录认证头、完整提示或凭据。
2. **统一序号与数量策略。** 将调用身份、流片段槽位与执行并发分开。以数量、单条参数和累计缓冲预算控制开销，不因一个安全整数序号大于 7 就终止回答。协议适配器只在映射唯一且可证实时兼容缺失/不规范序号；存在多个候选时要求模型重发，不猜测、不拼接成另一项操作。单轮数量上限由统一策略维护，不简单删掉限制或无限扩大。
3. **修复当前模型步骤。** 仅对“本步骤尚未派发”的可恢复解码失败，保留之前完整、配对的助手调用与工具回执，并增加受信任的运行时反馈，要求重新生成完整调用或直接回答。残缺原生调用不能进入下一次协议历史，也不能伪装成成功工具结果。第一轮先采用一次修复机会；必要时由适配器降为非流式，仍做完整身份、参数、结束状态与权限检查。
4. **防止重做已完成动作。** 前面成功的创建、写入、启动操作保留真实回执，恢复从失败模型步骤继续。身份检查不足以识别换 ID 后的重复副作用；应结合本次任务的执行记录、目标与动作核对，不能把新 ID 当成必须再做的理由。未知执行结果先核验，不能自动重放，也不能把正常再次修改一律去重。
5. **恢复失败仍给出结果。** 修复仍失败时，最多再请求一次禁工具收束，向模型提供已确认的执行情况与具体限制；在总轮次与 token 预算内提前预留收束额度。模型也不可用时，以本地确定性说明交付“已完成、未执行、结果未知”清单，保留阶段内容与历史；此类结果不得标记任务完整成功。恢复次数受当前任务总时长、token 和调用预算约束，不在错误中无限循环。
6. **展示和存储保持一致。** 恢复期间继续当前消息与计时，简短说明正在调整调用。有效最终正文渲染前不删除已有阶段内容；部分完成、停止或失败不套用成功时隐藏过程的规则。失败诊断与执行回执继续保存，不能因界面简化而丢失。权限撤销、用户停止及存储故障按真实状态处理，不能用恢复流程绕过或声称已经保存。

## 分工与验收

- C：工具流解析、完整调用解码、受限兼容及三协议历史有效性。
- A：模型步骤恢复、禁工具收束、任务状态与预算、跨域接线。
- D/E：执行状态核对与正式回执复用；不新增第二份聊天存储。
- B：如现有事件无法表达恢复状态，再协调展示字段；本轮不修改 B 的 UI。

验收覆盖成功写入后协议解码失败、缺失/字符串/负数/稀疏序号、身份变化、单轮超量、参数截断、修复失败后的禁工具说明、未知结果观察、取消、权限撤销以及三协议配对历史。要求保留真实结果，不重做副作用，不执行残缺参数，并能继续下一条消息。

## 当前实现及范围

`models/tool-call-validation.mjs` 定义带未派发证明的解码错误与统一参数/调用数量预算；`orchestration/tool-recovery.mjs` 只拥有当前请求的恢复记录，不建立第二份聊天存储。`tool-loop.mjs` 执行一次修复及一次禁工具收束，复用成功动作回执并重绑新归档身份，未知动作只允许观察，无法确认时保存部分说明与非成功终态。

`tests/tool-step-recovery.test.mjs` 与 `tool-loop.test.mjs` 使用三个协议的真实本机模拟 HTTP 和独立临时文件：成功写入一次后注入错误，再用新调用 ID 请求相同写入，断言文件只写一次、回执归属正确；下一条用户消息仍可读取合法配对历史。客户端流检查允许失败进展段之后的完整最终段，拒绝将不完整最终段认定成功。

没有实现跨进程崩溃后精确恢复、供应商断线续传、自动认证未知副作用或运行中的 UI 轨迹页；本次也没有调用用户付费模型。完整测试记录与局限见 [收敛修复记录](agent-hardening-20261009.md)。
