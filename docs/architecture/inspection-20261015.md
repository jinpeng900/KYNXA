## 删除语义

聊天删除清理其派生 SQLite/ANN 和候选，已有撤销恢复行为保留。工作资料的删除撤销检索及旧引用，但仍保留已有知识快照；这与物理擦除所有备份不同。本轮没有擅自改变原文、回收与撤销规则，也未清理用户正式数据。

## 再次反馈后的聊天定位和网页边界修正

旧聊天初次从目录载入时只有元信息，消息正文尚为空；界面误以消息数量判断新聊天，导致输入框居中，直到历史到达才移动到底部。现以正式聊天身份和真实消息共同判断：选择已有聊天即使用底部布局，历史和排版继续异步补齐；真正未发送的新聊天保持原有居中样式。主布局的 Translation 与选择入口使用同一判断，消息投影也先于侧栏同步。

## 正式画面复现：撤回仅凭 region 判定右栏无覆盖

用户再次反馈后，在正式 Shell 选择既有测试聊天，通过工作区地址栏打开网页，实际截图明确显示浏览器表面从右栏顶部开始覆盖任务、文件标签和地址栏。与此同时 GetWindowRgn 返回的裁剪数字仍正确。因此前述 13 项几何检查不能作为正式画面无覆盖的验收结果，也不能证明顶层窗口方案已修好。根因是代码一直使用 GWLP_HWNDPARENT 建立顶层 owner，且清除 WS_CHILD、保留 WS_POPUP；它并不是真正嵌入控件。

现将 Chrome 通过 WS_CHILD + SetParent 挂入内容行内的原生子窗口宿主，位置使用父客户区像素，依靠原生父子裁剪保护外部任务和文件标签；去除旧的顶层 region 模拟。自有无框浏览器气泡也挂入同一宿主，普通网页窗口与系统对话框保持区分。关闭视图和会话仍按现有生命周期处理。

浏览器启动的实际 target 检查发现，本机 Chrome 155 将 `--app=about:blank` 解释为 `chrome://newtab/`。现使用普通位置参数 `about:blank`，准确消费唯一初始页；先登记新页面，再执行初始化，取消或失败后清理准确页面和末个自有进程。原浏览器 host 单项通过，包含初始唯一页、导航、跨聊天登录、取消清理、末页退出和重新打开。
