「不使用文件夹」的工作聊天沿用已有隐藏项目路径，但该隐藏项目不提供共享工作记忆。每个聊天只使用自己的记忆与明确指定的用户全局记忆。

## 共享关系

| 信息 | 当前聊天 | 同一工作的其他聊天 | 其他工作/普通聊天 |
|---|---|---|---|
| 完整消息历史与旧对话摘录 | 可以使用 | 不自动使用 | 不使用 |
| 聊天确认记忆 | 可以使用 | 不使用 | 不使用 |
| 工作确认记忆 | 可以使用 | 可以使用 | 不使用 |
| 用户全局确认记忆 | 可以使用 | 可以使用 | 可以使用 |

例如在工作 A 的聊天 1 发送 `记住：本项目使用 Python 3.12`，工作 A 的聊天 2 后续请求可使用该约定，但不会收到聊天 1 的整段历史。工作 B 不能使用这条工作记忆。聊天 1 发送 `聊天记住：当前实验使用样本 A` 时，只影响聊天 1。

默认只有用户消息的完整开头指令触发记忆确认：

| 指令 | 保存范围 |
|---|---|
| `记住：内容` / `记住这个：内容` | 真实、未归档项目中默认工作；其他情况下默认聊天 |
| `聊天记住：内容` | 当前聊天 |
| `项目记住：内容` / `工作记住：内容` | 当前真实、未归档工作；无工作时拒绝 |
| `全局记住：内容` | 用户全局 |

中文和英文冒号都可使用。助手回复、引用、代码块、一般对话中的“记住”字样不会自动提取。不使用模型推断来将未经确认的事实提升为长期记忆。

每条记忆保存内容、类型（fact/preference/decision）、范围、来源聊天/用户消息、确认状态、版本和时间。更新/删除使用范围文件的 `expectedRevision` 做冲突检查。单范围最多 1000 个活动条目，单条最多 4000 字符，文件最多 8 MiB；超限明确失败并保留原文件。来源撤销清单同样受文件容量约束，不静默淘汰旧撤销记录。

来源聊天归档时，已确认记忆仍有效。删除来源聊天暂停使用其消息来源记忆，撤销删除恢复；移出原工作后不再向原工作提供该来源记忆。聊天独有记忆随整个会话目录移动。手动确认条目独立于来源消息的存活。删除明确记忆会保存来源撤销标记，原请求重试不能将删除的记忆重新创建。目标工作归档后，不注入其工作共享记忆。

## 请求上下文与恢复

`events.jsonl` 始终保留完整正式记录；本次请求投影不截断源日志。当前用户输入完整保留，历史按 `ReplyTo` 选择完整成功问答，排除失败、中断尝试及可见思考内容。切换模型、重启应用或迁移 Data 不改变聊天身份及确认记忆。

每个连接可配置 `contextWindowTokens`（2048–2000000），默认 8192；1M 为 1000000。**1M 是用户可设置的请求预算，不会自动赋予模型百万上下文能力**；窗口须与实际模型、供应商限制及本地服务启动配置匹配。算法使用保守字符估算，并预留输出与安全余量，不能替代供应商 tokenizer。

输出限制独立于上下文窗口。当前运行时使用 `min(2048, floor(contextWindowTokens × 0.25))` 作为输出预留和传给上游的输出上限；配置为 1M 后，输出上限仍为 2048 tokens。当前尚无独立输出预算设置。当前输入单独超过可用预算时返回 `CONTEXT_INPUT_TOO_LARGE`，原消息和失败状态仍保存，不调用上游。

上下文在预算内加入已确认记忆，优先保留短条目全文，长条目必要时使用明确标注的首尾原文摘录。预算放不下的条目只从本次请求省略，不从长期记忆删除；构建器返回入选、摘录、省略条目 ID 和诊断，但目前这些诊断没有通过聊天 HTTP/SSE 展示给桌面用户。当前不提供按问题的向量/相关性检索。

当前记忆注入配额为 `min(4096, floor(inputBudgetTokens × 0.20), inputBudgetTokens - currentCost)`，其中 `currentCost` 是含消息开销的当前输入估算。即使配置 1M 窗口，本次确认记忆仍最多分配 4096 tokens 的估算预算；扩大窗口不会让所有记忆全文自动进入请求。后续预算展示须说明这项独立配额及其省略结果。

较早历史超预算时，`context.json` 保存确定性的原文摘录，不额外调用模型，也不是完整语义总结。覆盖轮次、来源哈希和内容都须与当前原日志一致，否则重新生成。记忆注入内容不会进入该摘录。坏 JSON 在备份成功后移除并重建；未来版本、链接路径及真实 I/O 故障仍拒绝覆盖。长期记忆损坏则保留文件并报错，不当作空记忆继续写入。

## 模块职责与接口

| 模块 | 职责 |
|---|---|
| `conversations.mjs` | 正式日志和目录事务；按稳定 ID 查询当前归属与兄弟聊天元信息 |
| `data-layout.mjs` | 补齐目录并检查版本和链接路径 |
| `memory-contracts.mjs` | 范围、来源、内容及版本校验；明确指令识别 |
| `memory-repository.mjs` | 记忆与摘录持久化、原子替换、文件队列与版本冲突保护 |
| `memory-service.mjs` | 记忆确认、来源有效性、工作隔离与可用范围查询 |
| `context.mjs` | 不修改源数据的上下文预算、轮次选择、记忆投影及摘录验证 |
| `runtime.mjs` | 发送前确认记忆/组装上下文；调用模型并保存完整或失败状态 |
| `protocols.mjs` | 三类协议的系统字段及输出预算映射 |

所有正式写入由单个网关拥有。记忆和摘录的读写先进入正式会话队列，再进入文件队列；聊天移动或删除须等待这些读写完成，避免写回旧会话目录。范围列表在同一归属快照中读取，单范围报错也等待其他范围读取结束再释放会话队列。版本检查防止多个客户端覆盖共享记忆。这不是多个网关同时写同一 Data 的跨进程数据库事务方案。

后端提供 `/api/conversations/:chatId/relationships` 和 `/api/conversations/:chatId/memory` 查询；记忆 POST 创建、PATCH 修改、DELETE 删除，详细参数见 [模型网关说明](../../apps/model-gateway/README.md)。关系接口只返回兄弟聊天元信息。桌面通过健康协议检查拒绝复用缺少记忆/上下文能力的旧网关。

测试使用独立临时 Data 和模拟上游，覆盖共享隔离、归档/删除/撤销、来源移动、换模型、重启、真实迁移、三协议与 SSE、版本冲突、容量边界、路径链接、摘录篡改及损坏恢复。

| 交付 | 实施内容 | 完成条件 |

| 上下文诊断 | 网关保留并返回受限的预算诊断；同时扩展共享 DTO、JSON/SSE 事件和桌面读取器 | 诊断绑定当前会话/请求，晚到信息不写入其他聊天；流式与非流式一致；保留旧协议兼容，禁止直接向现有严格读取器发送未知事件 |

前端读取的版本来自范围文档 `scopes[].revision`，不是条目自己的 `entries[].revision`。旧聊天写操作返回范围文档，不保证带来源有效状态；独立范围接口包含这些字段，桌面仍在保存成功后重新获取列表。POST 的 `expectedRevision` 在后端是可选字段，桌面管理入口仍应提交已读取的范围版本，以检测其他聊天或客户端的同时修改。

聊天接口仅接受正式聊天 ID，未发送草稿不会进入管理目标列表。设置窗口使用独立工作/全局接口，可在没有任何聊天的情况下管理全局记忆，或为已有空工作添加共享记忆。工作身份来自正式目录，隐藏无文件夹工作不作为共享目标；归档工作可管理而不注入。读写顺序为会话目录队列 → 记忆文件队列，删除/移动等待管理操作完成。

第一批交付只包含列表和单条操作。按范围清除目前没有专用 API，需要另行定义原子提交、撤销来源保留及并发冲突行为；不能将逐条 DELETE 描述为一次原子清除。上下文诊断也尚未贯通 HTTP/SSE；现有 `context.metrics` 不等于桌面已经拿到诊断。

回归重点是三范围隔离、兄弟聊天共享刷新、来源归档/删除/撤销/移动、版本冲突、切换聊天时的晚到结果和空稿不持久化。记忆列表可以先交付；批量操作、检索、自动语义总结和执行检查点继续保持独立任务。

## 工具记录与应用技能

基础工具现已接入同一 Runtime，assistant 消息的 ToolActivities 由现有 events.jsonl 保存，没有另建可独立写入的聊天历史。记忆注入仍按原三层范围处理，MCP/Skill 与文件内容不能改变记忆来源或作用域。执行与恢复边界见 [基础工具、MCP 与应用技能](agent-tools.md)。
