# 聊天与工作记忆

本轮以现有项目作为“工作”，不另建 Work/Run/Task 身份。正式聊天记录、已确认记忆和本次模型上下文分开管理，稳定 ID 不依赖服务商、模型名称或关联文件夹位置。

2026-10-10：常驻确认记忆保持 4K 上限，预算压力下按当前问题相关性与偏好/决策排序；详细资料走共享检索额度。完整注入的多行记忆参与检索去重。每轮准备、资源准入后派发前及最终回答前核对所用条目的版本与来源；撤销旧投影、保留失效通知与回执，不重放已完成操作。实际使用与批准额度分别报告，见[资源与记忆收尾](resource-memory-closeout-20261010.md)。

2026-10-09 模型步骤恢复仍属于同一请求和同一正式聊天。有效助手调用/工具结果配对不丢失，失败步骤的公开草稿保留在 `AssistantSegments`，不把残缺原生调用插入模型历史。成功副作用复用回执时为新的调用 ID 建立正确归档身份；后续用户轮继续使用原始记录与合法历史投影。恢复成功允许此前进展段是 `interrupted`，最终段必须完整；结果未知或恢复未成功则保留部分正文与 `interrupted` 状态，不能将正常结果说明当成任务全部成功。

`ContextAssembly.budgetAudit` 保存实际输入窗口下的证据/工具配置、批准、使用与裁剪原因。资料任务提高证据份额，并保留系统指导、对话、代码、工具配对和输出预留；不以配置窗口直接承诺全部历史原文进入请求。原始日志、确认记忆和 Data 路径不迁移或改写。本轮未修改 B 的展示逻辑，见 [收敛修复记录](agent-hardening-20261009.md)。

目录自动初始化。`entries.json` 在首次保存该范围记忆时创建，`context.json` 在需要压缩请求历史时创建，`tool-results` 在首次保存工具结果时创建；没有发送内容的聊天草稿不成为正式会话。坏 JSON 摘录恢复时，同目录会留下 `context.corrupt-UUID.json` 原字节诊断副本。关联的外部工作文件夹保留项目文件，聊天及记忆仍归统一 Data 管理。

无关联文件夹的聊天首次准备工具调用时独立初始化 `Models/Workspaces/<聊天ID>/`；同聊天继续使用相同目录，文件 CRUD 遵守权限/哈希约定，终端使用真实 AppContainer 快照且不自动回写。目录不改变项目归属或记忆范围，Data 迁移完整带走。正式消息、长期记忆与截图工具结果仍在原聊天存储中，不能由工作目录的文件替代；目前删除聊天不自动删除这部分生成文件。详情见 [工具目录与本机控制](agent-tools.md#无关联文件夹的聊天与本机控制)。

「不使用文件夹」的工作聊天沿用已有隐藏项目路径，但该隐藏项目不提供共享工作记忆。每个聊天只使用自己的记忆与明确指定的用户全局记忆。

## 共享关系

| 信息 | 当前聊天 | 同一工作的其他聊天 | 其他工作/普通聊天 |
|---|---|---|---|
| 完整消息历史与旧对话摘录 | 可以使用 | 不自动使用 | 不使用 |
| 聊天确认记忆 | 可以使用 | 不使用 | 不使用 |
| 工作确认记忆 | 可以使用 | 可以使用 | 不使用 |
| 用户全局确认记忆 | 可以使用 | 可以使用 | 可以使用 |

例如在工作 A 的聊天 1 发送 `记住：本项目使用 Python 3.12`，工作 A 的聊天 2 后续请求可使用该约定，但不会收到聊天 1 的整段历史。工作 B 不能使用这条工作记忆。聊天 1 发送 `聊天记住：当前实验使用样本 A` 时，只影响聊天 1。

默认只有用户消息的完整开头指令触发记忆确认：

| 指令 | 保存范围 |
|---|---|
| `记住：内容` / `记住这个：内容` | 真实、未归档项目中默认工作；其他情况下默认聊天 |
| `聊天记住：内容` | 当前聊天 |
| `项目记住：内容` / `工作记住：内容` | 当前真实、未归档工作；无工作时拒绝 |
| `全局记住：内容` | 用户全局 |

中文和英文冒号都可使用。助手回复、引用、代码块、一般对话中的“记住”字样不会自动提取。不使用模型推断来将未经确认的事实提升为长期记忆。

每条记忆保存内容、类型（fact/preference/decision）、范围、来源聊天/用户消息、确认状态、版本和时间。更新/删除使用范围文件的 `expectedRevision` 做冲突检查。单范围最多 1000 个活动条目，单条最多 4000 字符，文件最多 8 MiB；超限明确失败并保留原文件。来源撤销清单同样受文件容量约束，不静默淘汰旧撤销记录。

来源聊天归档时，已确认记忆仍有效。删除来源聊天暂停使用其消息来源记忆，撤销删除恢复；移出原工作后不再向原工作提供该来源记忆。聊天独有记忆随整个会话目录移动。手动确认条目独立于来源消息的存活。删除明确记忆会保存来源撤销标记，原请求重试不能将删除的记忆重新创建。目标工作归档后，不注入其工作共享记忆。

## 请求上下文与恢复

工具流 v3 将每轮公开思考与阶段正文保存在同一助手消息的 `AssistantSegments`，工具活动带稳定 `round` / `order`。最终完成时 `Content` 只保存最终回答，因此下次请求不会把全部中途播报重复当作答案注入；全部阶段仍在正式 JSONL 中，界面重开后保持顺序。历史 v2 消息保持原始 Content 和兼容显示，不从句子或工具结果猜测缺失的边界。中断的部分消息与已完成工具回执保留，仍不提升为成功历史。

`events.jsonl` 始终保留完整正式记录；本次请求投影不截断源日志。当前用户输入完整保留，历史按 `ReplyTo` 组织整轮用户、助手调用和工具观察。失败、中断的草稿不当作成功答案；已有执行记录仍按其真实完成、错误或未知状态配对，避免把已经发生的动作说成从未发生。可见思考只用于展示，供应商私有续接另有保护边界。切换模型、重启应用或迁移 Data 不改变聊天身份及确认记忆。

每个连接可配置 `contextWindowTokens`（2048–2000000）；1M 选项为 1000000。本地、自定义和未知模型继续使用 8192 兼容默认；已知云端模型的新连接采用较大的、按已选模型集合计算的窗口，已有显式配置不自动改写。**1M 是用户可设置的请求预算，不会自动赋予模型百万上下文能力**。`model-capabilities.mjs` 根据官方 HTTPS API 地址和精确模型 ID 核对已知上下文、输出及独立输入硬上限；未知代理、未来型号或本地服务不猜测能力。窗口仍须与实际部署和账号能力匹配。算法使用保守字符估算，并预留输出与安全余量，不能替代供应商 tokenizer。

连接 `maxOutputTokens` 独立配置单次输出，默认 262144（256K），可选 4K/8K/16K/32K/64K/128K/256K 或自定义 1024–262144。它是生成上限，不要求短问题也写满，不按“闲聊/代码”的关键词偷偷调整。旧连接缺失字段使用新默认；已经明确保存的小值及旧客户端省略字段后的原值保留。修改程序默认值不会批量修改其他用户已有的连接；本次用户明确要求升级的本机连接已单独保存为 256K。

`output-budget.mjs` 为普通、流式和每轮工具调用统一预留：安全余量 `min(8192, max(256, ceil(window × 0.10)))`。实际输出取配置上限、已知供应商输出硬上限、窗口分配额度和扣除必要输入后的余额的最小值；不超过 32768 的窗口保留原有一半分配，更大的窗口最多预留可用窗口的 30%，给历史和代码留出更多输入。最终输入预算为 `min(window − output, providerInputLimit) − safety`（无独立输入上限时忽略该项）。小窗口允许输出下调至最少 256；不足时返回 `CONTEXT_INPUT_TOO_LARGE`，原消息和失败状态仍保存，不调用上游。例如 8192 窗口实际最多约 3686 输出 tokens；128000 窗口默认输出上限 35942、输入预算 83866；1M 可预留完整 262144 输出、729664 输入，若模型实际输出更低则夹到真实上限。推理模型的思考还可能占用输出预算。这些分配比例是 KYNXA 的产品取舍，不是行业统一值。

上下文在预算内加入已确认记忆，优先保留短条目全文，长条目必要时使用明确标注的首尾原文摘录。预算放不下的条目只从本次请求省略，不从长期记忆删除。SSE 的 `completed.contextUsage` 返回输入估算、配置/实际输出、摘录/省略 ID、警告及工具压缩诊断；这些是可选终态字段，桌面暂未显示用量控件，普通 HTTP 回复不带诊断。当前没有向量检索。

当前记忆注入配额为 `min(4096, max(256, floor(inputBudgetTokens × 0.20)), inputBudgetTokens - currentCost)`，其中 `currentCost` 是含消息开销的当前输入估算。即使配置 1M 窗口，本次确认记忆仍最多分配 4096 tokens 的估算预算；扩大窗口不会让所有记忆全文自动进入请求。后续预算展示须说明这项独立配额及其省略结果。

较早历史超预算时，`context.json` 保存 `extractive-v2/schemaVersion:2` 导航与确定性原文摘录。按当前请求优先选择相关用户约束、代码符号/附近原文，并补不同旧历史区间的证据，近期问答保持完整。较长代码不只取开头。摘录带真实消息 ID/原文范围；它不额外调用模型，也不是完整语义总结或已确认记忆，不保证抓住所有语义关系。

缓存覆盖数量、全部成功历史哈希、覆盖部分哈希、当前请求哈希、摘录预算和内容须与原日志一致，否则重新生成。注入记忆不会进入摘录。v1 留存到 v2 成功重建后原子替换；坏 JSON 在备份成功后移除并重建；未来版本、链接路径及真实 I/O 故障仍拒绝覆盖。长期记忆损坏保留并报错，不当作空记忆继续写入。

正式日志没有 200 条的条数限制。超过 200 条的聊天仍保存原文，预算足够就使用全部成功历史；不足时只缩小请求投影。启用基础工具的模型可调用 `conversation.history.search/read`，分页查当前有效聊天公开正文；失败尝试按其真实状态返回，不提升为成功事实。回查不读取兄弟聊天、Reasoning、工具内部结果、连接配置或已删除/归档聊天。

工具循环每轮连同 schema 检查输入压力，先缩小旧工具结果，再缩小旧的完整历史轮次。必要时最新的大结果也可使用较大预览和已保存 `resultRef`，通过 `tool.result.read` 查回。调用/结果配对、当前请求、系统权限和供应商原生续接字段不改；无法安全回源或必要字段仍超限时明确中断。执行回执先保存，再响应取消，不因压缩重放写入。三种协议的非流式/流式截断均保存已返回正文和可见思考，标为 interrupted，残缺工具参数不执行；当前不会自动付费续写或自动重跑整个任务。

本轮采用独立模块适配现有网关，未搬入第三方会话框架。工具结果先遮蔽/回源的取舍可对照 [pi 的压缩实现](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/compaction.ts) 与 [The Complexity Trap](https://arxiv.org/abs/2508.21433)；有限上下文与外部可回源记录的分层参考 [MemGPT](https://arxiv.org/abs/2310.08560)。截断与工具续接依据供应商真实结束状态处理，例如 [Claude stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)；这些参考不是 KYNXA 已实现语义记忆或所有模型能力的证明。

|---|---|
| `conversations.mjs` | 正式日志和目录事务；按稳定 ID 查询当前归属与兄弟聊天元信息 |

| `tool-context.mjs` / `tool-history.mjs` | 工具循环请求压缩与当前聊天公开原文分页回查 |
| `runtime.mjs` | 发送前确认记忆/组装上下文；调用模型并保存完整或失败状态 |
| `protocols.mjs` | 三类协议的系统字段及输出预算映射 |

所有正式写入由单个网关拥有。记忆和摘录的读写先进入正式会话队列，再进入文件队列；聊天移动或删除须等待这些读写完成，避免写回旧会话目录。范围列表在同一归属快照中读取，单范围报错也等待其他范围读取结束再释放会话队列。版本检查防止多个客户端覆盖共享记忆。这不是多个网关同时写同一 Data 的跨进程数据库事务方案。

后端提供 `/api/conversations/:chatId/relationships` 和 `/api/conversations/:chatId/memory` 查询；记忆 POST 创建、PATCH 修改、DELETE 删除，详细参数见 [模型网关说明](../../apps/model-gateway/README.md)。关系接口只返回兄弟聊天元信息。桌面通过健康协议检查拒绝复用缺少记忆/上下文能力的旧网关。

测试使用独立临时 Data 和模拟上游，覆盖共享隔离、归档/删除/撤销、来源移动、换模型、重启、真实迁移、三协议与 SSE、版本冲突、容量边界、路径链接、摘录篡改及损坏恢复。

## 现有缺口与下一步

建议先补齐用户能够理解和控制的记忆操作，再改进长记录读取；继续沿用现有桌面、网关和正式日志。

| 顺序 | 当前缺口 | 建议交付 | 验收重点 |
|---|---|---|---|
| 已落地 | 设置入口的记忆管理窗口 | 已实现三范围查看、来源状态、手动新增、编辑、单条删除及版本冲突；批量清除后续单列 | 工作共享范围可辨认；来源删除或移动后的暂停状态可见；删除后不再注入，旧请求重试不能恢复已删除记忆；原聊天保留 |

独立输出设置和当前聊天按需原文查阅已实现；诊断的可视化、范围清除、跨会话索引检索仍待开发。当前旧对话压缩只做相关原文摘录，**没有自动语义总结、跨会话全文索引或自动学习**；也没有可恢复的任务执行检查点或新的 Host。以后接入检索或模型总结时，仍须保留原记录、来源引用和范围边界，生成的总结不能直接变成已确认长期记忆。

## 下一轮实施切分

记忆列表、来源状态、单条写入与输出配置已落地；下表保留实现合同，诊断可视化仍待开发。复用现有 Data 目录，不要求先完成 Host。B 负责入口和展示，E 负责记忆契约与一致性，A 复核范围与共享边界。

| 交付 | 实施内容 | 完成条件 |
|---|---|---|
| 记忆列表 | 增加桌面记忆 DTO/HTTP 客户端，保留 HTTP 状态码和错误 `code`；聊天范围调用 `GET /api/conversations/:chatId/memory`；工作调用 `GET /api/projects/:projectId/memory`，全局调用 `GET /api/memory/user`，无需伪造聊天 | 普通及无文件夹聊天不显示工作共享范围；同工作看到相同工作条目，其他工作看不到；空范围、失败和加载状态可辨认 |
| 来源与有效状态 | 展示 `source`、`active`、`sourceAvailable`、`sourceArchived`；归属需要时读取 `GET /api/conversations/:chatId/relationships` | 归档来源仍可使用；删除来源或移出原工作导致的失效不能被当作条目已删除；不根据这几个布尔字段猜测未返回的详细原因 |
| 单条写入 | 手动新增调用 POST，编辑调用 PATCH，删除调用 DELETE；提交明确的 `scope` 和该范围当前 `expectedRevision`，DELETE 同样带 JSON 请求体 | 409 `MEMORY_CONFLICT` 保留用户编辑内容并重新读取，不能静默覆盖；写入成功后重新 GET，取得有效状态和最新范围版本；防止重复点击和盲目重试创建；删除原始聊天记录不属于此操作 |
| 独立输出配置 | 为连接增加独立输出上限，贯通存储、桌面配置、上下文预留及三类上游协议 | 旧连接保留兼容默认值；输出、当前输入及安全余量不能超过配置窗口；模拟三协议请求验证字段，不将配置值宣称为服务商支持能力 |
| 上下文诊断 | 网关保留并返回受限的预算诊断；同时扩展共享 DTO、JSON/SSE 事件和桌面读取器 | 诊断绑定当前会话/请求，晚到信息不写入其他聊天；流式与非流式一致；保留旧协议兼容，禁止直接向现有严格读取器发送未知事件 |

前端读取的版本来自范围文档 `scopes[].revision`，不是条目自己的 `entries[].revision`。旧聊天写操作返回范围文档，不保证带来源有效状态；独立范围接口包含这些字段，桌面仍在保存成功后重新获取列表。POST 的 `expectedRevision` 在后端是可选字段，桌面管理入口仍应提交已读取的范围版本，以检测其他聊天或客户端的同时修改。

聊天接口仅接受正式聊天 ID，未发送草稿不会进入管理目标列表。设置窗口使用独立工作/全局接口，可在没有任何聊天的情况下管理全局记忆，或为已有空工作添加共享记忆。工作身份来自正式目录，隐藏无文件夹工作不作为共享目标；归档工作可管理而不注入。读写顺序为会话目录队列 → 记忆文件队列，删除/移动等待管理操作完成。

第一批交付只包含列表和单条操作。按范围清除目前没有专用 API，需要另行定义原子提交、撤销来源保留及并发冲突行为；不能将逐条 DELETE 描述为一次原子清除。上下文诊断也尚未贯通 HTTP/SSE；现有 `context.metrics` 不等于桌面已经拿到诊断。

回归重点是三范围隔离、兄弟聊天共享刷新、来源归档/删除/撤销/移动、版本冲突、切换聊天时的晚到结果和空稿不持久化。记忆列表可以先交付；批量操作、检索、自动语义总结和执行检查点继续保持独立任务。

## 工具记录与应用技能

基础工具现已接入同一 Runtime，assistant 消息的 ToolActivities 由现有 events.jsonl 保存，没有另建可独立写入的聊天历史。记忆注入仍按原三层范围处理，MCP/Skill 与文件内容不能改变记忆来源或作用域。执行与恢复边界见 [基础工具、MCP 与应用技能](agent-tools.md)。

设置可为工具与技能选择独立扩展目录，用于连接配置、导入技能和 MCP 下载缓存；聊天、长期记忆与完整工具结果继续按这里的 Data 结构保存。未配置独立目录时沿用 Data 内的旧扩展位置，Data 迁移同步更新技能 ID 与自有路径；已单独配置时，Data 迁移保留扩展根不变。两种迁移共用维护锁并在切换后重建同一个 Runtime。
