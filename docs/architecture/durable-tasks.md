# 持久任务与执行尝试

任务表示待完成的工作，代理是其可更换的执行者。一个任务可由主循环直接执行，也可分解为子任务；工具调用仍是任务内的操作，不会自动创建一个子代理。

正式关系记录由 Rust `storage::task_repository::TaskRepository` 拥有，位置为配置 Data 根下的 `Agent/tasks.sqlite`。聊天 JSONL、既有工具归档和检索库继续拥有自己的正文与事实，不把任务表放进可重建的 `search.sqlite` 或 `retrieval.sqlite`。数据库复用既有受控路径检查、SQLite 连接池、预编译查询和写事务；不另建向量库或工具事实账本。

## 身份和接收

- `taskId` 是持久 UUID；更换模型、执行者或恢复不改变它。
- `requestId` 在聊天/工作范围内幂等。相同 ID 与相同请求内容复用任务；内容变化返回 `TASK_CONFLICT`。
- `attemptId` 表示一次接管，`executionVersion` 随接管递增，旧尝试不能写入新状态。
- `version` 是任务控制的 CAS 版本，与执行围栏和事件序号分开。
- 产品子代理沿用父任务的正式聊天归属，独立运行上下文和取消身份保存在任务产物，不向主聊天伪造子消息。关系仓储也允许明确授予的独立聊天，但 `projectId` 和不可扩大的 `permissionSnapshot` 必须与父任务相同。存储快照不是权限凭据；派发前仍须重新核验正式目录、当前权限和实际工作范围。
- 依赖须同一授权范围，禁止自依赖、祖先依赖和循环。必需依赖只有 `completed` 才允许继续，`partial` 不冒充完成。

接收事务同时写任务、父子/依赖关系和首条事件，提交后才可向客户端确认成功。正文和日志超过记录额度时传原文引用，不为方便恢复复制一份完整聊天。

## 执行、控制和恢复

`start_attempt` 核对当前版本、父任务控制状态、依赖结果、祖先累计预算及有效执行租约。有效租约存在时不同时派发第二个执行者。暂停和取消先落盘，父控制向未结束子任务传播；父恢复只解除由它引起的暂停，保留独立暂停的子任务。

`POST /api/tasks/{taskId}/control` 的普通 `resume` 不重开 Completed。用户明确要求修订已结算根任务时可用 `action:"revise"`，仍须提供原 conversationId 和 expectedVersion；只接受 Completed／Partial 根任务且原尝试已结算。事务以 `user-requested-revision` 追加控制事件，原 taskId、requestId、输入、用量、检查点和操作保持不变；只退役已结束的内存交付投影，恢复时重新生成答复，不复用旧完成快照。取消任务不复活，子任务沿用父级 `review:return`。该入口不自动调用，也不扩展原权限或预算。

验收输出按要求数量和既有修复次数分配，始终不超过模型实际协商额度；截断后可增加输出余量，不重复使用旧 640 token 预算形成无效重试。恢复时证据纠正、未绑定证据版本的待交付草稿或明确修订都会使缓存验收失效；历史公开输出和不可变检查点保留，后续回答只依据当前有效回执，并区分历史故障和实时连接状态。

非示例的 DSML 调用封套属于未派发意图，不能当执行或完成证据。主／子验收遇到它回到正式工具阶段；根检查点仅保存工具名称导航，普通改写和记忆刷新不抹掉待执行状态，参数仍由模型通过当前正式协议重新提供并经授权、准入及原去重链校验。旧终态检查点仅在缺少该字段时核验末尾连续 review 的已有续接引用，找到意图或实际工作边界即停止；只取公开 assistant text，不把私有思考转为工作。工具结果与具体质量验收仍分别核对。

主／子审查轮保留当前可用工具声明及正常上下文准入，不因审查阶段发送空工具或强制 `tool_choice:none`。指令优先请求验收结论；发现缺口时允许模型发出真实原生调用，并转入同一普通执行链。DSML 识别仅用于兼容错误输出，不是恢复执行的唯一通道。产物答复阶段也保留可用通道，实际能力缺失、撤权和真实工具额度仍按原规则处理。

租约过期只证明内部执行权过期，不证明外部服务已停止。接管把已派发且尚未结算的操作保留为 `unknown`；有未知写入时进入 `waiting-verification`，读取状态或回读来源核验后才能继续修改。旧尝试的模型结果、事件和检查点拒绝写入。取消后的当前尝试可以记录已派发操作的晚到回执，任务仍保持取消，不派发新操作。

`release_attempt` 结束执行归属但不删除任务。任务等待子结果时释放实际 Worker/model 配额，状态和最近检查点继续持久存在；资源配额由现有资源服务与 Hub 管理，关系库不再实现第二套资源调度。

任务列表只读展示，不承担执行选择。执行中普通发送进入可编辑等待队列，明确点击“引导”才提交当前任务；网关确认接受后立即移除对应等待卡片，失败或回执未知时保留同一消息身份供核实或重试。引导沿用原任务和稳定消息身份；尚未登记时只等待该次请求登记，不另行选择任务。空闲时直接发送普通聊天，模型结合已保存的上下文和用户提示词处理新问题或续作，不设置发送前任务分类、任务归属选择或额外确认。用户停止或真正退出时保存进度和回执；已确认暂停的任务不在启动时自动续做。

最新引导可以追加、替换或撤销旧要求。解释复用现有模型回复中的任务标记，不新增发送前分类请求；变更须绑定最新正式用户消息及其原文引用，同一消息只应用一次，后续 footer 不能按变更后的要求编号再次删改。`continue`、`deliver-existing`、`stop` 分别表示按当前指令继续、交付已有成果、停止后续工作。顶层与嵌套控制合并一致含义，冲突保留待处理，不能静默吞掉停止。缺少明确控制不能默认确认要求不变；最新引导尚未解释时，不派发旧工具提议或启动旧验收，跳过提议保留协议配对但不登记为执行回执。生成期间到达的新引导也须由下一次真正包含它的请求处理。

未提及的要求对继续执行仍有效，明确撤销的最低时长允许归零，已工作时长不清零。交付已有成果或停止独立于原目标验收：完成证据格式错误或文字工具标记不能吞掉有效用户控制。两者暂停任务树，保留挂起的原要求、上下文和成功回执，不追加旧核验，不将原目标记为验收成功；明确继续可恢复未完成项，已撤销时长不自动复活。普通请求仍严格核对证据、权限、版本和未知副作用。

续作进入原有插话与恢复链，保留 task/request/user/reply 身份、上下文、检查点和成功回执；查询或接收回执未知时保留原身份，不擅自作为新根重发。独立新问题不被旧暂停根阻塞，执行中的独立消息仍沿既有队列排队。右栏展开后通过 `GET /api/tasks/recoverable` 分页展示当前聊天的暂停及等待根任务，控制返回的 `recovery.pending` 仍需真实核验，界面不能自行清除。

生产恢复与用户继续共用核验闭环：在有效执行围栏下，查验原生派发／用量回执事件及既有工具归档，核对原调用身份、输入哈希、范围和结果引用后才结算。成功结算的根工具回执补回同一正式助手记录及模型轮次；`RecoveredReceiptVersion` 比工作检查点新时先回读更新后的正式记录，避免旧投影掩盖已执行事实。后续检查点覆盖该事件后可正常复用。真正没有留下派发结果或供应商用量证据的请求继续等待，不能把未知视为未发送、虚构精确用量或重做副作用；用户暂停和取消仍优先。

无回执的只读观察继续保留原 `unknown`，不伪造成功，但不自动升级为未知写入，也不单独阻止已由其他真实证据满足目标的任务结束。未核验的写入、不可逆副作用与未结算模型预约仍阻止核验完成；缺少必要资料时，任务仍须按实际结果记录部分完成。

无法取得原回执的非观察操作可由用户明确确认“结果未知并继续”：`POST /api/tasks/{id}/control` 使用 `action:"acknowledge-unknown"`，携带当前 `expectedVersion` 及 `operations:[{taskId,operationId}]`。兼容旧 `operationIds`，但同树存在重复局部 ID 时拒绝歧义，不能选第一个子任务。模型成本另用 `action:"acknowledge-unknown-costs"` 与 `modelReservationIds:[{taskId,reservationId}]`；仅确认 Unknown，不推测派发或已计费用量，预算预留继续保留。过期版本、错树身份、观察操作或仍未进入静止状态的活动执行者均拒绝确认。

确认不是核验：操作和模型预约仍为 `unknown`，不会改记成功或精确零成本，也不被重放；后到真实回执仍可结算。已确认项不再阻挡恢复／完成，但不能作为验收成功证据。续接提示明确未知事实，要求先观察实际状态。详情中的 `recoveryOperations`、`recoveryModelReservations` 包含后代的真实记录；桌面行内卡携带完整身份，也支持只有模型成本未知的情况。卡片占用输入框上方排队区显示，保留草稿、焦点及排队数据，不自动派发或弹窗。

活动请求遇到未知结果时可以保留同一执行尝试等待确认。执行者必须先结束本地 I/O，结算真实回执；确已结束而派发／成本无法核实的当前预约，才可经 `mark_model_request_unknown` 从 Reserved 转 Unknown。`mark_verification_quiescent` 在同一事务设置 WaitingVerification、记录 `task.state` 与绑定 attemptId／executionVersion 的 `task.verification.quiescent`，拒绝仍有 Dispatched 操作或 Reserved 预约的任务。确认时核对整个任务树的活动执行者都已静止；标记不能跨后续状态转换或新尝试复用。静止期间新操作与模型预约受围栏阻止，原回执、检查点和续租仍可写入。用户确认后 Hub 唤醒原 RequestRun，由它在未知屏障解除后切回 Running，不为等待确认释放租约、重建会话或启动第二个执行者。已经退出的任务仍走正常恢复流程。

Partial 保留终态投影和已有成果，但允许用户显式 Resume 同一任务；上次有效执行者必须先结算，版本、祖先控制和未知副作用保护不绕过。Completed／Cancelled 不能通过普通 Resume 复活；父任务按当前产物正式退回子任务是单独的受控接口。

显式 Resume 与 Revise 都退役原任务已结算的内存交付缓存，再沿原检查点恢复；旧 assistant 的传输状态为 completed 不能覆盖新的续作控制。已接受的引导固定在原根任务，重试沿用同一消息和任务身份；排队任务接收引导后须确认恢复调度已经接上，不能仅返回接收成功。任务上下文、累计进度和成功操作回执保持原记录，恢复不授权重放已完成副作用。

## 操作和回执

操作意图保存稳定 `operationId`、原始 `toolCallId`、工具名、输入 SHA-256、输入归档引用和副作用类别。状态依次为 `pending`、`dispatched`、`succeeded` / `failed` / `unknown`。

意图先提交，正式派发前把状态提交为 `dispatched`。结果引用和操作结果事件在同一事务中提交，成功必须保留正式原始回执引用。成功或未知操作不能重新变成待派发；未知结果变为明确结果需要可信执行层提交核验引用，模型文字不是核验证明。权限、完整参数和来源版本校验继续在现有工具边界执行。

这些记录引用既有正式工具归档，既有 `EffectLedger` 仍负责当前循环的文件状态失效和副作用复用；任务库负责跨进程执行归属及恢复位置，不复制工具正文、文件原文或模型凭据。

未加载的调用与复用已有回执的步骤只产生工具反馈，不创建假派发操作，也不对 `pending` 状态结算为成功。真正执行的步骤才先登记意图、派发并结算。子任务 `requestId` 可使用 `child:` 命名空间查重；正式工具归档使用稳定 `taskId` UUID 作为子执行请求身份，恢复仍沿用该 UUID，不写入虚构主聊天轮次。

同一任务树存在未知写入时，父任务和兄弟任务的新写入也须先核验；只读取证仍可执行。不能因为子 Worker 已退出、工作区写锁已释放，就把它的未知写入视为未发生。

## 事件、检查点、产物和计量

- 每个任务的事件序号单调递增；同一个事件 ID 只接受同一内容。重连按 `afterSequence` 分页回放，不读取整个聊天日志。
- 启动查询明确未结束状态索引，按任务读取最近检查点，不扫描全部历史。
- 检查点绑定已经持久化的事件范围、上下文原文引用、下一步和来源版本。摘要不能覆盖唯一原文，也不能替代工具成功回执。
- 产物保存受控引用、SHA-256、字节数和来源版本；实际文件读取与删除继续由其正式所有者执行。
- 每个实际计量 ID 只累计一次，子任务用量在同一事务中计入全部祖先。模型调用、失败、重试、压缩、已知输入/输出 tokens 分开计数，`unknownTokenRequests` 明确标注缺读数，不把未知当精确零。
- `reserve_model_request` 在同一任务事务内检查所有祖先的已派发调用加上子树未兑现预约，限制多个子代理同时看到剩余预算。`settle_model_request` 只计真实派发；未发送释放预约不计调用，同一预约只结算一次。Worker 崩溃后的预约保留 `unknown`，不能当零清空；确认未派发后通过带核验引用的 `reconcile_model_request` 释放。模型调用统一走预约/结算，不再重复调用一般用量接口记同一笔 HTTP。
- 已发生成本即使耗尽预算仍须记录，不因超额拒绝计量；后续接管检查剩余额度。Token 硬上限仍由实际上下文与调用额度控制：请求次数有持久原子预约，未知供应商 token 不冒充精确 token 预留。
- `modelDurationMs` 与 `toolDurationMs` 作为成本随计量 ID 幂等累计到祖先。`activeDurationMs` 单独保存本任务有效执行墙钟，由每个尝试的累计高水位只增加新时间，不将并行子任务工时相加给根；`maxExecutionMs` 使用这个墙钟口径。旧记录缺该字段时保留未知，不把旧成本冒充真实持续时间。资源等待、暂停和停机不计作有效执行，单次调用超时仍由对应 I/O 所有者管理。
- `retries` 计实际再次派发的失败步骤恢复请求；正常工具续轮和压缩摘要不算重试。计量结算失败时保留派发标记与预约身份，避免摘要审计把已发生的传输误报为零次。
- `completed` 要求没有派发/未知操作和未完成子任务；可交付部分成果时用 `partial`，保留缺口与真实停止原因。具体验收结果仍由执行层核对，数据库不把模型的完成声明当事实。

## 桌面流式投影

切换聊天时，异步历史和核验读取须仍归属于原聊天对象及当前读取登记，才能更新缓存或界面；控制回执使旧核验读取失效。历史分页保留请求期间的实际本地执行尾部，不能将刚完成的回复倒写为旧流式状态。后台回复结束只能更新自身观察，不能取消当前聊天的任务观察或释放其排队屏障；这些展示保护不改变正式任务、成功回执或恢复身份。

桌面沿用原正文缓冲和分段合同，只让发生变化的文字通道重新物化字符串；同长度绝对快照也立即替换，不用长度判断忽略重连覆盖。增长文本超过 256 KiB（128K UTF-16 单元）时以 120ms 合并展示快照，回复换锚、结束、暂停和关闭前仍强制保存完整尾部；该间隔不是输出大小限制或实时性能承诺。

转录控件按稳定消息 ID 记录脏行，普通更新只捕获、比较和发送这些行，导航或消息窗口变化才重新核对整窗顺序。沿用已有快照、HTML、Markdown 和 renderPatch 消费端，选择、复制、导出和历史正文保持完整。活动正文每次显示仍需要完整字符串和 JSON，本批未新增字符串增量协议，也不宣称彻底消除全部复制开销。输入框复用测量控件并按当前宽度、字体和缩放重新测量。

计时、执行阶段与终态独立投影：正式保存期间显示保存状态，计时冻结不等于任务已完成。终态元信息不等待 Markdown 排版或展示缓存，选区存在也立即移除生成标识；旧正文快照按展示版本不能覆盖较新的终态。正式终态收束残留流式分段，先释放发送状态与队列，再进行一次本地展示缓存维护。普通完成分支复用本次刚通过且期间没有新操作的最终来源核验，不在尾部重复相同核验；仍在正式持久化结算后发布完成。

## 定向验证

`tests/task_repository.rs` 使用独立临时 Data 与虚构来源，覆盖重启、请求重发/冲突、依赖循环与范围限制、执行权过期及旧尝试围栏、成功不重派、未知先核验、取消晚回执不复活、父子暂停恢复、事件分页、检查点/产物与祖先预算幂等。它验证关系存储合同，不能替代真实工具、模型、Hub 断线和桌面重连集成测试。

## 原生接线和 Hub

`gateway_task_journal` 是现有任务仓储的薄接线，继续使用 SQLite FULL 与唯一正式写入路径。私有控制队列保留 100ms/8KiB 刷新；公开正文由 `RequestRun` 按 32ms、32KiB 或 128 条的有界窗口排队，首次正文立即提交，后续同批事件一次提交成功后按序发布。分段、回复锚、工具／控制和终态事件先排空前面的正文，不延迟必要的派发与状态屏障。排队序号与已发布水位分开，重连只观察已提交发布的水位；部分提交或等待取消后重试沿用原事件 ID，不重做模型或工具操作。每个事务仍不超过 512 条，终态刷新事件和检查点后再释放尝试。任务自己的子上下文、工作日志、结果和检查点可写为 SHA-256 校验的 `Agent/task-artifacts` 正文对象；已有正式聊天和工具结果只保存回读引用。受控晚回执可在当前仍有效尝试内落盘，暂停、取消不允许重新派发，旧围栏不能覆盖新结果。

`gateway_task_hub` 提供 `task.delegate/status/wait/control/read/result`，HTTP 列表只分页根任务，详情另列子任务。父模型等待子结果使用状态通知，`task.wait` 带有界预览、真实验证引用和 `outputRef`；完整结果经同树授权和哈希核验读取。`task.delegate` 可用 `count` 或 `assignments` 表达用户指定数量，单批最多 4096；建议并发 5 是规划提示，不保证同时获得资源。根／子执行器可以继续受控委派，权限、原始限制、依赖和祖先预算始终继承，不通过新层级扩权。任务本身不持有全生命周期 Worker／写锁；实际模型、工具 I/O 由统一模型池和资源服务准入，实际修改才取得对应工作区锁，等待子结果不造成嵌套锁死。

父验收通过 `task.result` 的 `review:{decision,expectedVersion,outputRef,reason}` 提交，decision 为 `accept` 或 `return`。接受要求直属关系、有效父围栏、子任务 Completed 且无有效执行租约，以及当前版本和最新 task-output 引用匹配；`accept_child_output` 在同一事务追加父 `task.child.review`。子任务自报完成不等于父已接纳，未接纳的直接子交付仍阻止父完成与依赖放行。退回由 `request_child_revision` 在同一事务将 Completed／Partial 子任务置 Queued，保留用量、成功操作、检查点与产物，写入子 `task.child.review-return` 和父 review:return。相同版本／产物／原因的重试幂等，掉电恢复从正式退回事件重建 parentRevision 后继续排队，不能只保存内存修订要求。父事件只表示实际接纳决定，`correctnessCertified:false` 不被夸大为质量认证。

普通运行段 `runLimits.maxDurationMs` 默认 30 分钟、普通配置最高 6 小时。实质工作明确最低时长另记 `minActiveMs` 并预留收尾余量；8 小时、100 小时不因普通段上限缩回。隐式运行预算可由执行层通过 `extend_operational_budget` 单调续展请求次数和执行时间并留审计；不扩大 maxKnownTokens，用户明确限额不因续段被覆盖。有限问候或字面重复交付后完成，不空等或重复调用凑“100 小时”。同轮资源等待仅在整批没有实际执行且仍等待准入时抵扣，重叠取并集，其他调用仍工作时照常计时。

完成判定：本次请求有非观察类工具操作时，模型的 `unknown` 或自报 `complete` 都先进入一次完成核对；核对尾部可带 `unmet`（未达要求列表）和 `blocker`（`user-input`、`authorization`、`external`、`resource`、`difficulty`）。列出未达要求、给出下一步的 `complete`，或只是实现困难的 `blocked`，都继续原任务；只有声明外部条件的受阻才以受阻结束。`minActiveMs` 未满时，核对通过的完成也继续有意义的工作；执行段轮次耗尽返回续接并保存进度，不直接结算完成，也不通过空等凑时长。没有核对状态的真实操作记为 `partial`。主循环与子 Worker 的公开增量、快照和最终摘要过滤内部 `historicalToolCalls` 记录，原始协议历史及调用／结果配对保留；反复复述仍按既有有界纠正及 `MODEL_HISTORY_ECHO` 规则处理。

`minActiveMs` 按任务持久有效墙钟判断，跨恢复／运行段不清零，不以并行总成本充数。仅明确续作同一范围未完成工作的消息继承原目标、完整要求和未满时长余量，写入 `resolvedRunLimits`（`continuedFromTaskId`、`minimumInheritedFrom`）；新话题、有限问候、已完成或取消任务不继承。完整 `acceptanceRequirements` 保存在哈希核验的私有输入，短任务标签不能替代原文。

完成核对的 `met` 须覆盖每个原始验收 `requirementId`，并引用成功结算的调用或真实提交的输出路径；失败、运行中、未知、未派发调用及输入路径不能证明完成。调用 ID 精确匹配，路径规范化保留既有兼容规则。正规／旧归档恢复核对原聊天、请求、调用、工具、哈希和字节数后补证据，不重放操作。漏项继续推进；非法验收先修正 footer，再从检查点重建核对，不按固定两次错误终结仍可工作的任务。需要读回／图像验收的子任务必须有当前结果回读，图像须真实送达评估模型；证据身份和要求覆盖仍不能自动认证事实或视觉质量。

正式消息在每次派发前为完整合法轮预留调用、分段与顺序容量；接近 512 轮、4096 调用、512 分段或 8192 顺序边界时先持久保存，使用 `PreviousReplyMessageId`／`ContinuedByReplyMessageId` 关联新回复并发出 `reply_anchor`。原任务、执行尝试、已保存上下文、待验收阶段及成功证据继续，操作命名空间随回复换段以防局部调用 ID 冲突。有限存储边界不是任务寿命。内部格式／来源／能力变化先在原检查点上修正；无实际进展的永久冲突等待条件改变，不能无限重发相同写操作或付费请求。用户停止、真实网络／额度／授权／配置阻碍仍由各自边界处理，不宣称无限长执行或绝无错误。只读搜索握手断线、EOF 等暂态故障支持有界重试，鉴权、额度和明确用户选择不被备用通道绕过。

实时验收指引先计入必要输入预算，压缩后作为当前控制重新附回，不能被历史摘要替代；核对回合省略普通交付建议。验收项使用简短标签和有界相关证据引用（当前每项最多 64 条），避免将所有历史回执重复塞入每一项。

历史六项补修曾通过库全量 521 项及相关定向检查；本轮继续修改后的集成成绩以 [待修复清单最新实施表](../team/pending-fixes.md) 为准，不把历史数字复用为新父验收、静止确认和自动续段已经全面验收的证明。测试使用隔离存储和模拟供应商，真实多小时工作、第三方账号登录与视觉成品质量未由此认证。

`tool.result.read` 已接入主循环与子执行器的同一专用入口，按当前正式聊天回读公共工具归档，支持 UTF-16 分页与哈希校验。外部聊天、私有模型续接及内嵌媒体正文不能经该工具泄露；媒体仍使用正式引用。

桌面输入区的停止按钮调用带版本的 `pause`，保存断点；界面沿用原停止表现，不增加暂停通知或操作回执。任务执行时发送的多条消息先显示在输入框上方，按序等待，可编辑、删除及移动；暂停保留队列，恢复前不自动派发。点击等待消息的“引导”才将它作为当前任务的正式补充，不弹出选择或确认窗口；任务侧栏只展示进度、用量及产物。

用户补充通过 `/api/tasks/{id}/steer` 保存，以消息 ID、正文哈希及 `continue`／`update` 绑定同一根任务。网关确认接受引导后立即移除等待项，将正式用户消息与新回复位置接在对话末尾；旧未完成回复保存为 `interrupted` 并携带 `SupersededByUserMessageId`，已输出正文保留在引导上方。运行中的模型生成通过独立引导信号中断，已派发工具先收取真实回执，未派发的旧计划不再执行；发出 `reply_anchor` 后，新回复以新的 `replyMessageId` 保存，`InReplyToUserMessageId` 对应最新引导，外层传输 `requestId`、任务及执行身份不变。恢复仍读取同一任务与有效成果，重新打开聊天保持相同顺序。

模型可通过 `task.describe` 为当前任务设置简洁 `title` 和 `displayInTaskList`，不另起任务或额外模型请求；没有设置的旧任务沿用原展示策略。引导是原任务补充，输入/输出 token、模型及工具耗时、调用次数继续累计到同一任务，界面标题优先显示 `title`。

继续保留原方案及其他约束；更新方案停止旧的未完成委派，保留已完成操作和未知结果账本，主代理依据真实补充重新规划。明确被用户新方案取代的委派以 `superseded-by-user-steering` 取消，不伪报完成；未知副作用仍须核验。后到的再次暂停或取消优先。相同插话 ID／正文重发不生成新任务或重复消息，身份冲突明确拒绝。

`GET /api/tasks/{id}/stream` 仅观察该聊天原主任务，核对当前执行尝试后接回既有 SSE，不重发聊天请求。任务进度支持同工作跨聊天读取；子任务请求查重标识保留 `child:` 字符串，不能强制解析为 UUID。任务库仍保存短请求的幂等与执行事实，侧栏根据实际多步执行、长输出或需恢复状态展示，不把普通单轮聊天及单纯模型加载等待全部列为长期任务。

回复交付和任务核验状态分开呈现。即使 `partial`、核验失败或执行未知，也展示真实最终正文；已完成文稿不因没有程序测试误报部分完成。普通文本写入按同哈希及完整分页回读核对文件，代码修改仍要求关联当前版本的实际验证。文档回读不证明语义质量或字数达标，模型必须按用户原验收要求判断。桌面工具参数上限为 1Mi UTF-16 JSON 字符，保留 8Mi 单事件保护；审批不截断参数。

供应商明确返回输出长度终止、且本轮没有工具时，自动续写的正文段保存 `isAnswerContinuation:true`。终态投影合并最终段之前连续的这些正文段，一次渲染完整 Markdown、公式或代码围栏；普通工具进展不参与拼接。原始阶段与正式日志不改写，旧记录缺少该标记时保持原有规则，不依据措辞猜测续写。暂停和插话仍能保存这些已产生段落。

上下文预算只裁剪当前请求展示的声明，不删除已加载目录；声明额度按必要指导计算，历史正文由后续压缩处理。发现与加载始终可用，新加载工具优先展示，已知工具的精确协议别名可以加载，错误哈希仍被拒绝。程序生成的摘要、历史摘录和检查点作为带引用说明的资料消息传入，不构造缺少供应商私有字段的助手轮次；真实模型续传仍保留原始字段。DeepSeek 携带工具时要求续传助手的 `reasoning_content`，缺失会返回 400：[官方工具思考模式合同](https://api-docs.deepseek.com/guides/thinking_mode/)。

主循环与子 Worker 在原有历史来源侧车中保存派生投影来源；新的检查点可替换旧检查点、摘要与摘录，不把每个程序资料块永久当成用户要求。真实用户目标及限制继续保留；用户正文即使包含检查点 JSON，也不能自行获得可删除来源身份。检查点根据扣除系统、当前声明与真实目标后的剩余输入额度，逐步收缩预览、回执投影及导航说明，完整原文仍可按正式引用回读。诊断同时记录请求尺寸、可用额度、实际尺寸和裁剪状态；工具目录已经加载时不要求反复读取发现归档，证据回读按缺口展开。

正文摘录直接从真实回执正文取得，模型只接收紧凑来源身份；完整哈希回执保留在程序侧车与正式归档。低预算先让目录覆盖指针退让，再均衡缩短正文；仍装不下时保留最新有效证据及未知操作，并明确遗漏，不能把所有正文清零后仍塞满目录元数据。这里是原文投影，不把固定摘录称为语义总结或证据充分性判断。

当前工具轮次也可生成带原始结果引用的工作摘要。主循环与子 Worker 使用已有模型执行器、准入和任务成本账本，按实际输入及输出额度分窗口读取同聊天的公开归档；私有推理、未经核验的来源和其他聊天正文不进入摘要。v6 及此前每次压缩最多四次摘要派发；当前 v7 按尚待处理来源数规划 `max(4, pendingSources × 2 + 1)`，四次只是起点，再夹取真实剩余模型请求额度并为主循环与最终答复保留两次。剩余额度不足时可以低于四次或不派发，实际执行器仍逐次核对祖先任务硬限、未结算预约、取消与成本，不扩大任务总额度。实际调用、逐次耗时和已知用量保存在 `currentStepSummary` 审计中，不能把摘要开销藏进零成本的程序裁剪。

摘要继承当前生效的供应商输入、输出硬限，包括上下文错误恢复后得到的限额。正式消息诊断从真实派发观察记录次数与传输耗时，取消或投影未采用时也不漏记；任务费用仍只结算一次，不能根据摘要审计再次收费。

历史摘要与当前轮次摘要分开记录正文目标和传输输出授额：辅助请求先申请正文目标加 3,072 tokens、至少 4,096 tokens 的输出空间，再由统一预算接口和真实硬限夹住。传输预留不决定保存的正文长度，也不扩大模型上下文；输入计划随授额收缩。诊断分别报告 `contentBudgetTokens`、`requestedSummaryOutputTokens` 和实际输入、输出额度。历史摘要沿用原生语义服务的正文验收上限；截断、没有公开正文、错误引用或工具调用都不能接纳为有效摘要。

当前工具轮次的正文目标是软目标，`contentBudgetKind:soft-target` 与实际 `checkpointBudgetTokens` 分开记录。v6 的“一半、最多 2,048 tokens”是历史策略；当前 v7 总目标取真实检查点余量的 75%，每来源目标再按已核验来源数分配，软起点 256 tokens 仍不得超过总目标；零余量不派发摘要，不用最低额度掩盖已无空间的情况。普通窗口只携带当前来源的 `sourcePriorFacts`，模型只更新该原始结果 ID 的事实，其他来源已接受事实由 Rust 原样保留并合并；无需每读一小段都重发、重写全部旧文档。全局精简继续使用总目标和真实来源约束。检查点余量已扣除系统、当前声明、保留用户目标及实时指引；JSON、事实字段、引用与其他来源保留校验继续生效，软目标不增加模型输入或输出硬限。

工具定义统一按有效输入的 40%、最多 24,000 tokens 授额，并在必要指导之外保留约 40% 输入给工作上下文；极小窗口按实际剩余量降低授额。缩小的是当前请求的完整定义集合，已加载目录仍保留；`tool.search`／`tool.load` 入口不删除，显式加载会提升相应定义的顺序。未展示不代表不存在或无权限。最终压缩使用真实声明开销，未用额度继续可供事实与历史使用，不提前填满固定比例。

自动取证的正文与原结果引用作为 `broker-summary` 资料消息进入可压缩工作上下文，不再附加到常驻系统指导。必要规则、真实用户要求和资料分别计量，避免工具授额计算把同一份证据重复当作不可回收提示；原有正式检索归档仍可回读，不新增另一套资料存储。

通过上述校验的候选复用正式 ToolResults 保存为 `context.working-summary`：完整公开事实、原始来源引用、已处理游标和覆盖信息一起保存，不写入长期记忆。保存后按同聊天的公开投影逐页读回，核对完整正文、正式引用及哈希；缓存命中、无新模型请求和进程恢复也重新核验，不沿用持久化的 `verified:true`。事实、游标、目标和覆盖信息同时绑定摘要哈希；归档缺失、损坏、跨范围或存储失败时，回到原有全事实保留要求，不伪造可读引用。

使用程序刚保存的正式检查点引用与近期公开文本，调用既有纯 `checkpointFinalize` 试投影。完整事实和游标留在侧车及已核验归档，模型只接收硬余量内的事实投影，优先当前新来源；明确报告 `workingFactsTotal`／`workingFactsOmitted` 和真实 `tool.result.read` 入口。回读从公开 JSON 投影的 UTF-16 offset 0 开始，续页使用回执 `nextOffset`，不使用原文件行号或窗口偏移。只有完整侧车不变、可见事实属于完整摘要、省略计数和归档导航匹配、全部未完成副作用的回执与计数仍完整可见，且实际消息估算不超过硬余量，才接受。最小归档导航不能被裁掉后仍宣称通过；未知操作也不能隐藏。试投影不写状态、不执行工具、不授予权限；模型输入硬限、原始用户限制和正式操作账本不变。

`currentStepSummary.lastResponseShape` 直接记录真实摘要响应的安全形状：公开字符和估算 tokens、JSON 与事实结构、引用缺口计数、截断和工具调用状态；私有推理只记录是否存在，结束原因只保留已知枚举。审计不保存响应正文或私有推理；正式工作摘要归档仅保存通过引用校验的公开事实。`checkpointProjection` 另报实际尺寸、裁剪状态、可见／归档事实、未知副作用、侧车保留情况及拒绝原因；`overContentBudget:true` 表示超软目标，是否接纳仍看实际投影与最终 `reason`。

辅助摘要按已知协议选择生成模式，普通回复及用户保存配置保持原样。`openai-completions` 的精确 `deepseek-flash`／`deepseek-v4-pro`，在官方地址或明确配置的 DeepSeek 兼容提供方上，摘要专用请求使用 `thinking: disabled`；历史、当前轮次和子任务分段回退复用同一能力规则。诊断区分官方地址与配置声明，不据此推断代理窗口或额度，也不向未知协议和相似模型名注入参数。摘要模式纳入失败缓存签名，避免升级后的有效策略仍被旧失败阻挡。DeepSeek 默认开启思考，控制参数见[官方合同](https://api-docs.deepseek.com/guides/thinking_mode/)。

只含文件属性等结构信息的回执留在程序证据链，计入 `metadataOnlySources`，不冒充未读正文或产生语义摘要。MCP 的标准公开 `text`／`output_text` 块可形成正文，思考和媒体块不混入。模型看到实际正文处理覆盖及元数据类别，不能把结构回执总数当成尚未阅读的文档数量。

公开候选已通过格式与来源检查，但没有可核验完整归档、实际投影仍超限或丢失必要状态时，每次压缩最多追加一次精简反馈；它与原始摘要共享本轮动态派发计划、真实任务额度、取消和计量，历史 v6 的四次上限不再作为当前固定上限。反馈仅携带公开候选、必须保留的来源 ID、原文窗口位置、用户目标及实际压缩比例，要求合并同来源事实并保留当前值、适用条件和被覆盖方案的区别。反馈继续通过相同来源验证、真实归档读回及检查点投影，完整事实可恢复且未知副作用仍可见后才推进游标；再次失败保留旧事实并缓存确定性拒绝，不无限重试。

工作摘要回读页属于 `working-summary-read` 派生上下文，不成为新原始资料，也不触发对摘要再次摘要。最近实际读页中出现的既有事实 ID 可提高相应事实的投影优先级，保留有界公开窗口，以免刚取回的缺失事实在立即压缩后再次消失。之后真正新原文的更高执行序号仍可优先；原始引用身份、处理覆盖及未知操作不会被派生回读替换。

逐文档成果回读同样是 `document-work-read` 派生上下文，不增加待摘要的原始资料或其来源计数；记录和列举成果不当作新的证据正文。真实原文引用、完整版本和范围仍在侧车与正式产物中。来源正文已处理且有对应事实时，模型仅接收简短来源定位，避免与文档导航反复展示同一份版本／范围元数据挤掉工作事实；未知副作用仍保留完整可见状态。

完整候选虽已核验归档，但超出软目标且当前投影丢失事实时，优先复用既有的一次语义精简，把同来源事实合并并保留最终值、条件和冲突。全局反馈须保留其他真实来源，不能编造缺失内容；普通逐来源请求不要求模型重新生成其他文档。该步骤与其他摘要共享当前动态派发计划及原任务总额度；可选精简失败仍采用已核验完整候选及其归档、游标，不使已有有效成果失效。取消仍立即生效；未核验候选不作为回退成果。

已处理范围可在后续检查点复用；模型事实使用原始来源 ID，格式、引用和实际额度校验失败时保留旧事实及原文回查入口。只接收完整 JSON 或单独完整的 `json`／无语言围栏，不从夹杂说明、推理标签或多个围栏中抽取 JSON。安全诊断记录 `wholeJsonFence`、精简是否派发及其结果，不保存辅助正文或私有推理。失败签名包括真实目标、模型和协议、实际辅助模式、输入／输出／正文目标／检查点硬额度，以及原件版本与范围身份。当前规则版本 `checkpoint-incremental-working-facts-v7` 也纳入签名：工作笔记直接保存为可分页的 JSON，旧字符串包装归档仍经完整核验读取；新规则下相同配置和公开输入的失败不会反复付费。生成摘要不是原始证据，不证明事实正确、任务完成或副作用已结算；未知操作、权限和原始用户限制仍由原程序边界维护。

重复保护识别原生对象回执，归档读取按原始引用、版本、实际范围与正文指纹判断；说明参数、默认值写法或每次新增的包装回执不构成进展。工具发现及失败读取不抹掉已有观察历史，真实新来源、范围或版本仍可推进。重复告警进入当前系统指导，要求转向缺失来源或下一有效操作，避免被紧接着的历史压缩丢掉；它不扩大权限，也不因此截断整个最终答复。

恢复先检查正式工作绑定和仍有效租约，不抢占有效执行者。已接受的子任务从其原上下文引用重新排队；成功与终态任务不重做。未结算外部副作用或模型成本使恢复停留在 `waiting-verification`，不自动重放。正常软件退出以网关暂停原因保留未完成任务，与用户取消分开。

根任务也通过现有登记的 `task-checkpoint` 保存私有请求投影、完整来源侧车、工作事实与分页游标、已选工具名称和已经应用的插话身份。完成一次压缩后、下一次模型派发前保存；暂停后的有效尝试只可结算已取得内容，不能因此恢复派发。快照绑定原任务、请求指纹、当前权限范围和模型连接身份。重启读取须复核正文哈希、原件引用、文件当前哈希及知识来源版本；工作摘要归档再次完整核验，不能信持久化的 `verified` 布尔值。旧快照缺失、损坏或来源变化时改走正式原件回读，私有模型续传不进入公开接口。快照属于正式登记产物，永久清理计划会包含其受控 Data 路径，不删除用户工作文件。

恢复、输出续写、完成核验及工具错误纠正等程序指导统一带有 `broker-control` 来源标记，区别于真实用户消息；它们可以指导下一步，但不纳入用户目标签名或原始要求清单，也不因此重置已处理来源游标。恢复不再重复注入整个旧回复。用户真实插话继续按正式消息保留，不能依据措辞把用户的“继续”误删为程序指导。

后台语义发布可能替换词法分块的派生身份，即使原文未变，旧分块和关系引用也会过期。最终来源核验与根断点恢复只可复用已经正式归档、实际读取的原文窗口：核对当前范围、来源、原文哈希和版本、绑定与 locator，再按 UTF-16 范围逐字比较。成功只报告 `originalTextOnly`／`originalReadingsRevalidated`，不把旧 chunk、结构关系或未读内容升级为有效。通用 `knowledge.read` 与 `knowledge.relations` 继续严格拒绝过期引用；正文变化、来源删除或权限变化仍阻止复用。将词法与语义分块彻底拆为独立拓扑是另一项存储设计工作，不冒充本轮已完成。

已完成的原生短测包括关系仓储 10 项、Journal 2 项、Hub 9 项（按新增部分分批执行），覆盖根分页、控制唤醒、共享写锁、700 条事件合批、UTF-16 回读、祖先实际耗时、父子树未知写入保护、结果回读和以下删除生命周期。它们不代表全部任务完成率、所有第三方 MCP 或桌面断电恢复均已验收。

## 逐文档成果与工作进度

根任务复用 `TaskJournal` 保存 `document-progress` 产物；每次真实读取记录来源、版本、已读范围与原文回读引用。主模型通过 `task.document` 的 `record` 动作保存本步结论、未解决问题及产物引用，不增加逐文档辅助模型。记录分析表示已有可恢复工作成果，不证明分析正确或产物已验证。

`list` 按文档条目分页，`read` 按 UTF-16 范围读取完整已保存成果；模型上下文只带有界目录和必要结论。目录与工作进度随根检查点保存，原文不重复复制。恢复时先加载这些成果并核对来源；本地文件的新版本只使该文件的旧分析失效，未变化文件复用。完整来源与权限核验继续走既有程序边界，子代理暂不提供这组根任务专用动作。

重复包装回执、已覆盖范围回读和相同分析不算新增进展；有效新范围、证据或产物更新可以重置停滞。三轮实际工作没有新增信息时提示调整策略，等待状态不计停滞，启动阶段允许有限工具发现。剩余工具额度约五分之一、最多 48 次用于优先综合、写入、回读与验证；这是调度提示，未扩大额度、免计缓存调用或自动宣布完成。压缩展示活动不重复计为工具执行，真实摘要派发仍进入模型与压缩计量。

三轮停滞也可提前进入综合建议，不必等工具额度接近耗尽；模型依据原任务选择、加载下一步读取或交付能力，程序保留最新显式加载的展示优先级。阶段建议不按固定工具名单重新覆盖该选择，否则未读资料会被预算裁掉并形成重复加载循环。新证据或产物进展解除停滞建议，正常补证、用户取消和实际额度继续按原合同处理。读取覆盖完整不等于分析充分或任务完成，模型须据保存成果核对具体缺口后交付。

辅助摘要请求失败保留已接受事实和处理游标，不把这批未变资料缓存为永久拒绝；下一次必要压缩使用同一原件续接，无需重复文件读取。确定性输入或响应校验拒绝仍可缓存；单次摘要调用数、任务总额度和取消边界保持不变。

公开工作摘要的来源、游标、覆盖状态或事实载荷变化后重新归档并真实读回核验；不能复用旧哈希后声称新载荷已经核验。载荷未变时复用已核验归档，存储或核验失败不标为有效。

v2 归档只保存公开事实、来源与处理游标、目标及覆盖状态；`metadataOnlySources` 统计保留在检查点与诊断，不进入正文版本。仅该统计变化时复用原归档 ID，防止同样内容不断变成新的阅读目标；事实、目标、来源或游标变化仍重新保存并完整核验。旧 v1 正文按原格式严格核验，需要更新时迁移到 v2，不能用新版摘要解释旧字节。来源计数注明以已归档的读取结果为单位，同一文档的重复或分段读取不代表更多文档；独立文档覆盖以逐文档工作目录为准。

逐文档导航保留原始读取的 `resultId`，供主模型直接记录分析；回读成果使用对应 `sourceIdentity`，页参数不能替代来源定位。工具声明和参数错误都明确这两类身份，缺身份仍拒绝执行，不猜选其他文档。已展示的结论与定位可以直接复用；未记录分析不宣称已有完整分析可读，成果目录仅补缺失定位。

模型刚加载的下一步能力保留声明优先级，按明确请求顺序安排，不能被每轮固定读取或成果接口覆盖。已加载的读取与成果定义仍可按需提升；预算省略时提示准确已加载名称，下一次只加载必要定义，不要求重新搜索完整目录。再次发现已加载匹配项时，将其原有定义优先展示，不重新启动服务或授予权限。

文档导航、实际可调用／已加载但省略的工具、交付额度和无进展纠偏统一按真实消息 token 从同一输入授额预留一次，压缩后重新附入。它们不能被对话摘要吞掉，也不进入用户目标或新原始证据；旧程序提示按来源标记替换，用户原话和供应商调用／回执配对保留。核验阶段不给模型发送继续调用工具的提示。

检查点已有已核验归档的工作事实时，实时文档提示仅提供目录统计及成果目录入口，不再次复制全部路径、身份和结论，给工作事实保留输入余量。提示组装根据真实已选能力省略当前不用的详细说明；权限、用户限制、未知副作用、取消和交付规则始终保留，省略不代表能力消失或获准执行。

工具定义的准入规划计入实际系统、保留用户原话和本轮实时指引，不再只扣系统提示。预算裁剪每一步重算实际可调用／已加载但省略提示的成本，继续复用原生工作证据预留比例、总输入硬限和最新明确加载的优先级；没有增加窗口或减少输出预留。接近工具额度时优先使用当前可调用能力，在权限及执行契约允许时合并相容的回读和验证，不能用发现、目录或加载耗尽交付余量。

当前请求重新装入窗口后，已经读完但尚未整理完的公开来源仍按已保存游标续接，不等待正文再次超窗。仅真实核验过的工作归档允许触发，继续使用按待处理来源及剩余任务额度计算的动态辅助派发和同一真实输入授额；仅有实际处理进展且新投影装得下时接纳较大的检查点。完整来源处理后不再触发，历史摘要仍只在原压力条件下进行，不把文档续接变成每轮历史压缩。

读取身份兼容原生 `text`、旧 `content` 及 MCP `structuredContent` 正文。完整实际回执先归档并计量，再投影给模型：同一文档版本和完整区间三次读取且无新覆盖时，较长重复正文改为不完整摘录、已有成果和真实原件入口；文件变化或新增区间照常读取。停滞时对已经完整覆盖的大段归档回读采取同样投影，入口继续指向原始归档，不能形成新回执套新回执的循环。摘录不声明分析充分、正确或任务完成，权限校验、工具调用成本和原文存储不改变。

程序侧车的 `originalExcerpt` 始终来自已归档真实回执，不能取缩短后的模型展示对象。否则来源去重选到新回执时，会把已读正文误判成只有元信息，使尚未处理的原件退出摘要；模型展示与原始证据准入分开。

## 删除与清理

当前工作摘要验收版本为 `checkpoint-incremental-working-facts-v8`。处理游标全部完成但可见事实遗漏时，仅对保存事实进行一次精简；依据实际投影计算事实可用空间，不回读原文件。工作提示直接引导复用已完成分析及输出，删去重复的正确性警告与目录导航说明；实际权限、来源版本及执行回执仍由程序核验。

既有目录 `Tombstones` 属于可恢复回收站。`reconcile_deleted_chats` 对受影响任务持久取消并通知正在执行的根及子 Worker，原聊天和任务记录继续保留；旧工作绑定变化不能阻止用户停止自己的已删除聊天。目录还原不自动复活已取消副作用。

永久清理是独立原生接口 `purge_conversation`，不是把当前界面软删除改为不可恢复删除。它先取消并等待实际所属执行者及其晚回执结束；仍有有效尝试时保留记录并报告等待。任务库事务在删除正式任务元数据前登记 `TaskCleanupPlan`，仅包含配置 Data 内任务自己拥有的输入和产物的精确相对路径、哈希及大小。工具归档、正式聊天正文和用户工作文件继续由各自的数据所有者处理，不递归删除工作目录。

文件清理失败保留同库重试计划，启动可重试；文件已不存在视为幂等完成，文件内容变化或链接路径拒绝删除。计划完成前拒绝在该聊天重建任务，避免旧清理计划误删新的原文。清理所有关联任务状态、尝试、事件、操作、检查点、计量和产物元数据，不删除其他聊天依赖者的记录；依赖使用者先取消，避免继续使用已经撤销的前置条件。

当前永久清理按正式登记的引用逐项处理。如果产物文件已原子写入、随后的元数据事务失败，可能留有未登记的 Data 缓存对象；它不会成为正式证据，也未纳入本轮永久清理计划。因此不能把当前接口说成已验证“异常写入后的所有孤立缓存都被清零”。现有桌面删除仍使用可还原回收站，尚未把独立永久任务清理暴露为界面操作。
