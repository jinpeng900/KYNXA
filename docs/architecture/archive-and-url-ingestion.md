# 压缩包与明确链接资料

2026-10-13。复用资料快照、工作目录扫描、`retrieval.sqlite` 与现有 E5 链路；不创建第二套来源库或网页下载规则。

## 入口与范围

桌面“添加文件／文件夹”接受已注册的压缩格式；“添加链接”按行输入最多 64 个明确 HTTP(S) 地址。链接逐条提交，显示成功来源、失败链接及资料准备进度。仅抓取输入链接及通过既有公共地址规则的重定向，不爬取整站。普通状态查询保持 60 秒传输额度；链接导入使用独立 300 秒传输额度，不被普通请求上限再次截断。

正式 API 的旧文件请求保持兼容：

```json
{"scope":"project","projectId":"<工作UUID>","path":"<已授权文件或文件夹绝对路径>"}
```

链接请求不提供伪造的本地路径：

```json
{"scope":"project","projectId":"<工作UUID>","url":"https://example.com/guide.pdf"}
```

API 也支持明确的 `urls` 数组。`scope` 仍为 `user` 或 `project`，工作归属在正式目录中校验；网址不能扩大权限。网页、文档直链与压缩包直链使用同一导入入口，按实际 MIME、魔数与格式注册表选择解析器。代理、DNS 与逐跳重定向校验来自现有 `web.fetch` 传输，不能因导入资料放宽私网访问规则。

## 压缩格式与隔离

ZIP、TAR、GZIP 与 BZIP2 使用现有 Rust 解码库。7Z、RAR、XZ、LZIP、ZSTD、LZMA、LZW 和历史归档格式接固定 `SharpCompress 0.50.5` ToolHost 子进程。包装 TAR 以流读取，不先加载整个展开后的 TAR。适配器不落盘解压，不执行成员或嵌入对象；不支持的算法、密码、分卷或损坏数据返回实际原因，不能当作成功文本。

成员逻辑路径拒绝父目录穿越、绝对路径、设备名、ADS、链接、歧义重复名称。限制原件字节、单成员字节、总展开字节、成员数、递归深度与展开比例；跳过的 TAR 记录也消耗真实展开额度。较重解码器受资源租约、进程树、私有内存、取消与超时约束；确认进程退出后释放预约。

默认复用当前索引的文件数、输入和总量额度，单成员上限为 32 MiB，递归默认 4 层。保护上限为成员 100,000、总展开 2 GiB、递归 8 层；这是有界处理合同，不是“所有用户应开到最大”的调优结论。未知归档和无法解析的成员保留诊断，健康成员继续进入同一索引。发布或数据库错误仍上抛，不能伪装成单个解析失败。

## 身份、窗口与生命周期

压缩成员保存外层原始 SHA、递归成员路径与各层 SHA、解析身份及正文窗口。虚拟路径保留代码扩展名，窗口身份另行进入来源 ID，避免语言识别失败或窗口覆盖。大型普通文本窗口保留 UTF-16 范围。

链接来源保存输入 URL、最终 URL、响应原始 SHA、HTTP 类型、抓取时间与实际网络路径；HTML 解码可使用真实响应 charset，但不能改写原字节哈希。正文快照和向量引用仍采用原有范围、版本与删除规则。

导入资料是已授权快照，原网站或原压缩包变化不自动替换已保存内容；重新导入和撤销沿用现有合同。挂载目录成员回读检查当前容器、成员与解析身份，旧版本拒绝读取。删除资料后旧引用不能继续取回。中断或未知导入回执须先刷新来源状态核对，界面不自动重放导入。

## 验证入口

- `retrieval::gateway_archives::tests`：真实 ZIP/TAR/压缩包装、路径与嵌套边界、取消、发布错误、正文窗口回读。
- `tests/archive_url_ingestion.rs`：显式运行的 Windows 原生 HTTP/E5 测试，包含 PPTX/XLSX/EPUB 压缩包成员、中英文查询、网址快照、私网拒绝、跨工作隔离、删除及原始字节变化。
- `tests/retrieval-client-smoke`：旧文件请求兼容、明确 URL/URLs、部分覆盖回执。
- `tests/archive-worker-smoke`：实际 ToolHost TAR.XZ 有界流成员与退出回执，覆盖非寻址解码流回绕故障。

独立测试使用临时 Data 和自有资料，不读取日常聊天或凭据。实际运行结果单独记录，不把已接适配器等同于所有压缩算法或所有安装环境已经验证。

## 本轮实际结果

2026-10-13 在 Windows 上运行 `archive_url_ingestion` 原生集成，17.30 秒通过。测试以当前 Rust 库启动独立 HTTP 网关和资源服务，使用实际内置 E5 Q8 CPU 推理：ZIP 中 PPTX、XLSX、EPUB 和中文 Markdown 共 4 个来源，首次生成 9 个向量；中英文查询和来源回读均成功。

明确的公共网址成功导入，私网地址返回 `WEB_URL_BLOCKED`。该任务语义准备完成，共 10 个向量，其中复用 9 个；被测试故意损坏的挂载 ZIP 单独记录 `ARCHIVE_INVALID_INPUT`，健康网址仍完成索引，整体状态为部分完成。跨工作隔离、导入快照不随原件改写、挂载旧哈希拒绝回读、删除后旧引用失效均通过。测试结束后独立资源进程正常退出。

这证明上述正式接线和生命周期，不评估生成模型回答质量，也不能外推所有压缩算法或大型语料吞吐。完整作业回执由 `KYNXA_ARCHIVE_URL_RESULT_PATH` 指定路径保存；开发运行默认记录在独立的 `artifacts/development/archive-url-ingestion-20261013/native-http-e5.json`，不进入用户资料。

同轮 Rust 归档 5 项、网页解码与正文 3 项、子任务写范围与未知回执 1 项定向回归通过；网页代理专用测试保留为明确未运行。最后复核 TAR.XZ 发现第三方流工厂回绕失败，改用平台流式 TAR 读取器后，实际 ToolHost 成员正文与完整退出回执通过，Win-x64 ToolHost 构建为 0 警告、0 错误。RAR4、RAR5、7Z、XZ、LZMA 与加密 RAR 的早先独立编解码回执仍保留；不声称这些算法全部再跑了一轮。
