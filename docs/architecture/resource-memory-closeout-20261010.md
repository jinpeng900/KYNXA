# 证据预算、资源组批与三层记忆收尾

基线：`663feebb`。本次保留统一数据与检索底座，只修改已有预算、来源核验、模型推理、索引及接口；不修改 B 的界面，不迁移个人数据。本文的额度是策略起点，不是已经测得的最优参数。

## 已落地的链路

### 上下文与证据

- 删除搜索前固定扣除长 notice 与 120 token 包装费的做法。实际投影统一计算真实提示、短引用和摘录；最终按必要输入、输出、工具声明、历史及已确认记忆后的真实剩余量批准。
- 自动取证起点普通 20%、文件 30%、复杂/研究 35%，分别封顶 8K、16K、32K。小窗口起点至少请求 1024 token，但授额仍受真实余量限制；余量不足必须记录原因，不能硬塞或擅自降低模型合同。
- 普通候选起点每通道 64、融合 96、最终最多 16；文件最终最多 24；复杂/研究起点 128、融合 160、最终最多 40。资源与策略上限分别为通道 160、融合 192、最终引用 60。内部候选身份与最终短引用分开；每次投影保护不限制整个任务累计回读量。
- 完整摘录均放不下时，保留能容纳的合法来源导航和 `knowledge.read` 入口。空摘录不算支持结论。最终去重保留周边内容的回读入口，不删除正式聊天。
- `ContextAssembly.budgetAudit` 与正式检索归档区分配置、模型请求、资源建议、实际批准、实际选入、token/字符用量及提前裁剪原因。未用工具额度可回收，不把预留当实际占用。

### 全局、工作、聊天记忆

- 一个 `MemoryService` / `MemoryRepository` 保持权威。全局确认记忆可跨工作；工作确认记忆只共享给该工作；聊天原文与聊天记忆只属于该聊天。正式工作没有挂载文件夹仍支持共享确认记忆，隐藏普通聊天容器不提供共享工作记忆。
- 常驻确认记忆仍最多 4K token，预算充足时保留原顺序；压力下按当前问题相关性及已确认偏好/决策排序，再做明确标记的原文摘录。失效、未确认及越范围条目不进入请求。详细确认记忆仍可走同一 RAG/回源链路，不另建数据库或模型。
- 完整注入的记忆原文参与最终检索去重，包括 JSON 引号转义后的多行记忆；摘录不冒充全文。实际 `memoryTokens`、批准 `memoryBudgetTokens`、三作用域数量及省略原因分开记录。
- 内部快照只跟踪本次投影条目的内容、版本、来源与归属身份。每轮准备及模型资源准入结束后再次核对，再构造上游请求；最终回答前也核对。等待期间删除/修改的旧记忆不继续派发。
- 变更只移除请求投影，保留有界失效通知、受影响 ID 与核验状态；通知被模型实际接收前不当作已修正。历史及已完成工具回执保留，不重放副作用。无关记忆更新不触发整轮重做；核验只回读已使用条目的来源。

### 资源、模型与组批

- 上游读取当前 `batchSuggestions`，可规划 32/64/128 块，并按长度、已拟合 token、256KiB 请求上限收缩。建议不是执行许可；模型执行仍经过唯一资源服务批准内存、CPU、GPU、token 与租约。
- CPU/显存需求按模型形状和观测峰值估算；有余量时申请更大的执行档位和必要的增量预约。热推理按 token 吞吐与序列长度类别比较，冷加载/排队不用于奖励扩张；吞吐下降、前台压力或 OOM 触发退避。
- 重排 20/40/60 建议依据实际可用资源，不再被检索阶段 CPU=1 永久钳成 20；重排执行另行准入。显式候选请求与资源规划上限共同产生实际额度并报告原因。
- q8 在不同批次下存在数值漂移。增加模型会话/执行档位的归一化输出资格检查，保留既有空间身份和既有资格门槛；失败回退到合格执行形状。诊断公开余弦、最大差异、是否严格等价，并明确 `retrievalQualityValidated:false`。这不是检索质量回归成绩。
- CPU 与独立 DML 配置的向量空间校验继续保留；GPU 尝试、混合算子及 CPU 回退如实报告。资源与模型失败不冒充 GPU 已正常运行。
- 默认任务总预算 30 分钟，显式任务可到 60 分钟，不再被默认外层 30 分钟静默截停。显式部署级外层上限仍有效并记录；生成计时从准备完成开始，单次模型响应/无内容超时另列，不与任务总时长混为一谈。

### 索引和文档覆盖

- 索引未完成时继续使用已发布词法结果；模型未就绪可报告 `partial`，不把未完成索引当完整语料未命中。
- 修复作业校验拒绝 `coverage.limit/limits` 的问题，扫描限额和实际生效值进入作业记录。覆盖统计不因报告明细有界而变错。
- PDF/DOCX 独立输入、提取正文及页数限额进入统一设置与 C# 共享接口。当前安全上限保留 32MiB / 2MiB / 100 页，可以配置更小的额度；不能宣称已经支持任意大文档。
- 失败链路报告原始字节哈希、有效限额、已处理页数、未处理/未覆盖范围及原文导航。失败未发布正文时明确 `publishedPages:0`，首次失败不伪造来源版本，按真实作用域写入 SQLite 覆盖记录。
- 批次取消等待原生推理排空，保留此前正式发布和缓存回执。新的测试等待器识别 `partial` 终态，不再假装任务挂起。

## 本轮不直接采用的建议

- 自动将普通聊天逐轮提取为已确认长期记忆：仍需要候选、去重、用户确认及治理流程，不因性能优化绕过确认边界。明确“记住”和手工保存立即生效。
- 64K 自动证据、ANN expansion 512、大规模并发：现有实际合同与质量对照不足；本次先贯通 32K 及有界资源探索，不把全部常量乘二。
- PDF 页窗口/OCR与大型解析→推理→发布流水线：还需扩展正式来源/窗口/版本协议。本次提供真实未覆盖报告，原文导航仅为入口元信息，不宣称自动窗口回读已实现。
- Linux、多卡及其他 GPU 平台：本轮不增加支持。

## 验证边界

本轮只做隔离短测：临时数据、回环 HTTP、合成文档、固定离线 E5 模型与 Windows Rust 资源协议；不运行完整公开基准或付费 Agent 大任务。真实 HTTP 覆盖 8K 短引用、三协议派发前记忆撤销、准备耗时不侵占生成期限、多行确认记忆去重。另覆盖 128→32 组批、取消、PDF101页失败覆盖、来源隔离、重排实际限额及未知副作用恢复。

本轮定向集成 19 个文件、248 项通过（隔离约18秒，主工作区复测约31秒）；资源/推理 7 个文件 69 项中67通过、2项原生模型测试按显式开关跳过、0失败；Windows Rust 13/13；C# 客户端34项、隔离HTTP19项通过。分组之间有覆盖重叠，不将这些数字相加当独立任务数；原生模型跳过项不算通过。

实际 CPU q8 的32/64/128档位均完成短推理与资格检查：最小余弦约0.997015、最大坐标差约0.011230，严格等价为false、检索质量未验收。GPU auto实际尝试DML，但遇到 `CPU_OPERATOR_FALLBACK_REQUIRED` 回退CPU，GPU验证状态为false，预约释放完成；未报告GPU速度收益。正式Windows x64资源包已按现有准备脚本离线构建，包含静态CRT、版本/哈希清单和原许可证，最终用户无需Rust/Cargo。

历史 benchmark 数字不当作本轮测试。GPU 回退与批次数值资格不代表 GPU 提速或检索质量已验收，完整质量/耗时对照留给用户后续测试。

可重复的构建入口如下；开发机需要项目声明的 Windows/.NET SDK 和可用的 Rust 构建缓存或工具链，最终用户不需要 Cargo、Node、Python 或另装向量数据库：

```powershell

  -p:RuntimeIdentifier=win-x64 -p:SelfContained=true `

  -p:AppxPackageSigningEnabled=false -p:AppxSymbolPackageEnabled=false `
  "-p:AppxPackageDir=$packageOutput"
```
