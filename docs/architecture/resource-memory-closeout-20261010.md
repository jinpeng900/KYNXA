# 证据预算、资源组批与三层记忆收尾

基线：`663feebb`。本次保留统一数据与检索底座，只修改已有预算、来源核验、模型推理、索引及接口；不修改 B 的界面，不迁移个人数据。本文的额度是策略起点，不是已经测得的最优参数。

## 已落地的链路

### 上下文与证据

- 删除搜索前固定扣除长 notice 与 120 token 包装费的做法。实际投影统一计算真实提示、短引用和摘录；最终按必要输入、输出、工具声明、历史及已确认记忆后的真实剩余量批准。
- 自动取证起点普通 20%、文件 30%、复杂/研究 35%，分别封顶 8K、16K、32K。小窗口起点至少请求 1024 token，但授额仍受真实余量限制；余量不足必须记录原因，不能硬塞或擅自降低模型合同。
- 普通候选起点每通道 64、融合 96、最终最多 16；文件最终最多 24；复杂/研究起点 128、融合 160、最终最多 40。资源与策略上限分别为通道 160、融合 192、最终引用 60。内部候选身份与最终短引用分开；每次投影保护不限制整个任务累计回读量。
- 完整摘录均放不下时，保留能容纳的合法来源导航和 `knowledge.read` 入口。空摘录不算支持结论。最终去重保留周边内容的回读入口，不删除正式聊天。
- `ContextAssembly.budgetAudit` 与正式检索归档区分配置、模型请求、资源建议、实际批准、实际选入、token/字符用量及提前裁剪原因。未用工具额度可回收，不把预留当实际占用。

### 全局、工作、聊天记忆

- 一个 `MemoryService` / `MemoryRepository` 保持权威。全局确认记忆可跨工作；工作确认记忆只共享给该工作；聊天原文与聊天记忆只属于该聊天。正式工作没有挂载文件夹仍支持共享确认记忆，隐藏普通聊天容器不提供共享工作记忆。
- 常驻确认记忆仍最多 4K token，预算充足时保留原顺序；压力下按当前问题相关性及已确认偏好/决策排序，再做明确标记的原文摘录。失效、未确认及越范围条目不进入请求。详细确认记忆仍可走同一 RAG/回源链路，不另建数据库或模型。
- 完整注入的记忆原文参与最终检索去重，包括 JSON 引号转义后的多行记忆；摘录不冒充全文。实际 `memoryTokens`、批准 `memoryBudgetTokens`、三作用域数量及省略原因分开记录。
- 内部快照只跟踪本次投影条目的内容、版本、来源与归属身份。每轮准备及模型资源准入结束后再次核对，再构造上游请求；最终回答前也核对。等待期间删除/修改的旧记忆不继续派发。
- 变更只移除请求投影，保留有界失效通知、受影响 ID 与核验状态；通知被模型实际接收前不当作已修正。历史及已完成工具回执保留，不重放副作用。无关记忆更新不触发整轮重做；核验只回读已使用条目的来源。

### 资源、模型与组批

- 上游读取当前 `batchSuggestions`，可规划 32/64/128 块，并按长度、已拟合 token、256KiB 请求上限收缩。建议不是执行许可；模型执行仍经过唯一资源服务批准内存、CPU、GPU、token 与租约。
- CPU/显存需求按模型形状和观测峰值估算；有余量时申请更大的执行档位和必要的增量预约。热推理按 token 吞吐与序列长度类别比较，冷加载/排队不用于奖励扩张；吞吐下降、前台压力或 OOM 触发退避。
- 重排 20/40/60 建议依据实际可用资源，不再被检索阶段 CPU=1 永久钳成 20；重排执行另行准入。显式候选请求与资源规划上限共同产生实际额度并报告原因。
- q8 在不同批次下存在数值漂移。增加模型会话/执行档位的归一化输出资格检查，保留既有空间身份和既有资格门槛；失败回退到合格执行形状。诊断公开余弦、最大差异、是否严格等价，并明确 `retrievalQualityValidated:false`。这不是检索质量回归成绩。
- CPU 与独立 DML 配置的向量空间校验继续保留；GPU 尝试、混合算子及 CPU 回退如实报告。资源与模型失败不冒充 GPU 已正常运行。
- 默认任务总预算 30 分钟，显式任务可到 60 分钟，不再被默认外层 30 分钟静默截停。显式部署级外层上限仍有效并记录；生成计时从准备完成开始，单次模型响应/无内容超时另列，不与任务总时长混为一谈。

### 索引和文档覆盖

- 索引未完成时继续使用已发布词法结果；模型未就绪可报告 `partial`，不把未完成索引当完整语料未命中。
- 修复作业校验拒绝 `coverage.limit/limits` 的问题，扫描限额和实际生效值进入作业记录。覆盖统计不因报告明细有界而变错。
- PDF/DOCX 独立输入、提取正文及页数限额进入统一设置与 C# 共享接口。当前安全上限保留 32MiB / 2MiB / 100 页，可以配置更小的额度；不能宣称已经支持任意大文档。
- 失败链路报告原始字节哈希、有效限额、已处理页数、未处理/未覆盖范围及原文导航。失败未发布正文时明确 `publishedPages:0`，首次失败不伪造来源版本，按真实作用域写入 SQLite 覆盖记录。
- 批次取消等待原生推理排空，保留此前正式发布和缓存回执。新的测试等待器识别 `partial` 终态，不再假装任务挂起。

## 本轮不直接采用的建议

- 自动将普通聊天逐轮提取为已确认长期记忆：仍需要候选、去重、用户确认及治理流程，不因性能优化绕过确认边界。明确“记住”和手工保存立即生效。
- 64K 自动证据、ANN expansion 512、大规模并发：现有实际合同与质量对照不足；本次先贯通 32K 及有界资源探索，不把全部常量乘二。
- PDF 页窗口/OCR与大型解析→推理→发布流水线：还需扩展正式来源/窗口/版本协议。本次提供真实未覆盖报告，原文导航仅为入口元信息，不宣称自动窗口回读已实现。
- Linux、多卡及其他 GPU 平台：本轮不增加支持。

## 验证边界

本轮只做隔离短测：临时数据、回环 HTTP、合成文档、固定离线 E5 模型与 Windows Rust 资源协议；不运行完整公开基准或付费 Agent 大任务。真实 HTTP 覆盖 8K 短引用、三协议派发前记忆撤销、准备耗时不侵占生成期限、多行确认记忆去重。另覆盖 128→32 组批、取消、PDF101页失败覆盖、来源隔离、重排实际限额及未知副作用恢复。

本轮定向集成 19 个文件、248 项通过（隔离约18秒，主工作区复测约31秒）；资源/推理 7 个文件 69 项中67通过、2项原生模型测试按显式开关跳过、0失败；Windows Rust 13/13；C# 客户端34项、隔离HTTP19项通过。分组之间有覆盖重叠，不将这些数字相加当独立任务数；原生模型跳过项不算通过。

实际 CPU q8 的32/64/128档位均完成短推理与资格检查：最小余弦约0.997015、最大坐标差约0.011230，严格等价为false、检索质量未验收。GPU auto实际尝试DML，但遇到 `CPU_OPERATOR_FALLBACK_REQUIRED` 回退CPU，GPU验证状态为false，预约释放完成；未报告GPU速度收益。正式Windows x64资源包已按现有准备脚本离线构建，包含静态CRT、版本/哈希清单和原许可证，最终用户无需Rust/Cargo。

历史 benchmark 数字不当作本轮测试。GPU 回退与批次数值资格不代表 GPU 提速或检索质量已验收，完整质量/耗时对照留给用户后续测试。

## 后续缺口修复与短测

本节是在上述构建之后继续修改源码的结果，不能把上面的 MSIX 或正在运行的旧网关当作已经包含这些新增修改。没有重启运行中的桌面/网关，也没有提交或推送。

### 本次确认并修复

1. **未知执行结果与计量**：未知副作用只允许观察，单独最多 8 轮观察后以禁用工具的正常部分结果收束；总任务额度不重置，成功或未知操作不重放。受控后台终端以当前聊天的任务注册表、可信 PID/回执确认派发，保留原未知记录、核验回执及对应 ID。命令退出失败与“已经启动”分开，不认证任务成功。其他无法证明的副作用继续报告未确认。
2. **失败计量完整性**：最后一次失败、无工具总结失败、流中断、非流式截断、Responses 纯参数 delta/done 都计入已消耗生成量估算；done 快照不重复累计 delta。成功解码后先计量，再保存步骤，持久化失败或此时取消不漏记。资源准入未通过不计成已经调用模型，计时不包含准入等待。诊断不存原始工具参数，估计 token 不等于供应商账单。
3. **ANN 缩额**：先取得真实 RAM 额度再分片；后台再次缩额会在同一 scope/domain/model-space/generation 内拆为更小范围，合并重复建图作业。取消和磁盘保存失败不能标记 `preparedOnDisk`。默认自动阈值按观测精确扫描成本及批准容量有界调整；明确自定义阈值保持原样，缓存同时受数量和实际字节总量约束。
4. **资源服务恢复**：下一次 snapshot/acquire 可在 1–30 秒退避后重连自有服务，等待旧进程真实退出并恢复全部预约和已知执行器启动身份后才放行。旧 IPC 晚到不能影响新实例，等待队列重新走原生准入；缺包不循环启动，未知显存和内存债务保留。
5. **CPU/GPU 设置贯通**：嵌入的设备偏好贯穿 fit/embed/query、资源准入和 worker。新增独立 `local.rerankDevicePolicy: auto|cpu|gpu`，默认 `auto`，C# 增加末尾可选字段，旧界面补丁不覆盖新策略。重排使用独立 Router；CPU 策略不会影响外部生成模型。设置切换、禁用和清空配置经过安全退役，已接受请求及取消后的原生任务排空后才替代；状态读取不会把 CPU 改回 auto。
6. **文档额度与失败清理**：知识库及挂载回源传入当前输入、正文和 PDF 页数额度，存储的权威提取快照仍按当前正文/页数上限筛选。`DOCUMENT_DECODER_TIMEOUT` 属于暂时失败，最多重试一次，不永久缓存。完整发现清单包含仍活动的失败文件；删除、取消挂载及孤立旧行迁移能清除首次失败但未成功发布的覆盖记录。部分/截断目录清单不擅自删除旧覆盖，正式来源与历史作业保留。
7. **最终来源核验**：轻量依赖账本独立于 64 个原文摘录缓存，最多保留本任务 1024 个不同来源；容量不足显式报告，不能静默遗漏。直接回读、搜索实际返回的摘录和缓存命中都登记依赖，未选内部候选不登记，搜索摘录不冒充原文回读或支持认证。恢复总结同样核对来源及记忆，失效或核验不可用时标明相关结论未验证。
8. **小兼容缺口**：`.pyi` 与其他代码文件使用同一线索识别契约。

- 新增 `data/memory-candidates.mjs`，从正式保存的用户原话提取候选，不把助手、网页或工具内容自动变成权威事实。纠正、确认决策、用户明确完成阶段优先处理；普通聊天按 6–12 个新完整轮次及 2K–4K 新 token 的有界批次合并。算法是确定性原话抽取，不宣称模型语义总结。
- 候选使用原 schema 1 的 `draft`、来源消息与完整引文，默认属于当前聊天。只有用户原话明确指向工作或全局时才使用该范围。明确“记住：”保留立即确认的既有行为，普通自动候选须确认后才进入上下文和 RAG。
- 批次游标、撤销记录、来源校验和去重避免每多一句就重复提取；修改与确认继续使用 `expectedRevision`。来源移动、删除或改变后不能确认旧候选，也不因后台任务重新恢复被撤销记录。
- 正式消息保存后接入异步提取；完成回执重放不再次排队。任务阶段候选只在明确执行任务且受控回执 `checks-passed` 时触发，仍只保留用户目标，不把助手自报完成写成事实。
- `GET /api/memory/candidates`、`GET/PATCH /api/memory/candidates/settings` 暴露状态和配置，补丁为 `{ expectedRevision, patch }`。配置持久在既有用户记忆文件，使用独立设置版本，旧文件读操作不创建空配置或覆盖条目。
- 确认、修改、删除通过 `onMemoryChanged` 先串行撤销旧派生和引用，再选择性发布当前有效记忆。词法可用先于可选语义嵌入；草稿不启动索引。词法发布与删除使用同一提交屏障，语义发布前重新检查来源、范围及设备合同，旧嵌入不能恢复已删除内容。
- 后台队列合并同一身份的变化并限制为 256 条；延后的条目仍可由正式范围同步发现。补齐 chat 范围读取、清理微任务丢唤醒、取消排空和真实回执统计。`memoryIndexing` 区分已发布、部分语义、跳过、延后及错误，不以函数返回冒充发布成功。

### PDF 页窗口与 Windows OCR

- PDF 总页数与单窗口页数分开；超过 100 页可连续读取全部窗口。每个窗口保留绝对页号、局部 UTF-16 正文偏移、总页数、未覆盖范围与下一页，达到正文预算后在完整页边界结束；过大的单页明确失败。
- 窗口身份稳定绑定物理文件与起始页，版本同时绑定原始 PDF 哈希、范围、提取版本及 OCR 身份。回读参数为 `pdfPageWindow: { startPage, endPage, rawContentHash }`，文件改变后拒绝旧游标与引用，不把不同版本页面拼接成同一份资料。
- 导入与挂载扫描逐窗口推进；持久挂载清单保存 `documentWindows` 元数据，不保存整份正文，重启不会丢失后续页。后续窗口等待时，前面已完成窗口即可用于词法检索；覆盖状态明确区分暂时部分与完整。
- 图像页经隐藏 ToolHost 使用 `Windows.Data.Pdf` 和 `Windows.Media.Ocr`，只接收已授权字节及页号，不接额外文件路径，不启动前台窗口，不需要 Python。识别依赖操作系统已安装的 OCR 语言；缺失时返回准确类别，短暂失败缓存可恢复。
- OCR 窗口最多处理两个图像页以限制渲染内存，随后继续。取消先通知原生助手，必要时结束自有进程，观察真实退出后才释放资源。正文里的语言及 OS/适配器版本用于身份校验，不能冒充 Windows 未公开的识别模型权重版本。
- 单原始文件 32 MiB、单窗口正文 2 MiB/100 页仍有效；总文件、正文及索引额度继续由现有配置和真实资源限制，超限有覆盖说明，不承诺任意大小文件全部驻留内存。

### 索引流水线与资源协调

- 新增 `index-pipeline.mjs`，同批最多两个来源准备任务与嵌入消费重叠，单文件失败不阻断同批其他来源；所有接纳的工作在取消或消费失败后排空。正式发布保持有界批次及串行检查点屏障，不宣称 SQLite 写入与后续批次也完全并行。
- 当前批次正式回执及进度保存后才接纳下一批，继续保留逐源版本校验、失败覆盖和恢复检查点。预取不能越过取消、发布和优先级重排边界，发布无回执不能记为成功。
- CPU 不再受“线程数 × 4”批量硬限；32/64/128 的探索仍由实际获批激活内存、序列长度、模型形状及吞吐反馈约束，不能靠倍率越过预约。
- Windows NVML 增加逐进程显存观测，使用原生进程启动时间避免 PID 复用。同 PID 多租约只使用一次已兑现增量，旧缓存不转移占用信用。WDDM 返回未知时继续保留未知预约，不使用无法安全归属的共享显存计数放大额度。
- Ollama `/api/ps` 与 `/api/show` 接入实际驻留、上下文和模型形状，权重加载及 KV 扩展按已知条件协调。未公开的 KV 类型、并行槽及其他客户端活动明确为未知，按支持类型估算范围并保留余量；不能把单槽估算说成整台服务精确用量，也不擅自卸载用户模型。
