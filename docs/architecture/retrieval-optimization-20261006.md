# KYNXA 检索优化与 Agent 性能验收

本轮工作区未提交，不重启日常网关，不读取用户聊天。测量目标是固定基础模型下 KYNXA 的任务流程，不是基础模型排行榜。SciFact 的 300 查询 / 5183 文档用于检索组件回归；任务最终正确率由独立 Agent 验收记录，不能用 nDCG 代替。

## 当前落地

- 词法窄候选先执行 FTS、授权筛选和排序，再取完整行，避免每个来源重复触发匹配。40 条原样本逐 chunk 顺序和分数已核对；新的词频保留属于另一个质量变更，不能把等价 SQL 的提速归给模型。
- 文档词频版本 v2 与派生 FTS 渐进迁移；查询词仍去重。标题、真实章节和路径提供有界嵌入上下文，原始文本、偏移、哈希、撤销身份不改变。向量缓存记录文本上下文版本；旧版本不能混用。
- 按任务决定是否检索；简单社交跳过工具和模型资产加载，纯文件/终端执行省略自动证据检索，仍保留原工具循环和按需知识搜索。明确的资料续问保留当前问题及近期用户资料请求，无额外改写模型调用。代码和对话占用的窗口仍以真实输入预算约束。
- 48 候选经重复/重叠消除、MMR 和完整证据 token 预算选择；允许一份文档贡献多段不同证据。存在于实际当前上下文的片段不再注入；不因旧历史出现过就认为当前模型仍看得到。
- revision 缓存减少全量来源扫描，命中来源回读与范围/配置复核继续执行。弱/跨语语义证据给出回源提示，不将排序分数当答案置信度，也不直接中断聊天。
- 可选离线交叉编码器只在配置的复杂/研究请求中使用，普通请求不加载。它作为固定本机基线验证质量与耗时，不声称是最新权重。

## 如何评 Agent

固定同一个 DeepSeek 模型 ID、参数、工具范围、任务初态和任务预算；采用同任务的检索开/关配置对照。它是 RAG 配置消融，不冒称完整历史版本对照。模型与嵌入资产版本写入清单，密钥和原始连接地址不进入产物。固定任务集和标准答案先于运行建立，失败和超时都保留，不挑选成功轨迹。

主指标是实际任务完成率、答案中可核查事实、文件/应用最终状态，以及不必要工具调用。记录全部模型轮次、工具调用与错误、重复查询、总输入/输出 tokens、耗时分位数和失败消耗。只读回放和模拟上游测试验证运行时行为，不能充当真实 Agent 规划成绩。小任务集不等于公开完整榜单，更不能仅凭少量通过承诺任意任务成功。

现代基准入口与运行方式见 [Agent 验收说明](../../tests/agent-performance-benchmark/README.md)：BrowseComp-Plus（2025 / ACL 2026）适合固定网页语料；Agent Retrieval Bench（2026）适合编码上下文；LongMemEval / V2（2025 / 2026）适合用户与工作经验记忆；SWE-Effi（2025）适合预算下的任务成功与昂贵失败。借鉴它们的控制变量及 verifier，与声称完成其官方全量测试是两件事。

检索完整回归入口在 [retrieval-benchmark](../../tests/retrieval-benchmark/README.md)。原质量基线仅使用经逐排名一致性核验的等价快 SQL 执行器；原始分词和原向量不变。优化前后必须在相同完整语料、查询和证据预算下比较。缩减语料试测、完整组件测试、真实 Agent 小集和可选 NN 重排分别报告。

实测结果保存在忽略的 `artifacts/verification`；最终报告引用实际结果文件，发布及提交由用户后续指令决定。

## 已执行的完整检索组件回归

本节记录 2026-10-06 的实际离线运行。完整 SciFact 测试集包含 300 条查询、5,183 篇文档、22,858 个真实分块；339 对公开文档级相关性标注覆盖 283 篇相关文档。采用逐查询宏平均，不读取个人聊天、记忆、密钥或日常网关。查询和语料在检索前固定，标准答案只用于评分，不进入嵌入或排序。原始 ZIP 校验和、原文/分块哈希、查询顺序和模型资产版本均保存在运行清单。

这是一项 KYNXA 检索组件回归，不是 Agent 总分、聊天模型排名或生成质量评分。完整 SciFact 不等于完整 BEIR 多数据集；KYNXA 的分块、分块到文档聚合和候选限制也不同于其他系统，不能把以下数值直接与公开 SOTA 横比。中文续问、无答案、权限及端到端工具任务需要各自的验收，不能由英文科学文献排序推断。

| 固定项 | 实际设置 |
|---|---|
| 嵌入 | `Xenova/multilingual-e5-small`，384 维，q8；固定 revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78` |
| 原质量基线 | 冻结原分词、原分块正文嵌入；仅使用已核验等价的快 SQL 执行器 |
| 优化配置 | `han-bigram-code-tf-v2` + 真实标题/路径/章节上下文 `source-context-v1`；原文偏移与 384 字符分块边界不变 |
| 可选 NN | `Xenova/bge-reranker-base`，q8；固定 revision `280bcc27a84e0b898c251e06fddb25171bd9b101`，重排初召回前 20 个分块（实际 19–20 个） |
| 推理运行 | 真实本机 ONNX，CPU 每模型最多 2 线程；没有模拟向量、Python 或付费生成模型 |
| 缓存 | 二进制 Float32 + manifest；原文、分块、嵌入输入版本和模型资产严格匹配才复用 |

原慢 SQL 在完整语料上成本过高，因此质量基线使用语义等价的执行优化，而没有更换原分词或向量。原 40 查询的词法与混合结果各 40/40 逐分块 ID、顺序、分数完全一致；另外对 5 条查询运行原 SQL，两种排序也完全一致。独立评分脚本从公开 qrels 和实际排序重新核验了 42,140 个指标值，没有调用被核验的指标 helper。

### 文档级原始排序

以下数值为百分比。nDCG@10 看相关文档的排序质量，MRR@10 看首个相关文档的位置，Recall@10 看相关文档覆盖。原始候选排序与最终选入上下文的六分块覆盖分开报告。

| 配置 / 检索面 | nDCG@10 | MRR@10 | Recall@10 |
|---|---:|---:|---:|
| 原质量基线：词法 | 62.156 | 58.975 | 75.206 |
| 优化：词法 | 63.818 | 60.774 | 76.189 |
| 原质量基线：混合 | 66.639 | 64.060 | 78.183 |
| 优化：混合 | 67.566 | 63.965 | 82.200 |
| 优化：混合 + 实际 BGE 重排 | 66.402 | 61.763 | 83.644 |
| 原质量基线：纯向量诊断 | 61.792 | 59.090 | 73.611 |
| 优化：纯向量诊断 | 64.247 | 60.900 | 78.361 |

纯向量诊断是全量真实余弦相似度、按文档最高分块聚合的消融项，不代表生产混合链路。TF 与嵌入上下文是组合变更，本表不能分别归因给某一个改动。

优化混合相对原质量基线：nDCG 增加 0.927 个百分点、Recall 增加 4.017 个百分点，但 MRR 下降 0.094 个百分点。按 300 查询配对 bootstrap、固定种子 20261005、2,000 次重采样，nDCG 差值的 95% 区间为 −1.155 至 +3.025 个百分点，跨过零；Recall 差值区间为 +1.033 至 +7.083 个百分点。不能据此宣称排序普遍显著改善。

BGE 相对优化混合：Recall 增加 1.444 个百分点，nDCG 下降 1.164 个百分点、MRR 下降 2.202 个百分点。nDCG 差值区间为 −3.741 至 +1.328 个百分点，同样跨过零。它提升部分覆盖但损害前部排序，并增加实际耗时，保持可选且默认关闭合理。

原种子 40 查询 / 500 文档也原样复测，查询 ID 与文档 ID 数组完全相同：混合 nDCG 80.908 → 81.042，Recall 87.500 → 90.000，MRR 79.861 → 79.167；词法 nDCG 76.604 → 75.812。缩减语料包含正例，分数较乐观，不能把它的 80.9 与完整语料的 67.6 解释为优化下降。

### 第一阶段按预算投影后的资料覆盖

在短引用接线前，用已保存的真实排序和只读公共索引执行当时的纯函数：选择前预留 `EVIDENCE_NOTICE` 的估算 token 加 120（该次合计 368），再经 `projectEvidence` 和有界最终重投影。每次最多 6 个完整分块、10,000 字符，已有上下文为空；8,192 档启用研究回源提示。计算完整 JSON 记录、引用和提示文字，未把长引用从预算中忽略。以下保留第一阶段的真实观测，不冒充后续短引用投影的重新评分；短引用的预算收益也不能归给文档排序模型。

这模拟的是提示投影组件，不是再次调用模型或宣称提供方真的收到这些材料；没有在此评分项目/聊天授权、来源新鲜度、真实会话窗口余量。生产协调器仍负责这些检查，实际任务可能被最终输入预算进一步收缩。Recall 只按文档级 qrels 判断材料覆盖，不是证据句正确性、回答充分性或引用忠实度。

| 总证据预算 | 原质量基线覆盖 Recall | 优化覆盖 Recall | 优化 + NN 覆盖 Recall | 平均最终分块数（基线 / 优化 / NN） |
|---|---:|---:|---:|---|
| 2,048 | 57.178% | 55.661% | 55.844% | 1.937 / 1.880 / 1.873 |
| 4,096 | 67.994% | 69.978% | 67.594% | 4.053 / 4.010 / 4.027 |
| 8,192 | 73.478% | 72.339% | 73.661% | 6.000 / 6.000 / 6.000 |

优化相对原质量基线在同预算下：2,048 档下降 1.517 个百分点、4,096 档增加 1.983 个百分点、8,192 档下降 1.139 个百分点。8,192 档优化平均选择 3.99 篇不同文档，原质量基线为 4.393 篇；同文档多段可能补全细节，也可能减少跨文档覆盖。本实验未标注证据句，不能直接断言哪一方更能回答。

投影后的平均保守估算 token，三组分别为：2,048 档 1,831 / 1,806 / 1,804；4,096 档 3,597 / 3,592 / 3,600；8,192 档 5,314 / 5,348 / 5,347。预算变大允许更多证据，与同预算算法提升是两件事。

原 runner 还保存了只执行选择器、未扣通知和最终投影的 `evidenceBudgetSweep`：2,048 档 Recall 为 62.094 / 61.856 / 58.500；4,096 为 69.394 / 71.089 / 69.761；6,144 与 8,192 均为 73.478 / 72.339 / 73.661。它们是选择器消融，不能冒充最终入提示覆盖。`chunkPrecision` 和同文档重复槽位也仅是文档级代理指标，不等于相同文本重复或事实准确率。

### 实际耗时与资源

在其他自有原生测试结束后，使用两组已完成索引独立补测；同 300 查询、同顺序、同本机、同 warm E5，每个观测都真实重新计算查询向量，没有读取查询向量缓存。冷加载和第一条预热查询排除，原始首次测量仍保留。两组顺序执行，未停止系统或用户其他进程；这不是跨机器性能承诺。

| 暖态检索组件 | p50 | p95 |
|---|---:|---:|
| 原质量基线：混合，已等价提速 SQL | 411.05 ms | 534.20 ms |
| 优化：混合 | 431.82 ms | 506.12 ms |
| 原质量基线：查询嵌入 | 6.00 ms | 9.15 ms |
| 优化：查询嵌入 | 6.05 ms | 8.81 ms |

混合耗时包含查询嵌入与索引检索，不包括网页、模型生成、最终证据选择或整项 Agent 任务。相对等价快基线，优化 p50 变慢、p95 改善，不能写成整体普遍更快。

同 40 / 500 原慢 SQL → 优化的混合 p50 为 1,412.05 → 43.45 ms、p95 为 2,584.89 → 48.21 ms；主要收益来自窄候选 SQL 修复，而不是 E5 推理变快。完整语料文档嵌入阶段，原基线约 369.44 秒、优化约 399.03 秒；真实元信息增加了索引输入成本。

完整 BGE 300 查询实际重排无输入截断，其额外耗时 p50 为 917.51 ms、p95 为 1,606.73 ms；重排加选择 p50 为 924.15 ms、p95 为 1,613.81 ms。不同阶段的 p50 不能直接相加当整条链路 p50。NN 进程峰值 RSS 约 1.257 GiB，含自有 worker；原完整基线约 1.082 GiB、优化约 1.103 GiB。这些是测试进程峰值，不是桌面最低内存，也不是模型文件大小。

本轮固定 `deepseek-flash` 的合成五类任务、两次交换顺序对照共 20 次运行见 [Agent 任务实测](agent-performance-verification-20261006.md)。v3 限定验收为检索开启 10/10、关闭 9/10；唯一关闭失败未明确写出 ORION 名称，资料事实本身正确。开启组输入多约 30.2%、任务时间多约 9.2%，不能宣称整体提效。该小集不是公开 Agent 榜单，实际浏览器与长程任务不在本次范围内。

## 第一阶段 sourceRef 长串开销审查

[资料引用合同](../../apps/model-gateway/data/retrieval/retrieval-contracts.mjs) 将 `sourceId`、`scopeKey`、`sourceRevision`、`contentHash` 与可选 `chunkId` / `chunkHash` 编码为 `rag1:` + base64url JSON。第一阶段审计时，[证据记录与预算](../../apps/model-gateway/orchestration/retrieval/candidate-selection.mjs) 和 [提示投影](../../apps/model-gateway/orchestration/retrieval/source-projection.mjs) 每段都包含完整 `sourceRef`；后续已新增短引用模型视图，详见下节。引用本身不授予权限；回读仍校验当前授权范围、来源版本/内容哈希及分块哈希，过期引用会明确拒绝。

从完整优化的 300 查询、每条 6 段得到 1,800 个真实公共证据记录，按仓库保守 `estimateTokens` 计算：

| 平均项 | 实测值 |
|---|---:|
| `sourceRef` 字符数 | 487.60 |
| `sourceRef` 单独估算 token | 485.60 |
| 完整证据记录估算 token | 829.36 |
| 同记录去掉 `sourceRef` 后估算 token（仅审计） | 334.76 |
| 引用字段及其 JSON 开销差值 | 494.60（约完整记录的 59.6%） |
| 摘录正文单独估算 token | 170.16 |

这是现有保守估算器的开销，长无空格 ASCII 通常按字符计；不是 DeepSeek/OpenAI tokenizer 计数或付费 token 节省保证。公共 fixture 的 1,800 项 `sourceRevision` 均等于 `contentHash`，存在重复哈希；生产记忆或导入资料可使用独立版本，不能据此删除版本字段。分块 ID 自身也包含部分身份/哈希，完整 descriptor 又保留完整分块哈希。相同完整引用在多段及工具历史中出现，会继续占用上下文。

据此采用“只简化模型投影、保留正式引用”的方向：模型看到短句柄，后台按正式证据归档恢复完整 `rag1:`；工具边界解析句柄后仍走原回读校验。普通显示编号不够承担 `knowledge.read` 的稳定回源能力。

短句柄绑定证据归档和条目位置，解析依赖当前聊天中的正式回执、有效工作关联及授权范围，不建立跨聊天全局 `r1` 表。来源变化或撤销后不能回放旧正文；正式记录支持同聊天后续请求和重启恢复。原完整 `sourceRef` 保留在归档、证据引用与新鲜度链路中，原 API 继续兼容。

第一阶段只做了审计，未修改协议；随后改变的是模型投影，`rag1:` 原协议仍保留。不能通过删减/截断哈希、版本、范围来换预算，也不能停止计算实际序列化提示的成本。保守估算开销与真实提供方计费应继续分开报告。

## 第二阶段：短引用、缺口回读与观察投影

以下是第一阶段评分之后接入的机制，不把历史组件评分当成本轮新测试，也不预先承诺 Agent 成功率或 token 节省。实际端到端模型验收由 [Agent 性能验证](agent-performance-verification-20261006.md) 单独维护。

### 短证据引用与正式回执

[EvidenceReferenceStore](../../apps/model-gateway/data/retrieval/evidence-references.mjs) 增加固定 29 字符的 `ev1:` 模型句柄，包含可逆的证据归档 UUID 和条目号。自动证据提示及 `knowledge.search` 模型视图使用短引用，去掉重复身份/哈希字段；正式归档仍保存完整 canonical 来源元组。公开本机结果与模型投影分开，回源字段没有直接被截短成残缺哈希。

`knowledge.read` 同时接受原 `rag1:` 和新 `ev1:`。短句柄解析先定位当前聊天正式助手记录中的 `RetrievalResultRef` 或 `knowledge.search` 工具回执，再检查 request ID、call ID、工具名、归档 bytes/SHA、条目号和完整来源字段。随后仍通过当前索引与协调器校验范围、来源内容/版本及撤销状态；归档引用不能成为读取其他聊天或工作文件的权限。内部发布早于日志保存时，受信解析入口只接受本次请求身份，不能作为模型参数暴露。

短句柄可在同聊天保存重开和后续请求中恢复，不依赖进程内临时 Map。两次复用同一检索结果仍产生各自的正式归档和短句柄，完整来源身份相同；不能把上次调用的回执重新分配给新调用。正式归档或回执缺失、内容校验失败、工作关联变化及来源失效都会明确拒绝，不能静默读回旧正文。

目前的 29 字符长度是合同与功能验证，不是计费 token 数。第一阶段长引用平均 487.60 字符的观测提供优化动机；第二阶段实际 DeepSeek 复测结果见 [任务验收](agent-performance-verification-20261006.md#第二阶段短引用缺口回读与观察投影)，新的总体入上下文覆盖仍需独立组件实验，不能直接按字符比宣称同倍成本下降。

### 缺口驱动的追加检索与章节窗口

[EvidenceAcquisition](../../apps/model-gateway/orchestration/retrieval/evidence-acquisition.mjs) 由 [协调器](../../apps/model-gateway/orchestration/retrieval/coordinator.mjs) 按请求维护，记录检索额度、具体缺口、成功候选和当前来源观察。`knowledge.search` 新增可选 `gap`，说明缺少的事实或条件；兼容未提供 gap 的现有调用，并不新增每轮必须调用的判定工具或独立 LLM judge。

普通模型在原有规划轮中核对实体、时间、范围与条件，然后选择直接回答、回读已有来源或按缺口搜索。程序不把 40% 词面覆盖、RRF/NN 分数、出现原文引用或新观察数当作语义充分性。返回的 `acquisition.sufficiency` 和 `evidenceDecision.sufficiency` 均为 `not-evaluated`；`evidenceAssessment.state = usable` 仍只表示检索材料的可用性。

| 本地请求档位 | 总索引搜索上限 | 同缺口索引搜索上限 |
|---|---:|---:|
| 普通 | 16 | 4 |
| 研究 | 48 | 8 |

相同规范查询、范围/配置、来源版本与投影参数的成功结果可在本请求复用；协调器串行化访问，避免同缺口并发重复执行索引。复用前仍回读并校验来源，空结果不缓存为缺口已解决。缺口文字变化不能绕过总额度；缓存失效后重新检查额度，不能在第四次搜索之后因失效缓存再执行第五次。配置的可选研究 NN 重排不以旧成功隐藏当前健康状态。

返回的 `newEvidenceCount` 是新观察分块数，不表示新增事实已经验证。预算耗尽仅限制追加本地搜索，保留 `knowledge.read`、文件读写与其他任务能力，正常告知尚缺信息；它不是答案已经验证、任务完成或用户取消。新请求重新建立额度，正式聊天不断开。

[原文窗口](../../apps/model-gateway/data/retrieval/source-window.mjs) 为 `knowledge.read` 提供 `page`、`window`、`section` 模式。page 保留原 offset 分页；window 围绕命中分块或明确锚点读取附近原文；section 尽量在真实 Markdown 标题边界内回读。支持 ATX/setext 标题，围栏代码中的标题不作为章节；缺少可靠结构时退回有界窗口。最大 16,000 字符，原始 UTF-16 偏移和字符边界保持一致，返回裁切、下一位置等导航元信息。它不生成章节摘要、不改正文或分块索引，也不把整个目录树每轮塞给模型。

默认命中分块跨越标题时，不能按首个标题截掉分块后半段；此时退回有界 window，并返回最多 16 个相关章节导航、跨章节标记和范围覆盖状态。明确提供 anchor 时才选择对应章节。窗口不足以覆盖整个命中范围时保留裁切状态，不声称正文已经完整返回。

网页检索仍使用已有代理阶段预算：标准 2 次查询 / 6 页，深入 12 次查询 / 20 页。网页的 `gap` 和证据决策提示帮助规划，仍走现有阶段额度及重复观察机制；不能宣称 raw MCP 已具备上述本地 16/4 缺口 gate。浏览器显式操作、写入和测试的权限仍由各自代理控制。

上述安排借鉴 [Sufficient Context v3](https://arxiv.org/html/2411.06037) 的相关性与充分性区分，以及 [VikingRAG](https://arxiv.org/html/2609.11390v1) 的按缺口局部回读。它是轻量规则调度配合普通模型规划，不是论文独立 autorater、完整语义充分性分类器或经验边图，也不沿用论文的质量与节省百分比。

### 已核验的只读观察收缩

[观察身份与替代规划](../../apps/model-gateway/models/tool-observation-compaction.mjs) 配合 [ToolContextProjection](../../apps/model-gateway/models/tool-context.mjs)、历史投影和工具循环，缩短请求视图中的重复只读结果。当前仅考虑成功的 `filesystem.read`、`filesystem.stat`、`knowledge.read`；同目标、分页/窗口边界及完整正文重复，或者明确较新内容哈希/版本替代旧观察，才有可核验的替代依据。轮次变多、信息看起来旧或模型说“不需要”本身都不是依据。

`knowledge.read` 的重复比较只排除明确的引用/规划导航字段 `sourceRef`、`modelSourceRef`、`canonicalSourceRef`、`evidenceDecision`，使不同合法短句柄或缺口说明不遮蔽相同正文。真实正文、来源身份、版本、分页、章节、窗口裁切及未知元信息继续参与比对；工具调用参数与 gap 仍保留，不能把同源但不同语义窗口误合。

正式结果先按 call/request/tool 名称、bytes 和 SHA 验证，再生成短回执，注明重复或被新版本取代，并保留旧结果 `tool.result.read` 导航。工具调用及其结果仍配对，正式归档不删除；写入回执、错误、结果未知和原生不透明状态不作这种替代。章节结束不代表整份文件已经读完，不同窗口或章节不能因 `hasMore = false` 被合并成完整文件观察。

准备过程按本请求投影的 `inputBudgetTokens × 4` 限制累计归档验证 IO，每份引用最多验证一次；小结果预计不能节省 token 就不额外回读验证。归档损坏或校验失败保留原投影；取消等待已接纳读取结算后再停止，不丢失已返回的执行回执。最终模型请求仍按真实上下文预算收缩，完整原文可回查。

它借鉴 [AgentDiet v2 / FSE 2026](https://arxiv.org/html/2509.23586v2) 对无用、重复及失效信息的关注，但本轮采用可观察身份与版本规则，没有额外反思模型，也没有实现论文对语义无用信息的整体判定。论文需要额外 reflection 调用且未量化商业 API 的整体延迟；本项目不能直接宣称同样的成本或速度收益。

### 本轮独立集成验收

实际执行：`node --test apps/model-gateway/tests/retrieval-evidence-acquisition.test.mjs apps/model-gateway/tests/retrieval-evidence-acquisition-integration.test.mjs`，15 项通过、0 失败、0 跳过，约 4.72 秒。新增 [独立集成测试](../../apps/model-gateway/tests/retrieval-evidence-acquisition-integration.test.mjs) 占 10 项，使用真实临时 `ConversationStore` / `ToolService` / `RetrievalCoordinator` / SQLite 与正式结果归档；memory、嵌入不可用及可选 NN 健康状态使用隔离 fixture，没有调用真实 API 或读取个人 Data。

| 独立覆盖 | 实际结果 |
|---|---|
| 同缺口并发 | 索引仅搜索一次，两个调用各有独立 ID/SHA/bytes 回执及不同的 29 字符模型句柄，完整来源字段保持一致 |
| 空结果与局部额度 | 空结果不复用、不声称充分；同缺口第五次不执行，新的缺口仍受总额度约束 |
| 来源变更与撤销 | memory revision/内容改变、撤销及导入快照在目录版本未变时被改动，均不能复用旧结果 |
| 词面冲突 | 两份高词重合但日期相反的材料仍保留为证据，不自动升级为语义充分 |
| 跨语功能路径 | 模拟语义候选返回真实英文源，中文问题词面零覆盖仍可按原引用回读；这是功能检验，不是 embedding 质量评分 |
| 搜索耗尽后的工作 | canonical `knowledge.read` 与真实工作目录写文件、读回均成功，聊天上下文仍可继续 |
| 总额度与新请求 | 16 次总额无法靠新增缺口绕过；新请求恢复额度；失效缓存不会导致超过同缺口额度再搜索 |
| 可选 NN 健康变化 | 研究接口重新检查可选重排健康，旧成功不能掩盖后续不可用状态 |

这些是机制集成验收，不能冒充真实 Agent 规划、生成正确率或公开基准总分。整合后控制并发完整网关回归 836 项：835 通过、0 失败、1 个原生重排跳过；短引用实际 HTTP/重启回读与进展指纹 2 项均通过。最终定向的缺口/回读集成共 17 项通过，具体命令、首次并发超时复测与完整日志见 [第二阶段验收](agent-performance-verification-20261006.md#第二阶段短引用缺口回读与观察投影)。此前 SciFact 和历史桌面测试不计入这些新检查。

固定 DeepSeek 的新 20 次任务原评分为开启 10/10、关闭 8/10；两条关闭组失败有评分格式匹配边界，保留原分数并另作 [独立复核](../../artifacts/verification/agent-performance-benchmark/run-1791223504850-9d06bee6/independent-review-20261006.json)。开启组输入比前次减少约 14.1%、任务时间减少约 11.5%，导入/嵌入准备增加，计入准备合计仅减少约 5.4%。这些是同配置的小样本观测，不能归因全部给短引用、称统计显著或直接换算费用。
