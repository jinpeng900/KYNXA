# KYNXA 下一轮优化方案与来源

研究日期：2026-10-09。本轮新增作者论文资料、公开 Agent/检索框架源码和评测合同审查；只写研究文档，保留当前实现和冻结题目，没有运行新的模型/API 实验，没有提交或推送。

优先补齐当前任务与动作状态，验证现有多语检索，再对明确缺口有限补查。主模型继续选择排序候选；程序负责执行合同。现有 RRF、去重、多样性、来源版本缓存、可选重排和有界重试已有实现，下一轮应调优与测量，不重复建设。

## 有依据的优化顺序

| 优先级 | 优化与当前问题 | 具体方案 | 来源与成本边界 |
| --- | --- | --- | --- |
| P0 | 当前动作与任务绑定：否定/条件误放行、外语阻断 | 同一主模型决策轮看到原话、相关任务和候选，提出回答、观察或具体动作；附当前消息、任务、目标、限制、需要的真实回执引用。调用前复用 broker 参数/权限/版本检查。先影子评测，不直接删硬闸后信任模型 | OpenAI Agents SDK、ADK、LangGraph 支持模型提议与应用检查分开。结构合法、reason/confidence、原文引用都不能单独证明语义或授权；同轮元数据不必增加模型回合，但增加 token/本地检查 |

| P1 | 根据证据缺口补查：trial 只找到代码，缺退出协议 | 保留原查询分支，回读后将缺少的协议/概念写成中性问题，最多增加一条派生查询；记录新增词和依据。未经证实实体不成为硬限制；不自加年份、不改变否定/范围 | FLARE 作者对应章节、IRCoT 源码、此前 Rewrite What Matters。借按需补查，非复现训练收益；额外检索/回读及下一决策可能增加一轮，必须计总预算 |

## 最小接口建议，尚未实施

主模型提议的数据可含 `taskRelation`、当前 `userMessageId`、模型可引用的 `taskId/revision`、`toolName`、目标引用、原话约束出处、待核验前置条件及真实回执引用。控制器持有正式任务状态，核对对象/版本/权限，随后调用真实工具并保存回执。原始用户历史继续保留；模型看到的是相关状态投影，不把历史关键词当授权记录。

这是不可信的候选解释。引用能核对存在与范围，不能机械证明“这句话确实授权了此动作”；最终必须用真实主模型留出验证语义判断，并保留现有确定性执行检查。模型不能填一个 `authorized=true` 或 `conditionVerified=true` 就取得能力。后置否定、没有引号的转述、双重否定讨论也不能靠添加更长的正则词表承诺解决。

更详细的接口、领域分工和完整模型回合成本见[动作合同方案](agent-action-contract-proposal-20261009.md)。发现工具本身也可能有副作用：连接本机 MCP 服务可能启动进程，因此先用配置/缓存能力头供模型选择，真实连接延后到有效调用与既有资源合同检查；不能为了扩大候选提前连接全部本机服务。

若采用同轮元数据，应由 gateway 自有调用封装/计划接口承载，在边界剥离后仍按第三方工具原 schema 校验；不直接给任意 MCP schema 增加字段。若另设“规划模型→执行模型”阶段，或验证回调再调用模型，会增加串行调用，必须明记成本。已有授权的正常低影响动作无需一律新增确认流程。

条件要求分为用户描述、模型待检查项和工具已观察事实。例如“如果下载结束就打开，现在解释要求”不能马上执行；“若浏览器未运行就启动”可以先做符合当前权限的状态观察，再按实际结果执行相应动作。未观察到的条件不当作已成立，也不能因出现条件句就丢掉句中的其他独立要求。

补查不使用生成的猜测答案作为既定前提。例如参加者退出的问题应独立查 consent/withdrawal 条件，而非继续放大 abort 函数候选。中文 volunteer 概念可提出英语候选以验证；原查询始终保留，检索范围仍由真实授权决定。无答案时有候选只是排名输出，回读后不足则说明覆盖或证据缺口。

## 现有结果与下一步验收

当前冻结诊断：查询解释 36/50、工具闸门 42/58；40 题小语料中，可回答 34 题的任一正确来源 Top 5 为 33/34、全部必要来源 32/34。尚有 volunteer 完全漏检、trial 部分缺证，工具语义偏差也未消失。前两项不是主模型成功率；授权内的多余只读检索还应区别任务错误与效率浪费，现有标签不事后修改。

已有稳定词法子流程 plan/search/verify/read 均值 4.738→5.480 ms，增加 0.742 ms；不含 embedding、rerank、模型 API 或完整 Agent。下一步要按阶段实测，并计入模型轮次、token、费用、P50/P95 首个有用结果/最终结果、候选与全部事实覆盖、错误动作/错误阻断、旧任务污染、重复已完成动作和取消后余计算。

先以现有机制运行多语 hybrid 对照，同时冻结新的语义留出；随后在影子/隔离工具环境比较同轮主模型提议与当前硬词闸；最后只对实证缺口试一条补查。一次只变一个机制，全部失败保留，不能先全换再把提升归给某份提示词。所有这里列出的后续收益仍是待验证方案。
