## 3. 修改位置与前后端边界

### 3.1 展示与交互代码

生产改动全部位于 `apps/desktop`：

- `Views/ShellPage.*`：主页面接线、模型菜单、导航、搜索、发送和项目操作状态。
- `Views/ShellPage.PresentationActions.cs`：新增的导航、反馈、快捷键、查找、复制与导出接线。
- `MainWindow.xaml`、`MainWindow.xaml.cs`：标题栏菜单接线。
- `ModelManagementWindow.*`：模型窗口草稿保护及布局，其中 `EditorState.cs`、`Layout.cs` 是新增的 partial 文件。
- `ToolManagementWindow.xaml`、`ToolManagementWindow.xaml.cs`：工具管理搜索、切页和布局。
- `Controls/ConversationTranscript.cs`、`Resources/Transcript`：WebView 正文与原生宿主之间的复制确认、反馈和滚动行为。

新版没有把所有 UI 放在一个独立文件夹。窗口文件位于 `apps/desktop` 根目录，页面、控件、样式及展示服务分布在各自子目录，这是现有 WinUI 项目结构。维护入口见 [前端 UI 维护入口](../../apps/desktop/UI-COMPONENTS.md)。

## 4. 本轮发现并修复的问题

1. 切换会话时，旧 DOM 的迟到滚动通知可能取消新会话的首次滚到底部。现已核验会话身份与导航代次，并保留用户主动向上阅读或选择文字的行为。
2. 会话搜索结果复用了单行模型菜单的固定高度，所属项目一行被截断。现已设置独立结果行高，并检查真实 TextBlock 的完整显示边界。
3. 项目操作进入/退出忙碌状态时，需要同步重新计算发送按钮状态，防止操作完成后仍不可发送。
4. 新增快捷键必须识别已有工具审批弹窗。已使用生产审批窗口验证其焦点、审批身份和背后草稿均未被快捷键改变。

部分原生测试最初在弹窗退出、Pivot 切页动画尚未完成时继续下一步或截图。测试夹具已改为等待相应生命周期及完成的渲染帧；这些等待改动在测试目录中，不向生产页面加入固定等待时间。

## 6. 你如何运行与验收

1. 在 Visual Studio 中打开 `apps/desktop/KYNXA.Desktop.slnx`。
2. 选择 `Debug`、`x64`，确认启动项目为 `KYNXA.Desktop`。
3. 生成项目后按 `F5` 启动，使用新版打包的网关。若旧 KYNXA 窗口或旧网关仍在运行，先正常结束当前回复并退出，再启动新版，避免连接到旧接口版本。
4. 检查模型菜单搜索与配置入口；修改连接后切换连接或关闭窗口，确认未保存提示符合预期。
5. 打开两个模式的会话，各留一份未发送草稿，再用 `Ctrl+F` 切换，确认草稿能恢复。
6. 缩窄窗口后展开侧栏、查找会话，再恢复宽窗，确认侧栏宽度回到原设置。
7. 在真实模型回复中验证停止、向上阅读、选中复制及整段 Markdown 导出。

测试夹具的执行方法见各测试目录 README。模型和工具脚本可用进程级参数运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/model-ui-smoke/run.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/agent-ui-smoke/run.ps1
dotnet build tests/shell-migration-ui-smoke/ShellMigrationUiSmoke.csproj -p:Platform=x64
dotnet run --project tests/shell-migration-ui-smoke/ShellMigrationUiSmoke.csproj -p:Platform=x64 --no-build
```

以上 `ExecutionPolicy` 参数只作用于本次脚本进程，不修改 Windows 全局策略。原生 UI 夹具应串行运行；日常运行应用不需要先执行这些测试。

## 7. 后续多人开发与合并建议

- 后端仍维护正式配置、会话日志、目录版本、记忆和工具执行结果；前端读取这些结果并展示状态。不要把筛选结果当成完整配置保存，也不要让 UI 重写助手归档。
- 后续迁移按功能对照 `ShellPage.*` 的接线和新增 partial 文件，避免整份覆盖旧版 `ShellPage`，否则容易丢失新版的流式、记忆和工具状态保护。
- 新增界面优先复用现有样式、PickerMenu、布局规则和 UiText。需要新字段或路由时，由前后端先确定契约，再补充调用与模拟接口验证。
- 每次合并先构建，再按实际改动选择验证入口。涉及稳定 ID、取消、版本冲突或流式终态时，除页面外还要验证对应客户端边界。
- 知识库、定时任务及独立执行轨迹属于后续业务范围；不要通过显示按钮或占位文字宣称已经完成业务实现。

### 10.2 结束时间的数据范围

`CreatedAt` 是消息记录的创建时间，`DurationMs` 是网关本次流程的单调时钟耗时。准备流程先开始计时再写创建时间，重试又可能保留原创建时间，因此不能将两者相加冒充准确结束时刻。SSE 帧的 `createdAt` 也来自流开始时固定身份，不是最终帧产生时间。

本轮以 `MessageTimePresentation` 在前端用弱引用保存本机首次观察终态的时刻，保留原会话、当前请求对象及取消保护。迟到 `finally` 不覆盖首次观测；同 ID 重试的新消息对象不继承旧观测。没有修改正式消息字段、序列化、HTTP DTO 或后台存储。该时间仅属于当前消息对象的运行期展示，历史重新读取或应用重启后没有持久化记录，不能宣称已实现永久保存的服务器结束时间。

若后续要求历史记录也永久显示准确结束时间，应在前后端协同下定义独立的正式终态时间字段及兼容规则；本轮不通过 UI 推算或旁路写文件补造历史数据。

## 14. 聊天正文上方的 Ctrl+F 自动提示修复（2026-10-07）

### 14.1 原因与修复范围

用户报告鼠标停在聊天正文附近时偶尔出现只有“Ctrl+F”的悬浮提示，滚动正文时提示仍停在原位置，等待或点击输入框后才消失。`ShellPage` 将 Ctrl+F、Ctrl+L、Ctrl+N 和 F1 注册在整个页面上，WinUI 默认 `KeyboardAcceleratorPlacementMode.Auto` 为所属元素显示首个快捷键的自动提示。该原生弹出层与 WebView 内部正文的滚动区域分离，因此正文滚动不会带着它移动。此行为与微软的 [Keyboard accelerators 官方说明](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-accelerators) 一致。

在 `Views/ShellPage.PresentationActions.cs` 的展示初始化中，将页面自身的 `KeyboardAcceleratorPlacementMode` 设置为 `Hidden`。仅禁止页面生成自动快捷键提示；四个快捷键注册及处理函数未改，搜索按钮原有的中英文完整 ToolTip、菜单文字和 F1 帮助继续保留。生产改动为这个界面文件的一处属性设置及双语注释，不改聊天渲染、消息、DTO、客户端、网关、模型或工具服务。

### 14.2 复现与实际验证

将修改前提交 `81de764` 导出到独立目录，让新增验收夹具直接链接旧版生产页面；旧版默认 `Auto` 在实际窗口悬停与长正文滚动中检测到裸 `Ctrl+F` 弹出层，对应断言失败。真实正文从 `scrollTop=5816` 滚到 `5516`，滚动距离为300像素，继续悬停后观测到自动提示。页面附加 ToolTip 的空值不能证明不存在提示，验收实际枚举打开的原生 Popup 并读取可见文本。
