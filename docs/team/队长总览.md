# 队长总览

配套：[五人分工入口](README.md)。本文是首轮执行计划；表中的未完成项不表示已建立 Issue 或已实现。

## 1. 队长的责任

A 是五人之一，同时负责 Host 开发。建议每周约 60% 时间开发，40% 用于接口、评审、联调和排障；排期时为这些工作留出容量。每天掌握五件事：本周能演示什么、谁被什么阻塞、接口是否变化、数据和执行是否可信、下一次集成何时完成。

第一轮最终验收：用户能在受控仓库中完成一次实际代码修复，拿到修改内容和测试证据；在中断后能恢复已确认状态，遇到不确定的文件或进程结果不会盲目重做。

## 2. 开工前两天要统一的决定

| 决定 | 建议基线 | 负责人/确认方式 |
|---|---|---|
| 实际投入 | 填五人姓名、技术特长、每周时数；P0 排期预留约 20% 联调与缺陷时间 | A 组织，五人一起估时；超容量就重新排期 |
| Host 语言 | 建议 .NET 10，与现有 C# 桌面和 R3 Host 方向衔接；README 中 Rust Host 描述需要统一 | A 写 ADR，E 复核数据接口；批准后更新架构入口 |
| 模型运行层 | 保留当前自有 Node 网关，集中做模型协议；首轮编排在 Host，不增加第二套任务状态机 | A、C 确认；历史外部参考不作为当前必需依赖 |
| 权限边界 | 独立 Rust Authority；执行工具只接受验证后的有限请求，不运行模型生成的任意 Shell | D 设计、A 复核；若能力不足，缩小首轮范围，不假装已经隔离 |
| 通信方式 | 建议 Desktop↔Host 用 Windows Named Pipe；Host↔网关保留本机 HTTP；Host↔Authority 用受限 IPC | A、C、D 定消息样例、身份校验、超时、版本和错误约定 |
| 首轮场景 | 一套小型示例仓库、一种已验证可用模型、一个固定修复流程；其他连接继续用于聊天 | A、C、D、E 选定并记录环境 |
| 名称与数据 | UI“项目”和 Work 的关系先写映射；工作身份不等于文件夹路径，无父子权限继承 | A、B、E 确认；不直接把旧项目 JSON 当成已完整实现的 Work |

上述选择是本轮建议，尚未修改实现或冻结正式协议。不要让一名成员按 Rust Host、另一名按 .NET Host 同时开工。若换语言，必须同时更新接口实现、构建链和排期，不能只修改架构图。

现有工作区有较多未提交实现。开工先备份、审阅并建立可编译的共同基线，再分支；不要用 `reset --hard` 或覆盖文件处理拉取冲突。真实模型密钥、用户聊天、模型权重不进入仓库。

## 3. 模块边界和文件负责人

| 模块 | 主要位置 | 主责 | 必须参与评审 |
|---|---|---|---|
| Host 与共享契约 | `apps/host/`（拟新增）、`apps/shared/` | A | E；涉及受保护执行时加 D |
| 桌面展示和交互 | `apps/desktop/Views/`、`Controls/`、ViewModels、资源 | B | 接口对应的 A/C/E |
| 模型协议与推理 | `apps/model-gateway/`，桌面 `ModelPresets.cs` 的模型元数据 | C | A；认证和凭据变更加 D |
| 权限与执行 | `crates/kynxa-authority/`、`crates/kynxa-executor/`（拟新增） | D | A |
| 数据与验证 | `apps/host/Persistence/`、`Context/`、`Verification/`（拟新增） | E | A；凭据迁移加 D |
| 集成与交付 | `tests/integration/`、`.github/workflows/`（拟新增） | E 实现测试汇总，A 管发布 | 各模块负责人 |

新目录只是建议落点，当前不存在的服务不能写成“接入即可”。B 维护桌面文件，E 通过 PR 与 B 配合替换桌面的业务持久化；C 提供模型元数据，模型管理窗口由 B 修改。跨边界改动先说明，不让多人同时大改 `ShellPage.xaml.cs`。

业务数据由 Host 单一逻辑写者提交；E 实现存储层，A 调用它推进状态。审批、凭据、授权消费等安全事实由 Authority 管理。UI 保存布局偏好，但不自行推进任务完成；网关只输出模型结果，不拥有任务完成状态。

## 4. 首周必须交付的接口包

由 A 管版本和合并，各提供方在第 3 天给出可运行替身，第 5 天做第一次端到端联调。以下是需要定义的接口，不是当前已有 API。

| 契约 | 提供方 → 使用方 | 最小内容 | 首次联调 |
|---|---|---|---|
| Work/Chat 命令与事件 | A → B | 创建/读取/取消；`workId`、`conversationId`、`operationId`、`requestId`、`sequence`、状态和错误 | 第 1 周 |
| 模型请求与增量事件 | C → A/B | 消息、模型、能力；文本增量、工具意图、结束原因、用量、取消 | 第 1–2 周 |
| 存储事务 | E → A | Work/消息/事件/检查点；版本冲突；原子提交；按游标重放 | 第 1–2 周 |
| 能力申请与执行回执 | D → A | 工作范围、工具、规范化参数、批准版本、执行 ID、结果和副作用状态 | 第 1–3 周 |
| 验证报告 | E → A/B | 测试退出码、日志引用、代码版本/哈希、验证结论；区分失败和无法验证 | 第 2–4 周 |

所有契约附成功、拒绝、超时、取消、旧版本、重复请求的样例。重传沿用同一个业务 `operationId`；事件按顺序去重。Desktop 切换会话后检查事件所属会话，晚到结果不得进入新会话。消息状态至少区分生成中、完成、中断、失败，不能用“收到文字”代替“任务成功”。

本机 HTTP 不是天然可信边界：新管理接口需要会话认证；Named Pipe 限制可访问用户并校验对端。具体方式由 A/D 定义，并纳入 D 的权限测试。

## 5. 六周里程碑

| 周次 | A：Host/队长 | B：前端 | C：模型 | D：权限/工具 | E：数据/验证 | 周末演示门槛 |
|---|---|---|---|---|---|---|
| 1 | 基线、ADR、契约、Host 骨架 | UI 回归清单、模拟事件接入 | 三协议行为表、流式接口替身 | 能力 schema、审批设计、进程骨架 | 数据 schema、迁移样本、修复样例 | 五人代码可独立构建；模拟消息贯穿 UI→Host |
| 2 | 命令与事件、普通聊天接入 | 流式显示、停止、错误状态 | 真实流式与取消、工具调用结构 | 范围内只读工具、凭据保护首版 | Work/消息落库、旧记录导入 | 真实聊天、停止、重启保留消息；旧聊天可查 |
| 3 | 有限步骤修复循环、审批等待 | 任务与审批面板 | 工具结果回传、上下文预算 | 批准后补丁写入、固定测试命令 | 事件事务、检查点、基础验证器 | 从 UI 批准一次实际修改并显示测试结果 |
| 4 | 失败修复、取消与预算上限 | Diff/日志/结果展示 | 模型异常处理、本地启停最小版 | 去重、进程停止、审计 | 验证报告、结果绑定、恢复数据 | 固定失败样例经有限修复后测试通过 |
| 5 | Host 重启恢复、旧实例隔离 | 恢复入口、长记录与 DPI | 断流、本地进程故障恢复 | 未知副作用核实、越界用例 | 迁移回退、故障注入、跨模型上下文 | 中断后恢复；不重复写入；不误报成功 |
| 6 | 冻结、集成、交付演示 | 交互缺陷收尾 | 模型连接回归、诊断说明 | 权限与凭据验收 | 集成报告、环境初始化脚本 | 新机器按说明运行；P0 用例全部有证据 |

若第 2 周流式和持久化未打通，停止增加新界面；第 3 周工具边界未通过，不扩大命令范围；第 4 周闭环未完成，P1 全部顺延。允许缩小模型和仓库覆盖，不删审批、数据保护和验证门槛来宣称完成。

## 7. 协作和交付规则

- 一项任务一个短分支，命名如 `feat/B-streaming-chat`；尽量一至两天提交一次可评审 PR。每个 PR 写问题、结果、接口变化和验证证据。
- 共享契约先合并，再实现两端；过渡期间保留旧接口适配，迁移完成再移除。新增构建项目须同时提交启动说明。
- 每日 10 分钟同步“完成、阻塞、今天交付”；阻塞超过半天就由 A 协调接口替身或重新排序。每周至少两次集成，每周一次可操作演示。
- 合并需模块评审和相关检查；权限、数据迁移、共享协议必须由对应负责人参与。每个人为自己的错误路径写测试，不只交成功截图。
- 完成定义：代码可构建、接入真实调用、正反例通过、数据迁移可恢复、日志可定位、文档可复现；UI 显示按钮或模拟服务返回成功不算实现完成。

可复用的当前检查命令（具体测试依赖按对应项目说明准备）：

```powershell
dotnet build apps/desktop/KYNXA.Desktop.csproj -p:Platform=x64
node --test apps/model-gateway/tests/*.test.mjs
dotnet run --project tests/ui-layout-smoke/KYNXA.UiLayoutSmoke.csproj
dotnet run --project tests/model-presets-smoke/KYNXA.ModelPresetsSmoke.csproj
dotnet run --project tests/code-highlighting-smoke/CodeHighlightingSmoke.csproj
```

原生选择复制回归使用 [Markdown UI 测试项目](../../tests/markdown-ui-smoke/)，需要 Windows 交互桌面。真实模型测试单独记录模型 ID、服务版本、硬件、提示、耗时和结果，不能把固定回复的模拟测试等同于模型能力验证。

## 8. 风险与队长看板

| 风险 | 预警 | 处理 |
|---|---|---|
| 五人投入不够、Rust 不熟 | 首周骨架或接口样例拖延 | 调整配对和范围；不硬塞全量 R3 |
| 前端不断微调挤占闭环 | 第 2 周仍只有静态页面 | 暂停非阻塞外观调整，先联通任务事件 |
| 模型无法稳定完成修复 | 工具调用不完整、循环失控 | 选经过验证的模型和固定样例，限定步数；如实报告失败 |
| 数据重复或丢失 | UI、Host、网关同时写会话 | 按版本切换单一写者，迁移前备份、比对，停旧写入 |
| 凭据和执行边界薄弱 | 密钥仍在配置；未批准命令能运行 | D 优先修复，阻止启用受影响功能 |
| 长会话卡顿 | 当前为跨消息选中保留所有消息控件 | B 做量测和按需加载方案；不得牺牲已确认的复制行为 |
