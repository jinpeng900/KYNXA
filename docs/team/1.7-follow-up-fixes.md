## 1. 按任务与风险选择证据，减少反复截图

目标：使用能够证明当前要求的最直接回执，减少无必要的截图、窗口切换和模型调用；真实视觉要求继续进行视觉核验。

行为要求：

- 打开本机软件时，优先复用启动工具返回的成功启动、进程或窗口回执。回执已能证明软件实际启动时，不再固定补截图、再次查找或重复启动。只有请求已接收、仍在运行或结果未知时，先通过相应只读状态查询核实，不能把未知当成功。
- 右侧文件或页面已经登记、存在且目标身份明确时，通常用工作区登记或状态回执确认展示；不能为了证明登记成功反复切换、截图。
- 用户明确要求看图或视觉检查、设计与建模质量验收、界面故障定位，或关键结果无法由已有回执判断时，才选择能解决具体疑问的截图或渲染图。设计与建模按有实质变化的版本或关键验收点取图，不把每一个小步骤变成截图步骤。
- 视觉结论必须来自模型实际收到并能观察的当前图像；图像路径、生成成功、历史截图或纯文字描述不能冒充“已经看过”。无法观察时如实说明并换用可用的核验方式。
- 核验复用原任务、来源版本与成功回执；来源变化或结果未知时重新核对相关部分，不重做已经成功的操作。界面操作确为用户任务的一部分时，保留执行能力。

验收要求：

1. “打开 Blender”等普通启动请求取得可靠启动回执后可以正常结束，不默认再调用截图，也不重复启动。
2. 产物已登记时，后续确认登记不会新增截图或改变当前标签。
3. 用户要求检查建模画面、界面错位或视觉质量时，能够取得并实际观察对应新图；不能为减少调用而跳过必要视觉验收。
4. 启动结果未知时，执行只读核验并保留原操作身份；不能据截图策略直接声明完成或盲目重新启动。

## 2. 右侧自动更新不抢用户当前标签

状态：待实现、待验证；本批没有将该项标记完成。

目标：模型可以登记和更新右侧内容，用户仍掌握当前浏览位置。

行为要求：

- 自动激活限首次初始展示，或者用户明确指定的目标标签、文件或页面；一次初始展示完成后，后台更新继续复用对应目标，不重复激活。
- 用户切到其他标签后，模型后台登记、刷新、预览完成及重连恢复不把用户切回去，不自动滚动或跳到另一页面；需要提示时使用原位更新状态或轻量提示。
- 用户明确要求“切到这个页面”“在右侧打开这个文件”时，允许激活指定目标；普通“继续处理”“更新内容”不隐含再次切换标签的授权。
- 使用工作区正常登记、更新与激活入口区分这些行为，不通过模拟鼠标点击绕过不抢焦点规则。正常建模、浏览或用户明确要求的界面交互能力不因此删除。
- 首次预览异步加载结束时，若用户已经选择了其他标签，不再迟到抢回；标签切换、任务引导及恢复后保留这一点。

措辞备注：截图反馈中的“指定的模型”，本轮按“右侧目标页面／标签”理解并保留记录，不据此新增更换 LLM 或模型分工的需求。

验收要求：

1. 模型首次展示指定成果后，用户切到终端；随后文件更新、预览完成或后台登记不能把终端切走。
2. 用户明确指定一个页面时，只切到那个目标；后台连续更新不会不断重选它。
3. 多个预览异步完成、切换任务或恢复软件后，当前选择保持一致；未发生模拟点击抢切。

## 3. 提高自动展示门槛，复用已有产物

状态：部分已实现。过程截图使用现有 `CatalogOnly`，默认不打开右侧标签或读取图片；资源入口、用户手动打开、明确 `artifact.open` 图片及最终产物保留。模型正常与紧凑提示、桌面 Skill 同步要求优先最终成果，截图仅按用户展示需求提供；必要视觉取证不受影响。完整原生 UI 场景本轮未运行，不将其记作已完成验收。

目标：右侧展示有用内容，避免每次产出都自动打开。

行为要求：

- 优先展示用户指定的内容、最终总结和关键交付产物；普通进度文字继续在聊天中简短汇报，不为汇报额外制造文件或标签。
- 临时截图、调试文件、验证脚本、草稿和中间渲染默认不自动展示；用户要求查看或它们确实是当前关键验收对象时，才登记展示。
- 同一路径、同一逻辑产物的更新复用原标签；刷新数据与版本不等于再次打开或激活。相同内容不重复登记。
- 不机械设置“四个标签”的固定上限。根据任务需要、用户选择和资源情况管理自动打开的数量；资源紧张时使用既有排队、按需加载和缓存机制，不关闭用户正在用的标签，不因此中断任务。
- 用户仍可主动打开更多文件、浏览器页面与终端；自动展示策略不缩减这些能力，也不阻止模型在已授权终端中执行命令。

验收要求：

1. 一次任务产生多份草稿和中间图时，默认只展示用户指定或关键最终成果；中间文件仍可被主动打开。
2. 同一文件反复更新仍只有原标签，内容与版本正确，且遵守上一节的不抢焦点要求。
3. 用户需要超过四个标签时可以使用；普通任务不会因生成很多临时文件而刷满右栏。
4. 后台预览加载和展示排队不阻塞聊天发送、停止、引导与任务恢复。
