## 1. 活动请求名额与完成缓存分开

- 代码证据：[gateway_runtime.rs](../../apps/agent-core/src/orchestration/gateway_runtime.rs#L853) 的 `begin_raw` / `begin_with_priority` 保留未完成请求及创建不足 1,800 秒的请求，随后按整个 `runs.len() >= 64` 拒绝新请求。30 分钟从创建时间算，并非完成时间。`active_requests`（约 1354 行）却只统计未完成请求。
- 影响：64 个近期创建且已完成的短请求也会挡住新任务，尽管没有对应数量的活动执行。相同请求 ID 的指纹核对和重连复用已经存在。
- 修复要求：活动准入与已完成重连缓存分别计量；保留缓存的容量和生命周期管理。不能通过立刻清空完成记录而破坏幂等重连，也不能删除正式聊天、成功回执或恢复身份。
- 短回归：64 个已完成请求后可接受新任务；真实活动任务仍受资源准入约束；同请求重连不重复派发模型或工具。

## 8. 大文件搜索与按行回读接齐

- 代码证据：[service_search.rs](../../apps/agent-core/src/tools/service_search.rs#L23) 允许搜索最多 16 MiB 的文件并返回行、列和 SHA-256；[service_filesystem.rs](../../apps/agent-core/src/tools/service_filesystem.rs#L197) 的 `read_page` 却先整文件读取，受 1 MiB 上限限制，之后才处理 startLine。因此即使只要几行，也可能先被整文件大小拦住。
- 限定：不是大文件完全不能读。[gateway_document_read.rs](../../apps/agent-core/src/tools/gateway_document_read.rs#L62) 的 document.read 可走普通来源读取，支持的文本默认按 maximumSourceBytes（32 MiB）读取并分页，核对 expectedSha256；已有索引窗口也能回读。
- 修复要求：补搜索结果到按行 / 范围读取的直接链路，或明确引导到兼容的现有读取入口。按实际窗口和输出预算有界读取，保留编码、行号、哈希、权限及取消。读写限额分别处理，不能简单扩大写入上限来解决读取问题。
- 短回归：2 MiB UTF-8 日志搜索命中后可按行回读；文件变化拒绝旧哈希；UTF-16、长行及跨窗口边界正确；输出和内存保持有界。

## 9. 统一新连接握手、快照与回放顺序

- 代码证据：[task_repository.rs](../../apps/agent-core/src/storage/task_repository.rs#L686) 接受任务时写入 task.accepted 并推进水位；[gateway_runtime.rs](../../apps/agent-core/src/orchestration/gateway_runtime.rs#L913) 将非零水位放入尚无控制事件的回放状态，spawn 后即返回。[gateway.rs](../../apps/agent-core/src/gateway.rs#L285) 的 `RequestEventStream::new` 随即执行 recovery(0)，而 runtime 约 523 行可能先发 content_snapshot；真正 started 尚待模型循环发布。[ChatStreamReader.cs](../../apps/desktop/Services/Models/ChatStreamReader.cs#L60) 要求每个新 HTTP 流首事件为 started。
- 另一路可达窗口：runtime 的 reply_anchor 清理旧 controls 后，新连接也可能先收到锚点。已有连接与新连接不能按同一种握手方式补事件。
- 初始核查时的影响边界：源码确认存在竞态，当时尚未执行隔离或本机复现。本轮已补隔离及实际 SSE 合同回归；不能把 UI 拒收、反复观察直接说成后台任务必然停止、上下文丢失或操作重做。
- 修复要求：新连接先提供合法 started 和稳定身份，再发送快照 / 回放；同连接 lag 恢复按既有水位去重，不重复插握手。保留完整快照、回复锚点、分段顺序、授权范围与只读恢复，不通过删除快照或简单放宽客户端身份校验解决。
- 短回归：非零账本水位、空 controls、延迟 started 的首次订阅；reply_anchor 后新连接；正常及终态重连；同连接 lag。事件流送入真实 ChatStreamReader，每个新连接 started 恰一次，快照完整，模型及工具派发次数不增加。
