## 数据迁移怎么做

先读现有格式并制作脱敏样本，保留旧 ID 与导入映射，比较数量、顺序、正文和关联关系。导入完成前不切换正式写入；切换时停旧写者，验证后更新位置/版本标识。失败回到已确认的数据版本，不将新旧两套会话存储长期双写。

当前网关已按稳定聊天 ID 统一保存完整 JSONL；桌面只持有展示快照。旧版按模型分片的日志只作备份保留，不能凭文本相同猜测跨来源顺序或自动合并。继续迁移时沿用当前稳定 ID 和已确认消息映射，不建立第二套正式历史。

用户消息、完整/中断回复和事件状态已统一保存，再由上下文构建器选择本次模型所需内容。既不只依赖模型上下文窗口，也不将全部历史无限拼入每次请求。保留源消息引用，摘要标记为派生内容，不替代已验证事实。

Data 迁移复制聊天、附件、记忆、摘录、模型配置及桌面设置，校验完成后才切换位置指针并保留源目录；已有迁移与恢复回归。正式会话和记忆/摘录共用网关队列，移动或删除会话等待相关读写结束，不能在旧路径继续写入。保证范围是单网关拥有 Data，不承诺多个进程同时写同一目录。

## 记忆范围和验证职责

当前记忆已有聊天、工作、用户三种确认范围，保存来源、版本及删除约束。只有真实保存的用户消息开头确认指令或手动管理操作创建记忆，助手回复不自动晋升为长期记忆。同工作聊天共享确认的工作记忆，不自动共享整段历史；普通聊天和“不使用文件夹”的工作聊天只用各自聊天记忆与用户全局记忆。

来源聊天归档保留已确认记忆；删除暂停其来源记忆注入，撤销恢复；移出工作暂停原工作的来源记忆。手动条目不依赖来源聊天；明确删除记忆记录来源撤销，原请求重试不能恢复该条目。修改/删除使用范围版本冲突检查，B 应展示当前范围、来源和有效状态。

上下文按窗口预算选取，当前输入完整保留；旧对话摘录可重建且不包含长期记忆。算法是保守估算，非供应商 tokenizer。1M 是请求预算设置，不扩大模型能力，也不扩大输出：当前输出上限为 `min(2048, floor(contextWindowTokens × 0.25))`，独立输出配置与用户预算状态尚未实现。构建器内部已有入选/省略/摘录诊断，仍需公开给桌面。全文/向量检索、语义总结与自动学习未实现。

每个 Work 的身份与物理存储路径分离。普通聊天在 `Data/Chats/聊天ID/`，真实工作聊天在 `Data/Projects/项目ID/Sessions/聊天ID/`；关联外部工作文件夹只存工作文件，聊天与记忆仍由 Data 管理。不使用文件夹的聊天沿用隐藏项目目录，但不能通过该隐藏项目共享记忆。用户选择统一 Data 根已完成，每工作独立存储根仍需 E07 与 D 确认新路径授权、复制校验、切换时机和失败回退，B 提供相应页面；不能只改关联文件夹路径就宣称聊天迁移完成。

验证器优先检查测试退出码、约定测试是否实际运行、日志、文件和产物哈希，并绑定修复时的代码版本。测试没启动、日志缺失、结果过期分别给出原因；模型说“已修好”不能直接通过验证。

目录和正文拆分是读取优化；按需上下文检索是请求内容选择，二者分开验收。索引可以重建，原始历史不可由索引、摘要或 UI 缓存替代。

## 接手后的第一周与验收证据

第一天核对现有数据字典、写者和迁移基线；第二天与 B/C 固化记忆、诊断及输出合同；第三天提供目录/正文拆分接口和脱敏大记录样本；第四天对并发移动、删除、版本冲突与损坏恢复回归；第五天与 B 演示实际管理和加载结果。Host 的任务事务和验证器在 A/D 确定合同后推进。

交付 schema/迁移说明、脱敏数据样本、迁移前后比对、验证报告和故障注入结果。真实用户数据不用于破坏性测试。集成测试可以用确定性模型替身，另由 A/C 维护真实模型演示，不把两者混称为全部能力已经验证。

3226527 的网关 151 项回归及 WinUI 编译记录是已完成基线；现有 smoke 只证明对应合同或有限操作场景，不等同于长记录、所有 DPI/布局/选区或真实模型 1M 能力验收。性能报告须写明机器、样本、冷/热读取路径与指标；工具成功还必须另有当前代码版本的执行证据。
