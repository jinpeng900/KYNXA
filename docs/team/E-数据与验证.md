## 数据迁移怎么做

先读现有格式并制作脱敏样本，保留旧 ID 与导入映射，比较数量、顺序、正文和关联关系。导入完成前不切换正式写入；切换时停旧写者，验证后更新位置/版本标识。失败回到已确认的数据版本，不将新旧两套会话存储长期双写。

当前网关已按稳定聊天 ID 统一保存完整 JSONL；桌面只持有展示快照。旧版按模型分片的日志只作备份保留，不能凭文本相同猜测跨来源顺序或自动合并。继续迁移时沿用当前稳定 ID 和已确认消息映射，不建立第二套正式历史。

首轮统一保存用户消息、完整/中断回复和事件状态，再由上下文构建器选择本次模型所需内容。既不只依赖模型上下文窗口，也不将全部历史无限拼入每次请求。保留源消息引用，摘要标记为派生内容，不替代已验证事实。

## 记忆范围和验证职责

当前记忆已有聊天、工作、用户三种确认范围，保存来源、版本及删除约束；上下文按窗口预算提取，旧对话摘录可重建且不晋升为长期记忆。详见 [聊天与工作记忆架构](../architecture/chat-work-memory.md)。后续 Work 状态、执行检查点、全文/向量检索与自动学习仍需独立设计，不把本轮明确指令提取等同于完整自动记忆系统。

每个 Work 的身份与物理存储路径分离；将来迁移目录不改变 Work ID，也不自动继承其他工作权限。E07 要与 D 确认新路径授权、复制校验、切换时机和失败回退；B 提供用户设置页面。

验证器优先检查测试退出码、约定测试是否实际运行、日志、文件和产物哈希，并绑定修复时的代码版本。测试没启动、日志缺失、结果过期分别给出原因；模型说“已修好”不能直接通过验证。

## 第一周与验收证据

第一天整理现有文件格式；第二天与 A/D 确认事务和安全事实边界；第三天提供内存存储替身；第四天准备可重复失败的小仓库和对应断言；第五天接入 Host 并演示存取。

交付 schema/迁移说明、脱敏数据样本、迁移前后比对、验证报告和故障注入结果。真实用户数据不用于破坏性测试。集成测试可以用确定性模型替身，另由 A/C 维护真实模型演示，不把两者混称为全部能力已经验证。
