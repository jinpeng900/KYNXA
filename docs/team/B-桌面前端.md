# B：桌面前端与交互

[总览](队长总览.md) · [分工入口](README.md)

**你的成果：让任务过程、审批和结果看得见、操作顺畅，保住现有聊天体验。** 正式前端继续采用 C#、WinUI 3、XAML；不另起一套网页前端替代现有实现。

## 已推送基线（3226527）与当前工作区

截至 2026-10-02，现有链路是 WinUI 桌面 → 本机模型网关 → 已配置的模型服务，尚未新增 Host。以下能力已经落地，后续接入任务执行时沿用，不重复开发：

- 网关按稳定聊天 ID 保存统一 JSONL 正式记录；桌面持有展示快照。换模型、重启及迁移 Data 保留聊天身份，不按模型另建历史。
- 聊天、工作、用户三层确认记忆及查看/创建/修改/删除接口已经实现；工作共享记忆与各聊天正文隔离。桌面完整记忆管理入口仍待做，详见 [聊天与工作记忆架构](../architecture/chat-work-memory.md)。
- 模型连接可设置 8K、32K、128K、256K、1M（1000000）或自定义 2048–2000000 的上下文窗口；旧连接默认 8192。保存和测试均校验，实际可用窗口仍取决于模型服务及本地启动参数。
- 主聊天使用一个 WebView2 DOM 展示用户消息、正文、思考和表格；Markdown、代码高亮、KaTeX 公式可选择复制。流式合并更新变化尾部，保留活动选区，思考可展开/收起，打开聊天到底部，在底部发送后跟随回复增长。
- 数据根目录选择、迁移入口、最近/项目/任务区的聊天关联和发送后前置已实现。只有发送消息更新顺序，打开聊天不前置；项目默认折叠，最近独立展开，任务区列出当前工作的聊天。

统一记录迁移、可重建的 SQLite 元数据索引和记忆持久化由 E 维护；B 不建立第二份正式历史。现有“任务”区是工作聊天列表，不代表任务步骤、执行检查点或审批流程已经完成。

当前工作区另完成新增聊天交互修复，尚未提交或推送：项目行和任务标题的 `+` 共用内存草稿流程，任务区显示当前项目未发送的新聊天。两个入口重复点击仍只保留一个空草稿；同项目重选保留输入，切到其他项目丢弃未发送草稿，返回不恢复。正式存储和“最近”只收录已发送聊天，发送后才更新最近及未置顶顺序。

本轮工作侧栏 55 项检查通过，主 WinUI 构建零警告、零错误；实际 UI 检查覆盖两个入口、单一草稿、同项目重选、跨项目切换和返回，未发送操作前后目录版本（catalog revision）不变。151 项网关测试属于 `3226527` 的历史基线，本轮未重跑，不能用于宣称本轮完整模型或性能回归通过。

## 接手位置与边界

- `apps/desktop/Views/ShellPage*`、`Controls/`、`ViewModels/`、资源和 `ModelManagementWindow*`。
- 先读 [UI-COMPONENTS.md](../../apps/desktop/UI-COMPONENTS.md)，复用输入框、选择菜单、字体、间距、颜色和布局常量。
- 业务事件来自 A；模型数据来自 C；数据路径/历史来自 E；审批结果来自 D。界面不得自行授予权限或直接执行命令。

## 必须保留的已有交互

- 默认工作模式；聊天模式不显示项目功能；项目可展开且默认折叠；空白新会话不落入正式历史与“最近”。项目行/任务标题新增入口共用内存草稿，任务区可显示当前草稿；同项目重选保留输入，跨项目切换丢弃未发送草稿。
- 最近与项目分别展开；打开工作聊天同步当前工作和任务区选中项；只在发送后更新最近和未置顶顺序。
- 项目和聊天的悬停操作、置顶/重命名/归档/删除、统一字号与上下居中；不恢复选中项的蓝色竖杠。
- 模型和权限选择未悬停时融入输入框；模型菜单可滚动，自定义入口固定底部；项目选择区与输入框等宽连接。
- 右栏按窗口宽度出现、可收起、可拖动且有边界；分隔线明确，拖动不额外显示另一根线。
- 只有代码等 Markdown 区块适度灰底；普通文字保持原背景；代码高亮和中文排版保留。
- 跨用户/模型多条消息连续拖选；上下自动滚动；松手固定选区；Ctrl+C 和右键复制按顺序输出。

## 接手后的第一周与配合

第一天整理已有 UI 的可重复操作步骤及真实性能样本；第二天与 E/C 确认记忆、诊断和输出配置合同；第三天复用真实记忆接口完成最小管理入口；第四天联调目录/正文分开加载；第五天演示范围修改、删除、快速切换和异常恢复。Host 任务页面在 A/D 提供真实事件及审批合同后接入。

流式期间沿用增量 DOM 更新和后台 Markdown 解析，不每个 token 重建整段文档。当前跨消息选择使用浏览器 Range，聊天 DOM 与渲染 HTML 缓存已有容量边界；若引入分页或虚拟化，必须同时约定稳定消息 ID、选区跨加载边界、复制顺序及缓存失效，不能只测单条消息渲染。

验收材料：关键页面截图、T11/T12 操作记录、500 条混合消息和长代码块的内存/滚动记录、流式过程中选择复制的回归结果。性能数值写清机器与样本，不把既有 smoke 测试等同于完整 UI 验收。
