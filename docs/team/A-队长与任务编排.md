# A：队长、Host 与任务编排

[总览](队长总览.md) · [分工入口](README.md)

**你的成果：把已经能聊天的桌面程序串成能执行、验证和恢复工作的应用。** 不包办前端、模型协议、数据库和工具实现，通过约定接口集成其他四人的成果。

## 当前基线与接下来要补的部分

截至 2026-10-02，团队基线为 `3226527`。已实现的链路是 WinUI 桌面 → 本机 Node 模型网关 → 云端或本地模型服务，尚没有 `apps/host/`，也没有工具执行、任务状态机或受控代码修复闭环。

- **已实现：** 三协议文本流式回复、取消与中断状态、同聊天请求串行和去重；网关统一保存正式聊天日志，桌面读取其投影。
- **已实现：** 聊天、真实项目、用户三个范围的确认记忆，以及有来源校验的确定性旧对话摘录。工作内聊天共享项目确认记忆，不直接拼接其他聊天全文；普通聊天和无文件夹工作不继承项目记忆。
- **已实现：** 模型连接可保存上下文窗口，桌面可选择 1M；请求按预算保留完整轮次或使用有限摘录。1M 是请求配置，不代表任意模型或本地服务已经具备该容量。
- **部分实现：** 桌面自动启动模型网关、已有服务模型列表获取和手动本地启动脚本；推理进程的应用内启停、自动发现本机 Ollama 全部已配置模型仍待完成。
- **计划：** Host、Work/Run、工具与审批执行、工作检查点恢复、正式 ADR 和自动 CI。现有回归测试不能算这些新模块已通过验收。

近期按四组推进：第一组由 B/E 做确认记忆的查看、修改与删除，由 B/C/E 并行补独立输出配置；第二组拆分轻量聊天列表与按需正文加载；第三组定义 Host 契约并接入受控只读工具；第四组再做批准补丁、固定测试与验证闭环。自动发现和应用内启停本地模型、模型下载属于后续 P1，不阻塞前两组。

## 身份与单一正式记录

| 标识 | 当前/后续职责 | 不应混同的内容 |
|---|---|---|
| `projectId` | 当前已存在；组织工作空间、关联文件夹、项目内聊天和共享确认记忆 | 不是文件夹路径，也不是已经完成的执行任务 |
| `conversationId` | 当前已存在；稳定标识正式聊天，跨模型继续使用同一份记录 | 不是模型 ID、项目名或某次推理请求 |
| `workId` | 后续定义；描述目标、计划、状态、产物、验证和检查点 | 不直接把一个项目或聊天改名后当成完整 Work |
| `runId` | 后续定义；标识一次执行尝试及其工具、预算、取消和恢复状态 | 不覆盖 Work 身份，也不等同于消息的 `requestId` |

建议未来 Work 显式保存可空的 `projectId`，并关联已有 `conversationId`；同一项目可组织多个 Work，一个 Work 的聊天与执行尝试由关系记录连接。无项目的聊天仍能存在。最终映射由 A/E/B 评审后记录，表中的后续字段不表示已经添加到现有模型。

**当前正式聊天只有网关拥有的一份 `events.jsonl`。** Host 接入后通过会话接口提交、读取和关联它，不能在 `apps/host/`、工作文件夹、模型分片日志或 SQLite 中另存第二份可独立写入的聊天全文。Host 的任务事件、工具回执和 Work/Run 检查点可以有自己的持久记录，通过稳定 ID 引用聊天；目录与索引、上下文摘录和 UI 状态都是各自用途的投影，不替代正式聊天。

若后续确需更换正式聊天的存储所有者，必须先停旧写入、备份并校验迁移、切换协议和单一写者后再启用。不能让桌面、Host 和网关同时修改正式历史。确认记忆继续按聊天/项目/用户范围隔离，Host 构造上下文时复用有效来源与预算规则；不得将模型推测、任务摘要自动升级为用户确认记忆。

## 依赖与验收证据

当前从 C 可接收真实模型文本、增量和终止状态，从 E 可复用统一会话、确认记忆和有预算的上下文构造。接下来定义 C 的工具意图、D 的真实执行回执、E 的 Work 事务和验证报告，以及 A 向 B 提供的可重放状态事件；这些后续契约先接替身再替换真实实现，不等待四人全部完成才集成。

最近一次集成应先证明聊天回归不倒退：普通/项目聊天不串记录，项目确认记忆只在允许范围内共享；改名、关联文件夹、切模型与重启保持稳定 ID；8K 与 1M 配置的预算行为明确。此后再验收 Host 与受控工具闭环，不能把“工具意图已经显示”当作执行完成。

状态至少覆盖等待、运行、待批准、验证、恢复、成功、失败、取消请求和已取消。取消请求后必须等待执行停止与副作用核实；不确定结果进入待核实或阻塞，不自动重试写入。

最终提交完整演示记录：输入、模型/环境、候选修改、批准、测试日志、检查点、中断位置及恢复结果。使用固定替身测试状态机，再用真实模型跑同一验收场景，分别报告。
