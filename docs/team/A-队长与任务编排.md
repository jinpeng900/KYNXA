# A：队长、Host 与任务编排

[总览](队长总览.md) · [分工入口](README.md)

**你的成果：把已经能聊天的桌面程序串成能执行、验证和恢复工作的应用。** 不包办前端、模型协议、数据库和工具实现，通过约定接口集成其他四人的成果。

## 接手位置与边界

- 阅读 `apps/shared/ChatApiContracts.cs`、`apps/desktop/Services/ModelApiClient.cs` 和 `apps/model-gateway/README.md`。
- 主责拟新增 `apps/host/` 的进程、命令、事件和编排；E 主责其中 Persistence、Context、Verification。
- 共享契约由你维护版本。Host 不直接用任意 Shell 绕过 D 的执行入口，也不把模型回答当作验证报告。

## 第一周逐日安排

1. 第 1 天：记录五人投入与基线，列差异和技术决定；与 D/E 确定审批、事务边界。
2. 第 2 天：合并最小共享协议；确定演示仓库和模型；给各成员拆成可评审的小任务。
3. 第 3 天：Host 接收命令并输出带会话标识的模拟事件；让 B 开始联调。
4. 第 4 天：接入 C/E/D 的替身，验证超时、重复请求与错误呈现。
5. 第 5 天：组织第一次演示，重新评估后五周的容量和阻塞。

## 依赖与验收证据

从 C 接收模型文本和工具意图；从 D 接收真实执行回执；从 E 接收事务、上下文和验证报告；向 B 提供可重放的状态事件。不要等待四人全部完成才集成，先接替身再替换真实实现。

状态至少覆盖等待、运行、待批准、验证、恢复、成功、失败、取消请求和已取消。取消请求后必须等待执行停止与副作用核实；不确定结果进入待核实或阻塞，不自动重试写入。

最终提交完整演示记录：输入、模型/环境、候选修改、批准、测试日志、检查点、中断位置及恢复结果。使用固定替身测试状态机，再用真实模型跑同一验收场景，分别报告。
