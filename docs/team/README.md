暂按**队长计入五人、成员 A–E、六周首轮开发**安排。姓名、技术特长和每周可投入时间尚未确定，因此这是可调整的排期基线，不是六周完成全部产品的承诺。队长在开工两天内按实际能力替换负责人、校准工作量。

## 首轮共同目标

在保留当前聊天体验的基础上，完成一条可演示、可验证的工作流程：

> 创建工作 → 选择受控示例仓库和模型 → 分析问题 → 提出修改 → 用户批准 → 修改文件 → 执行规定的测试 → 根据失败结果修复 → 验证成功 → 保存检查点与结果 → 重启后继续查看或恢复。

首轮只做**单工作内串行执行、有限步骤和有限修复次数**。普通聊天继续可用，不强制创建任务图。示例仓库、命令及执行环境必须由团队预先检查；没有操作系统级隔离时，不开放任意仓库脚本执行。

## 现状与下一步

| 模块 | 当前已有 | 首轮还缺什么 | 主负责人 |
|---|---|---|---|
| 桌面 UI | 工作/聊天切换、项目与会话管理、模型设置、可收缩拖动的右栏 | 真实任务状态、审批、结果展示；流式增量期间的交互稳定性 | B |
| 消息展示 | Markdown、代码颜色、跨多条消息拖选与复制 | 长记录性能、流式时保持选区和滚动位置 | B |
| 模型接入 | 自有 Node 网关；三类协议；云端、本地 API、Ollama；流式、取消、最终状态保存 | 工具调用、进一步统一错误与能力标记 | C |
| 本地模型 | 已有 Qwen3-8B；脚本启动 llama.cpp；可直连也可经 Ollama | 应用内启停、健康检查、失败诊断；下载管理为后续任务 | C |
| 权限 | 请求批准等选项及请求字段 | 真正的策略判断、批准绑定、执行约束和审计 | D |
| 数据与记忆 | 统一 JSONL 正式会话、模型无关上下文；聊天/工作/用户确认记忆；预算摘录与来源校验；可迁移 Data | 持久任务、执行恢复、全文检索；完整记忆管理界面 | E |
| Agent 执行 | 当前网关返回模型文字 | Host、工具调用闭环、验证、检查点恢复 | A、D、E |

现有正式记录按稳定聊天 ID 保存；切换连接或模型继续使用同一聊天历史。工作内聊天通过已确认工作记忆共享约定，各自原始历史与预算摘录独立。当前实现与后续 Host 的衔接见 [聊天与工作记忆架构](../architecture/chat-work-memory.md)。权限菜单目前仍不代表模型能够操作电脑。

## 范围与优先级

| 等级 | 内容 | 安排 |
|---|---|---|
| P0：首轮必做 | 保留聊天、流式取消、持久 Work、受控文件修改与测试、真实审批、验证证据、恢复、旧数据保护 | 六周计划围绕这些交付；容量不足时调整日期或减少支持场景 |
| P1：P0 稳定后 | 下载链接与指定安装目录、下载校验/恢复；独立工作存储设置；全文检索；更丰富的模型管理 | 已分配负责人，但不挤占 P0 验收 |
| P2：后续版本 | 完整 RAG、多人 Agent、插件市场、浏览器/桌面自动操作、手机远程、钱包交易、复杂自动化 | 首轮不排实现；保留设计，单独估时 |

下载模型、选择安装位置和每个工作独立存储都是已有用户需求，放入 P1 是排期安排，不是取消需求。原 139 页愿景不按页数平均分给五个人，而按可独立开发、可联调的模块分工。
