# 模型请求并发

调度依据实际服务能力，不以 `localhost` 或回环 IP 判定只能同时生成一条回复。

| 连接 | 准入规则 |
| --- | --- |
| KYNXA 内置模型 | 当前自管运行时只有一个生成槽，上层按同一容量排队，避免把等待藏在推理服务内部。 |
| 已观测到容量的外部 llama.cpp 服务 | 复用已有 `/props` 观测，按 `parallelSlots` 调度，同一地址下的不同模型共享容量。 |
| 未报告容量的外部服务、Ollama、LM Studio、本机 API 转发及云端 API | 使用现有 API 并发池：6 路起步，成功反馈后逐步增加至最多 32 路，限流回退；服务自身仍可排队或限流。 |

外部槽位必须来自对应来源的运行观测，不接受仅凭端口、主机名或未经观测的配置字段推断容量。地址末尾的斜杠不产生额外名额。不同主机别名不能仅靠猜测合并为同一服务。

外部观测同时用于并发与原有增量资源预算，正常请求复用同一份结果。Ollama 排队跨过原有两秒观测有效期时，资源预约前按原缓存规则刷新，避免把已完成的模型装载再预约一次。服务容量降低时保留在途请求，等待实际空位再派发；取消等待不重做已派发操作。

排队、前台优先、后台老化防饥饿和主任务保留名额沿用原规则。此调整不改变内置模型的线程数、上下文、KV 配置、休眠、任务恢复或模型缓存，也不声称增加并发一定能加速单条回复。
