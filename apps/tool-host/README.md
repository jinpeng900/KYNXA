# Windows terminal sandbox

`KYNXA.ToolHost` is a .NET 10 console helper used only by `model-gateway/sandbox-runner.mjs`. It launches copied Node or pinned Windows cmd executables with a fresh Windows AppContainer token and no network capabilities. It does not launch a host shell, elevate privileges, or fall back to a normal process.

Build with `dotnet build apps/tool-host/KYNXA.ToolHost.csproj`. Desktop packaging builds a self-contained helper for its runtime identifier (`win-x64`, `win-arm64`, or `win-x86`) and copies the complete output into `ToolHost` beside `model-gateway`. For a standalone self-contained build use `dotnet publish apps/tool-host/KYNXA.ToolHost.csproj -c Release -r win-x64 --self-contained true`. Framework-dependent development builds require .NET 10.

The helper reads one UTF-8 JSON request line from stdin. A second `cancel` line or stdin EOF cancels execution. Stdout contains a `sandbox_started` JSON line followed by one final result/error JSON line. Capabilities returns one line. Protocol version is `1`. Node stdout/stderr is returned only inside the final result. The gateway never treats helper diagnostics as model thinking.

Only command names `node`, `node.exe`, `cmd` and `cmd.exe` are accepted. The gateway supplies its own `process.execPath`; cmd is copied from `Environment.SystemDirectory`. Tool arguments cannot choose an executable path. Debugger flags are rejected. Node runs with `--preserve-symlinks` and `--preserve-symlinks-main` so loading a snapshot script does not require probing inaccessible host ancestor directories. Use `node --test --test-isolation=none fixture.test.cjs`: default process-isolated Node test IPC is incompatible with this AppContainer. Ordinary child processes inherit the AppContainer token and remain subject to the same job.

cmd is restricted compatibility, with arguments exactly `['/d', '/c', 'command text']`. The helper forces `/d /u /s /c`: AutoRun and interactive input are disabled, builtin output uses Unicode, and command text remains inside AppContainer. Actual smoke covers `echo`, `type`, output redirection, and a cmd-created Node child. `dir` can be denied when it requests host volume/root metadata; use `filesystem.list/search` for listing. No host ACL is relaxed and no shared DOS drive mapping is created. Child programs can emit a different encoding than `/u` builtins, so avoid mixing Unicode builtin and non-Unicode program output in one command.

Each run copies at most 512 files, 2,048 entries, 32 MiB total and 4 MiB per file, to `%TEMP%/kynxa-tool-sandbox/<random>/workspace`. Nesting is limited to 32 levels. Copying excludes links/reparse points and hard-linked files, configured application Data roots, `Data`, `Models`, `Memory`, chat/index/backup directories, credential/configuration directories, `.git`, dependency/build directories, common credential filenames, `.env*`, private-key/certificate files, settings and transcript logs. Open file handles are checked against the allowed source root before copying. These exclusions cannot recognize arbitrary credentials embedded in otherwise ordinary source files; choose the authorized workspace accordingly. The original workspace ACL and files are unchanged.

The service may pass `trustedManagedWorkspace: true` only for the catalog's exact default work folder. It is absent from model tool parameters. The helper additionally requires the shape `<excluded Data root>/Desktop/Projects/<GUID>`, and ignores only Data exclusions that are strict ancestors of that work folder. Sensitive child directories and exclusions inside the work folder still apply. Data/Chats, Data/Models and arbitrary folders do not obtain this exception.

The stage receives a protected ACL for the current user, SYSTEM, administrators and the unique AppContainer SID, plus a low-integrity label. No network capability is granted. A child is created suspended, assigned to a Job Object, and its `TokenIsAppContainer` value is checked before resume. The job permits at most 16 processes, 256 MiB committed memory per process, and 768 MiB per job. Combined stdout/stderr is limited to 256 KiB; exceeding it terminates the job. Timeouts are 100–120,000 ms. Completion, timeout and cancellation terminate all descendants, and successful results verify the job has zero active processes. The non-inherited job handle has `KILL_ON_JOB_CLOSE`, so terminating the helper also ends its children.

Successful stages are retained during the tool turn for explicit inspection, without writing files back. `SandboxRunner.cleanup(result.stagingDirectory)` removes only a run returned by that runner; `cleanupAll()` handles remaining owned copies on service close. The broker releases stages when a turn completes. Graceful cancellation/failure removes its stage and profile. Abrupt OS/process termination can leave a uniquely named profile and temporary copy; job cleanup still terminates execution. Disk growth created by the script is not an OS disk quota, and AppContainer is not a VM: do not describe either as provided. PowerShell/Python, arbitrary top-level executables, external networks and remote MCP processes are not enabled by this helper.

Official design references: [AppContainer launch](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer), [mandatory integrity control](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control), [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
