# 验证与协作

验证目标是本次用户行为及受影响约定。下列命令从仓库根目录执行，按改动选择；不要求每次全量运行。

## 最低必要验证与推进节奏

- 优先让用户的主流程可用。先核对实际改动和调用关系，只选能回答本次问题的最低必要检查；已有检查能够覆盖时直接复用，不另建同义用例。
- 约七成工程把握即可推进，是基于源码、现有证据和改动影响的判断，不是测得的 70% 成功率，也不能写成量化验收成绩。已知的主流程阻断、越权、正式数据损坏或重复副作用仍应处理，不能据此宣称已完成。
- 复用仍适用于当前逻辑、数据和环境的有效结果，只补变化与真实使用缺口。报告区分本轮执行、已有结果复用和未验证部分，不将历史记录冒充本轮实测。
- 小改动不自动增加冒烟套件、诊断探针、开发快照、逐文件哈希对照、完整基准或全套构建测试。注释、格式和规范修改通常以差异及相关引用核对收尾；行为修改选择最接近主流程的现有检查。只有改动影响、已出现的故障或明确用户要求能解释新增成本时才扩测。
- 必要检查通过后停止，继续集成或交付。不追求完美覆盖，不为尚无证据的边界情况堆叠防御、反复调用模型或延长验收；新变更、失败或影响主流程的疑点才扩大对应范围。
- 精简的是开发过程中的额外验证，不删除运行时的权限、作用域、正式数据一致性、来源版本与未知副作用保护。任务暂停的业务断点继续保留；开发用副本或快照不是业务断点，不要求每次修改都制作一份。模型资产完整性和来源引用所需的哈希仍按正式合同执行。

## 当前验证入口

本机保留两层回归，测试目录被 Git 忽略、不随源码分发：`apps/agent-core/tests` 及源码内 `cfg(test)` 模块是主回归，覆盖不重放、权限、缓存投影、恢复与检索等规则；`tests/verify.py` 是整包冒烟。旧冒烟目录、模拟后端和一次性验证产物已移出仓库，不再维护。

```powershell
cargo test --manifest-path apps/agent-core/Cargo.toml -j 2
python tests/verify.py
node tools/development/check-architecture.mjs
```

本地脚本使用已构建的真实网关、模拟上游和独立临时数据，检查关键 HTTP/SSE 与任务执行路径；实际覆盖和通过项以输出为准。缺少当前构建时先说明条件，不自动下载资源、调用真实 API 或重建整套环境。它不替代 Windows 界面、视觉质量、格式矩阵或长期性能实测；改变这些行为时只补相应的实际操作检查，不复制新框架。

架构守卫检查源码边界与引用，不能计为产品行为测试。GitHub CI 仅运行此源码检查；依赖本地测试文件的打包检查不在 CI 运行，正式构建内的部署路径与载荷校验继续保留。

## 按需构建

正式目标为 Windows x64。统一入口是 `apps/desktop/Build/build-desktop.ps1 -Action Setup|Build|Run|Rebuild`，复用其工具链发现、资源准备和阶段日志；产物已匹配时直接运行，不重复恢复依赖。只有用户要求或改动确需编译时构建。

```powershell
powershell.exe -NoProfile -File apps/desktop/Build/build-desktop.ps1 -Action Build
cargo check --manifest-path apps/agent-core/Cargo.toml --locked --lib --bins
cargo check --manifest-path apps/resource-service/Cargo.toml --locked --bins
```

以上是按需选择的独立命令，不是逐个必跑。干净克隆可构建生产程序并运行架构守卫；不再分发旧测试工程或夹具，也不使用旧套件的完整测试命令。Windows 桌面需有效包身份，按工程或已注册包入口启动；裸 EXE 的 COM 身份错误不能当作网关故障。

## 数据与结果

- 验证只使用明确的独立临时 Data、虚构凭据和模拟服务，不能默认连接正式聊天或消耗用户 API；用户明确授权真实调用时按其范围执行，不输出密钥或私密聊天。
- 只启动、关闭本次验证拥有的进程；不替换日常网关、结束用户任务或修改正式存储配置。临时进程退出后清理自有数据，不永久累积二进制副本、截图和测试报告。
- 优先核对用户可观察结果：消息完整交付、引导生效、暂停和恢复保留原任务与回执、成功操作不重复。内部计数不能代替实际行为。
- 缓存与性能的结论需要同边界测量；界面行为需要实际显示或交互证据。编译通过、模拟上游通过均不能冒充真实模型或全部 UI 验收。
- 复用仍有效的已有结果，只补本次改动和实际失败；必要检查通过就停止扩测。报告区分本轮运行、历史结果及未覆盖项。

## 协作与交付

- 独立工作可委派，约定文件和共享接口，避免同时修改；主代理负责整合，不把子代理报告当作完整验收。
- 保留已有源码改动，不用重置或清理消除不理解的变化。验证清理只针对已核定的自有临时文件，正式数据、工具链和正常构建缓存继续保留。
- 修改影响公开合同或维护入口时同步文档；不为小改动新增同义用例、诊断探针或归档副本。
- 交付说明实际行为、有效证据和未覆盖范围。提交、推送和发布遵循用户已有授权，代码修改不自动扩大为安装包发布。
